# 数据库迁移(Alembic)

> 状态:耐久参考(快照 2026-10-21)。自 `CLAUDE.md`「Database migrations (Alembic)」原文迁出(2026-10-21)。硬规则(每次模型改动配迁移、`upgrade heads` 口径、勿加 stamp 捷径)在 `AGENTS.md`;本文是完整语义。
> 相关:[`ops/deploy-docker.md`](../ops/deploy-docker.md) · [`ops/deploy-baremetal.md`](../ops/deploy-baremetal.md) · [`ops/taxonomy-v1-deployment.md`](../ops/taxonomy-v1-deployment.md)

Schema evolution is versioned via **Alembic** (`alembic/`, config `alembic.ini`). `alembic/env.py` uses `SQLModel.metadata` (import `models.db`) as the autogenerate target and reads the DB URL from `settings.storage.database_url` (unless a URL is injected programmatically — see `src/storage/migrations.py`). SQLite has no native `ALTER`, so `render_as_batch=True`.

- **Runtime bootstrap is still `create_all()`** — `DatabaseStorage.__init__` builds tables from metadata for fresh/in-memory DBs (fast, and what the tests rely on). Alembic is the authoritative mechanism for **evolving existing file DBs** and CI/ops.
- **SQLite foreign-key policy is connection-wide and intentional** — runtime `DatabaseStorage` connections set `PRAGMA foreign_keys=ON` so declared CASCADE/SET NULL rules execute; Alembic temporarily uses `foreign_keys=OFF` for SQLite batch-table replacement. Run `PRAGMA foreign_key_check` on a production backup before upgrading an established database.
- **The invariant that keeps the two in sync**: `create_all()` (== metadata) must always equal `alembic upgrade head`. `tests/test_migrations.py::test_upgrade_head_has_no_drift_from_metadata` enforces this — so **every model change needs a matching migration** (or the drift test fails). Author changes as: edit `models/db.py` → `alembic revision --autogenerate -m "..."` → review.
- **Adopting Alembic on a legacy DB**: `storage.migrations.ensure_migrated(db_url)` handles "has tables but no `alembic_version`" by stamping the baseline (`5ee31a7c5393`) then `upgrade head` (avoids re-running baseline `create_table` on existing tables). It runs automatically at every startup entry: the production container entrypoint (`docker/entrypoint.py`) calls it before uvicorn, **and `src/main.py` calls it before `uvicorn.run`** (covers dev bare-start; in-memory DBs are skipped, at-head is a fast no-op). Only importing `api.app` directly (e.g. tests) bypasses it. 迁移链多头(下游分叉仓自带迁移支线合入 main 后 DAG 双头)时 `ensure_migrated` 检测到即 `upgrade("heads")` 并行全升(main 单链下恒等价于 head);**勿给收养路径加「探哨兵 stamp head」类捷径**——会跳过带数据语义的迁移,`test_ensure_migrated_adopts_legacy_db` 是护栏(3.38.1)。**issue #130 起口径统一 `heads`**:测试与文档一律 `upgrade heads`;守卫 `test_main_migration_chain_has_a_single_unlabeled_head`(`storage.migrations.main_chain_heads`:去掉迁移文件里**声明了** `branch_labels` 的 revision 及其后代后,主线子图恰好一个叶子;不能看 `Script.branch_labels`,alembic 会把标签传给祖先)只允许 main 自己的链单头,下游带 label 的支线无论从旧节点分叉还是直接延伸 main 末端都可长期并存,**不做 alembic merge**(每合一次下次照样双头);测试里读版本表一律 `get_current_heads()`。
- **Taxonomy deployment posture is explicit and independent of `runtime.role`**: configure `[taxonomy] deployment = authority` on the external producer, `replica` on the internal Archive Sync receiver, or `manual` for an intentional startup no-op; both production nodes may still use `role=all`. `DORAMI_TAXONOMY_DEPLOYMENT` and `DORAMI_TAXONOMY_CATALOG` override INI. Official Docker, bare-metal, and dev entries run the shared reconciler after `ensure_migrated` and before API/workers. Authority imports the packaged approved catalog transactionally and idempotently by digest/receipt but never publishes; replica never reads or installs the catalog. Conflicting receipts or pre-existing taxonomy fail startup closed. See `docs/ops/taxonomy-v1-deployment.md`.

```bash
.venv/bin/alembic upgrade heads                      # apply migrations to the settings DB(单链下等价 head;下游带 label 的支线一并升)
.venv/bin/alembic revision --autogenerate -m "desc"  # generate a migration from model changes
.venv/bin/alembic check                              # report drift between models and the current DB
```

> Note: legacy DBs built by the old hand-written `_ensure_compatible_schema()` `ALTER TABLE ADD COLUMN` path are **missing the `index=True` indexes** those columns declare (raw ALTER never created them) — a real pre-existing drift that a follow-up migration repairs.
