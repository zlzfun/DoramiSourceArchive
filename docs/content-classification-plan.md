# 内容分类与双评分(issue #178)方案

> 状态:**第一波已实现、检视通过,待用户验收**(2026-10-12 动工,分支 `feat/issue-178-content-kind`)。
> 结论与可视化见 [issue #178](https://github.com/zlzfun/DoramiSourceArchive/issues/178)
> 和样页 [`docs/design/dorami-classification-scores-quiet.html`](./design/dorami-classification-scores-quiet.html)
> (仓库公开,可经 htmlpreview 免登录打开)。#168 的历史探索不作为本方案的前提。

## 0. 拍板(2026-10-12)

1. **定位**扩展为「资讯 + 值得深读 / 收听」。
2. **双评分**:每条内容都打两个分。**新闻价值**(这件事有多重要)保留现有 `quality_score`,定义、数值、门槛不变;
   **内容价值**(值不值得花时间读或听)新增,标准随内容类型变化,所有类型都有领域相关性上限(与 AI 无关最高 4.9),
   播客现有附加尺迁入内容价值。这推翻了 issue #22(2026-09-07)「只留一把尺子」的拍板,理由写在 issue #178。
3. **条目级内容类型**:资讯 / 论文 / 教程 / 观点 / 版本更新 / 项目 / 汇编;体裁 `content_genre` 拆成「内容类型 + 事件类型」。
4. **公共日报**继续收少量论文:论文名额仍 3 篇,改为从内容类型为论文的条目里按内容价值挑选(第三波)。
5. **个人早报**新增「值得读」「值得听」(第三波)。
6. **阅读器**:每条显示一个主分(内容类型决定默认维度,新闻价值 ≥ 8.5 时以新闻价值为主);评分卡里 AI 速读不变,
   分数下方小字标当前维度,点分数切换维度,悬停分数显示该分数的评分依据(第二波)。条目挂类型签,列表头加类型筛选(第一波)。
7. **左轨撤销「动态」并入「文章」**,版本更新用紧凑行(第一波)。
8. **维度收口**:`content_type` 只是数据结构、不再当分类展示;`category` 拆出准入状态后退役;源级 `content_tags` 退役;
   标签与映射表合一。对外说法:文章 / 播客 / 社交是「呈现形态」,「类型」专指内容类型。

## 2. 第一波

### 2.1 词表与推导

单一事实来源 `src/services/content_classification.py`:内容类型 / 事件类型 / 体裁 / 数据结构四张中文名表,
体裁 → (内容类型, 事件类型) 映射,个人早报板块与公共日报分类两张分区映射,以及判定规则。

判定序(`classify_item`):

1. **来源先验**:抓取器类属性 `default_kind`。HF Daily Papers → 论文;8 个 changelog / release notes 与 3 个
   GitHub Release 源 → 版本更新;2 个 HF 模型、1 个 GitHub 仓库、1 个 GitHub 趋势源 → 项目;日报源 → 汇编。
2. **数据结构兜底**:只对没有来源先验的源(配置源、历史 / 导入源、未设 `default_kind` 的注册源;`github_release` → 版本更新,模型卡 / 仓库 / 趋势 → 项目,`arxiv` → 论文)。
3. **链接形状**:arXiv / OpenReview / HF papers 链接 → 论文。只认 URL 开头的「协议 + 主机 + 路径」前缀(`PAPER_URL_PREFIXES`),
   查询串或片段里引用的论文地址、相似域名都不算;社交帖、播客、日报不套用,它们的链接指向自身。
4. **体裁**:`research_paper` → 资讯 + 研究成果(分析看到的是讲研究的内容,不一定是论文原文);`tutorial` → 教程;
   `opinion` → 观点;`aggregation` → 汇编;其余 → 资讯 + 对应事件类型。
5. 都没有(通常是分析未完成)→ 未判定,读者面按资讯处理(不挂签)。

事件类型只对资讯 / 版本更新 / 项目填写。

**为什么读取时推导、不落库**:所有输入(源 id、链接、数据结构、体裁)都已入库并随归档同步到接收节点,两端同一份代码
算出同一结果,零迁移、零回填、同步协议不动;分析版本不变也就不触发重跑。SQL 镜像只有一份:`kind_expr` 是按判定序排列
WHEN 的 CASE 表达式(体裁用相关标量子查询),筛选取它的 IN(`kind_condition`),分面按它 GROUP BY 一次聚合。
它与 Python 推导共用规则表,`tests/test_content_classification.py` 在由规则表生成的穷举组合(源 × 数据结构 × URL × 体裁,
含无分析行)上逐条对拍。第二波大模型给出的内容类型落库后,作为额外输入同时接进 `classify_item` 与 `kind_expr` 即可。

### 2.2 接口

- `GET /api/articles` 列表 / 详情 / 收藏的条目新增 `kind`、`kind_label`、`kind_basis`、`event_type`、`event_label`、
  `content_genre_label`、`content_type_label`(中文名由后端下发,前端不再维护映射表)。
- 新参数 `kind=paper,tutorial`(CSV,任一非法值即 400,在任何查询之前校验)与 `kind_facets=true`:附带当前范围
  (不含 kind 自身)的各类型计数 `[{kind, label, count}]`,筛选带的选项来自它(约定 §6「选项来自聚合端点」)。
  分面只随分页对象返回,所以 `kind_facets=true` 隐含 `include_total=true`;两者都不传时默认响应仍是数组。
  代价:真实库副本(7194 篇,文章容器 4307 篇)全范围请求约多 17ms,订阅范围下差异在抖动之内;合成数据 10 万篇全范围时,
  一次 GROUP BY 约 183ms(原先六次 COUNT 约 362ms)。用于筛选时 CASE 比原先的 OR 分支慢(同组合成数据计 tutorial
  89ms → 135ms),换取 SQL 镜像只有一份,检视时双方同意这一取舍。
- `GET /api/articles/facets` 的 `content_types` 每项附 `label`(数据结构中文名)。
- `GET /api/reader/sources` 每个源新增 `default_kind` / `default_kind_label`(发现页源卡、日报名单用)。
- 字段名用 `kind` 而非 issue 里写的 `content_kind`:后者已是自定源的源级字段(article|podcast),避免同一接口面二义。

### 2.3 「动态」并入「文章」

- 15 个原 bulletin 源(另 3 个模板)的 `content_shape` 回到默认 article,改设 `default_kind`。
- `api/sources.normalize_shape`:入参 `bulletin` 视同 `article`。用在 `/api/articles`、`mark-all-read`、`mark-scope-read`、
  `favorites` 四个入口——**不能把 bulletin 当未知值忽略**,否则旧客户端的 `mark-all-read?shape=bulletin` 会把全部订阅
  (含社交)标读、列表混进社交与播客(测试锁定)。其余非法值分两类处理:两个标读端点是写操作,返回 400 且不写任何读态;
  列表与收藏是只读查询,沿用既有的宽松处理(视为不过滤)。
- 未注册的历史源按数据结构兜底时,版本发布 / 模型卡也归文章容器(此前会落到不存在的容器)。
- **榜单口径不变**:`rankings._source_shapes` 把来源先验为版本更新 / 项目的源标为 excluded,继续不进文章榜与必读榜;
  配置源(如绑定 `generic_github_releases` 的公共源)按其预期数据结构求类型,同样排除。
- **批量订阅**:「订阅全部文章源」随形态合并纳入原动态源(前后端同口径),待验收确认。
- 管理面节点目录去掉「动态」页签,计数量词按来源先验(版本更新 / 项目用「条」);日报名单的「· 动态」改为类型名。

### 2.4 读者面

- 条目行:源名后挂内容类型签(`.reader-entry-kind`,沿 `.reader-entry-tag` 细线语法,墨色提一档),资讯不挂;
  与主标签同名时主标签让位。主标签兜底从体裁中文名改为事件类型。播客行同样挂签(教程 / 观点类播客的提示不因此丢失)。
- 紧凑行由内容类型决定(版本更新):`.is-bulletin` 改名 `.is-compact`,与文章混排。
- 筛选带 `.reader-kind-band`:列头下,仅文章容器;单选,再点取消;选项只列计数 > 0 的类型(选中项除外)。
  选中值绑定在当时的作用域上:切容器 / 源 / 轴 / 收藏的同一帧即失效(不先发「旧类型 × 新范围」的请求),并永久清除——
  返回原作用域不复活;按 id 打开文章(深链、引用跳转)也退出类型筛选。
- 按类型筛选时收起列头的「全部标读」:标读按源水位推进,会连同没显示的其它类型一并标掉。右键 / 长按里的「该源全部已读」
  是显式的源级动作,与兴趣透镜下同一菜单项口径一致,不随类型筛选收起(会连同该源其它类型一并标读)。
- 分析轮询:每次列表加载(首页 / 翻页 / 整窗重拉)都让列表版本 +1,轮询整次提交前核对,期间有过加载的旧轮询整体作废
  (不回滚新条目、不重复累加分面)。不筛选时,已加载条目的类型变化按增量修正分面计数。按类型或标签筛选时,在途条目
  不在本轮响应(同一窗口)里即视为窗口成员变了——可能改判出了范围,也可能被补位挤出窗口,而翻页可能已拿到服务端的新总数——
  不在本地移出或扣总数,改为静默重拉同一窗口、带总数与分面的快照整体替换。未加载条目的变化等下次列表加载。
- 阅读窗眉头「源 · ___」:非资讯写内容类型,资讯写事件类型。
- 移动端:底部 Tab 去掉「动态」;筛选带放在列表顶(顶栏须单行,e2e 有约束),横向滑动。
- 发现页:形态筛选 5 档 → 4 档;源卡「动态」签改为来源的默认类型(论文 / 版本更新 / 项目)。

### 3.1 存量数据(2026-10-12 拍板)

**生产实测**(2026-10-12,v3.62.0,只读聚合,口径与本分支 `kind_expr` 一致):共 11689 篇。公开文章 10307 篇中,
资讯 2067、论文 1650、版本更新 546、汇编 149、项目 145、观点 121、教程 15,**判不出类型 5614(54%)**。分月:
6 月 66%、7 月 76%、8 月 77%、9 月 20%、10 月 21%。

- 2026-09-10 开启文章分析之后,有正文的新条目基本全覆盖(当天仅 6 篇在排队)。判不出的主要是无正文条目(487 篇,
  其中 HN 发现源 475 篇):外链帖只有标题与链接,按设计不送分析,读者面按资讯显示,arXiv 链接由链接规则判为论文。
- 2026-09-10 之前:**4337 篇有正文但从未分析**(开启分析时只自动回填了近 7 天,历史全量回填从未在生产执行),
  主要是 IT之家 1244、新智元 779、量子位 701、r/LocalLLaMA 420、The Decoder 308;另有 784 篇无正文。它们没有类型、分数与标签。

**决定:第一波不回填。第二波新提示词落地后对这 4337 篇做一次完整回填**,同时产出新闻价值、内容价值与内容类型。现在用旧提示词回填,
第二波还得为内容价值再跑一遍,同一条目的两个分也会出自两个提示词版本。估算(按生产实际用量,单次分析约输入 3.6k / 输出 1.3k token):
2000–4000 万 token,约 5–10 美元;按 9 月观测的每分钟约 8 篇,约 9 小时;复用可续跑的历史回填任务。
副作用:全站榜单「历史高分」会纳入 6–8 月内容,回填前告知。

其余存量约束(各波动工时遵守):

- **第一波补**:`category` / `content_tags` 只停写新条目,历史条目的扩展标签不改写——档案忠实性;下游 feed / MCP 已消费;
  改写存量会经归档同步触发器把全库重新广播一遍。
- **第二波**:内容价值用独立字段与独立版本号,**不动新闻价值的 `scoring_version`**(公共日报只认当前版本的新闻分,动了会让存量全部
  失效、改为现场补评,读者面分数集体变化)。缺失即缺席:没有内容价值的条目主分回落新闻价值,评分卡只显示一个维度。
  已分析的条目按内容类型定向补内容价值(论文 / 教程 / 观点 / 汇编 / 播客),只写内容价值与模型给出的类型,不覆盖已有新闻价值;
  旧尺子 `content-value-v1` 的记录不复用。回填只在外网生产者执行,新字段随归档同步到内网(同步协议扩展分析流字段,外网先于内网部署)。
- **第三波**:播客门控改读内容价值时,新口径只对切换日之后发布的单集生效,防止存量单集一次性触发大额语音识别 / 语音合成;
  早报「值得读 / 值得听」与日报论文名额只作用于新版次,旧版次不重编。
