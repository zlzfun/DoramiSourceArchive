# Podcast 成本门控与评分标定方案（issue #97）

> 状态：P0 成本门控已实现，待合入与上线观察；P1 评分黄金集尚未启动。评分提示词调整必须等
> 黄金集与对照实验完成，不阻塞成本门控上线。本文中的分数均指完整逐字稿终评，简介分只用于
> 判断是否值得支付 ASR 成本。

## 0. 拍板结论（2026-09-17）

1. 简介初评进入**付费 ASR 回退**的固定门槛从 `>= 5.0` 调整为 `>= 6.0`，`5.9` 不通过、
   `6.0` 通过；仍允许管理员强制全文。
2. 只要存在可用的发布方逐字稿，就直接进入全文分析，不看简介分，也不占用 ASR 预算。
3. 发布方逐字稿抓取、格式或质量校验失败后，是否允许回退 ASR 重新看简介分：低于 `6.0`
   必须停止，`>= 6.0` 才能走现有 ASR 准入、容量和预算门控。
4. 全文终评的优质/TTS 门槛默认改为 `>= 7.5`，继续使用运行时 KV
   `podcast_premium_score_threshold` 动态调整；`7.4` 不通过、`7.5` 通过。
5. 本 issue 不新增读者点播或“现在生成”按钮；普通访问不能触发 ASR、全文分析或 TTS。
   主分支另行实现的 issue #138 点播能力不属于本波成本门控范围。
6. 暂不直接放宽 9 分锚点。先建立播客专项黄金集，用成组对照确认严格度、名气泄漏、
   原创性和阈值稳定性，再决定是否修改提示词及版本。

代码默认值只影响没有保存过运行时设置的新环境。已有环境若 KV 仍是 `8.0`，上线清单要由
管理员显式保存为 `7.5`；部署不得静默覆盖管理员已经选择的其它值。

## 1. 问题与目标

当前“是否值得做全文分析”和“是否值得支付 ASR”共用一条简介分门槛，而且在候选发现与真正
入队时各检查一次。发布方逐字稿虽已是首选输入，但低分单集在到达逐字稿抓取逻辑之前就被
过滤，导致零 ASR 成本的官方全文也无法被利用。

本波把两个决策拆开：

- **全文分析资格**：发布方已经提供逐字稿时天然具备，不看简介分。
- **付费 ASR 资格**：只有没有可用发布方逐字稿、且简介初评 `>= 6.0` 时自动具备。
- **优质/TTS 资格**：完整逐字稿分析完成后，以全文终评 `>= 7.5` 判断。

这不是“官方稿完全免费”：仍会发生逐字稿下载、规范化和 LLM 全文分析成本；它只是明确为
**零付费 ASR**。权利门、SSRF/大小/MIME/格式校验、完整性 QA、LLM 可用性和产物存储边界均保留。

### 1.1 评分服务对象

Podcast 终评不是衡量节目的一般制作质量、传播热度或对所有人群的普遍价值，而是衡量它对
**多啦美的技术读者**是否值得投入时间。核心读者是工程师、研究人员和技术负责人，优先关注：

- 技术前沿与研究进展；
- 工程方法、架构、数据、评测和产品实践；
- 会改变技术路线、产品选择、职业判断或研发资源配置的行业趋势。

投融资、IPO、组织管理和个人经历可以作为技术产业背景，但内容详尽、嘉宾知名或资本影响大，
都不能单独达到 `7.5`。非技术内容要达到优质线，必须明确改变技术人员对技术成熟度、路线选择、
工程落地、供需结构或职业机会的判断；只对投资人或管理人员有用的内容应显著降分。

2026-09-17 本地快照只用于估算方向：473 条简介初评中，`>= 5.0` 有 372 条，`>= 6.0`
有 277 条，候选池机械减少 95 条（25.5%）。这不是成本节省承诺：最终费用仍取决于官方稿
命中率、单集时长、失败重试和实际 ASR 结算。

## 2. 目标流程

| 发布方逐字稿 | 简介初评 | 自动动作 | 是否允许付费 ASR |
|---|---:|---|---|
| 本地已有且与当前 locator 匹配 | 任意/缺失 | 直接用该 artifact 全文分析 | 否 |
| RSS 有 locator，抓取与 QA 成功 | 任意/缺失 | 发布 artifact 后直接全文分析 | 否 |
| RSS 有 locator，但抓取或 QA 失败 | `< 6.0` 或缺失 | 记录失败并按既有退避回访，不下载原音频 | 否 |
| RSS 有 locator，但抓取或 QA 失败 | `>= 6.0` | 重新通过 ASR admission/容量/预算门后回退 | 是 |
| 没有 locator/官方 artifact | `< 6.0` 或缺失 | 不自动全文处理 | 否 |
| 没有 locator/官方 artifact | `>= 6.0` | 走现有源音频校验与 ASR | 是 |
| 已有全文终评，locator/artifact revision 变化 | 任意 | 用新逐字稿刷新全文终评 | 仅官方稿不可用且达到 6.0 时 |
| 管理员强制全文 | 任意 | 保留现有 override 与审计 reason | 是，仍受权利/供应商/预算硬门约束 |

必须把“locator 存在”和“locator 成功取得合格逐字稿”区分开。locator 不是免费通行证，
它只允许先尝试官方路径；失败后不得替低分单集偷开 ASR 回退。

## 4. 开发验收点

### 4.1 门槛边界

- `5.9` + 无发布方逐字稿：landing 不产生自动候选。
- `6.0` + 无发布方逐字稿：landing 产生候选，仍需通过 ASR admission/容量/预算。
- `7.4` 全文终评：不是优质，不自动 TTS。
- `7.5` 全文终评：是优质，可进入现有预生成 TTS 队列。
- 强制全文、强制 TTS 的现有 override、审计和幂等行为保持。

### 4.2 发布方逐字稿旁路

- `5.9`、缺分或简介分析失败，只要官方逐字稿抓取并 QA 成功，都能全文分析。
- 第一处 landing 资格门和第二处 `request_processing` 入队门均不得拒绝该路径。
- 使用官方稿时不产生 source-media 下载、ASR attempt、ASR 预算预占或 ASR cost ledger。
- 已有当前官方 artifact 时直接复用，不重复联网抓取；locator 改变时生成新 revision 并刷新。
- 当前 artifact 与 locator 不匹配时不能把旧稿当成成功旁路。

### 4.3 失败防线

- `5.9` + locator 404、HTML 冒充文本、超限或解析失败：停在官方稿失败态，绝不回退 ASR。
- `6.0` + 同类失败：只有重新通过 admission、容量和预算检查后才可回退 ASR。
- 供应商未配置、容量不足和预算拒绝仍走现有 gated/retry 语义；不得被“有 locator”绕过。
- 网络瞬时失败继续退避；确定性失败不能每分钟重抓；revision 变化后重新放行。
- 权利拒绝、私有/退役源边界、过长音频和媒体安全检查行为不变。

### 4.4 配置与历史语义

- 新库默认优质线为 `7.5`；已有任意合法 KV 值原样保留。
- 调低到 `7.5` 后，历史全文分 `>= 7.5` 且无成品者成为待生成候选；历史成品不删除。
- 后续调高门槛只改变当前资格与待生成集合，不撤销、删除已经发布的博客或音频。
- 本波不新增读者点播端点、前端按钮或内存任务；页面普通访问零生成副作用。
  issue #138 已在主分支独立提供显式点播入口，需按其自身门控验收。

## 5. 评分需要六组内容对照

最小可用黄金集为 **6 组、32 个评测输入**。这不是为了规定生产分布，而是让每个容易误判的
方向都有正反例；只堆“公认好节目”会把名气、节目品牌和英语长访谈误学成高分条件。

| 组 | 数量 | 作用 | 预期区间 |
|---|---:|---|---:|
| A. 天花板锚点 | 4 | 一手、原创、证据深、足以长期改变专业判断 | 9.3–9.7 |
| B. 优秀但非天花板 | 4 | 权威且深入，但原创性、证据或影响面缺一项 | 8.5–9.2 |
| C. `7.5` 阈值边界 | 8 | 四个刚低于、四个刚高于，直接验证 TTS 分类 | 7.2–7.8 |
| D. 深度胜过名气 | 4 | 非明星嘉宾、窄议题，但数据/工程细节/实践价值强 | 8.0–9.1 |
| E. 外在质量不能替代受众价值 | 4 | 大嘉宾、高播放量或产业信息丰富，但泛聊、重复、证据不足或对技术读者帮助有限 | 5.0–8.0 |
| F. 原创性/转述配对 | 8 | 四对同主题：原始一手内容 vs 转载、复述或二手解读 | 每对原始项高 `>= 0.7` |

样本约束：中文不少于 12 个、英文不少于 12 个；同一节目最多 4 个，同一嘉宾最多 2 个；
至少覆盖模型研究、AI 工程/基础设施、产品实践、产业/治理四类。每项保存完整逐字稿、来源 URL、
发布日期、人物身份依据和选择理由。事后声誉只用于挑选标杆，人工评分仍站在节目发布当时，
不能用后来发生的事情给它倒加分。

另设一组**技术鲁棒性配对**，但不计入上述六个内容组：选 4 份同文本，分别以
`publisher_transcript` 与规范化后的 `asr_transcript` 输入；文字相同则中位分差应 `<= 0.3`。
它只验证输入来源标签不会偷偷加减分，不能拿来校准内容价值。计入这 4 对后，每轮实际运行
为 40 个模型输入；每项跑 3 次时共 120 个**完整评测任务**，不是 120 次底层 API 调用。
全文链路会为每个逐字稿分段调用 map，证据过长时还会调用 compact，最后再调用一次 reduce；
实际请求数和费用必须先由 dry-run 按逐字稿长度、分段数和模型价格估算，不能只按样本数计算。

## 6. 人工标注与模型门禁

### 6.1 人工标注

- 两位评审独立阅读完整逐字稿，先给允许区间，再给中心分与不超过 40 字理由；彼此不可见。
- 中心分相差 `> 0.8`，或两人结论跨越 `7.5` / `9.0` 档界时必须复议并记录分歧理由。
- 评审同时标 `guest_authority`、`novelty`、`evidence_depth`、`practical_value`，用于判断模型是
  因为什么给错，并新增 `technical_reader_relevance` 记录它能否转化为技术判断、学习或行动；
  不把这些维度机械相加成第二套分数。
- 不以播放量、点赞量或嘉宾职位直接定档；它们只作为公共影响力的证据之一。
- `technical_reader_relevance` 是受众适配，不等于“只收代码教程”：高质量产业趋势仍可高分，
  但必须能说明它对技术路线、工程落地、研发投入或技术职业判断有什么直接后果。

### 6.2 离线运行

- 评分尺子标定使用生产相同模型、参数和 transcript 分块归约实现。先按 transcript hash、map
  prompt version、模型和分块参数生成并缓存一次 map evidence；同一份 evidence 独立执行 3 次
  reduce，取中位数并报告最小/最大值。这样隔离终评尺子的误差，也避免三次重复支付相同的
  证据提取成本。
- 另选至少 8 个覆盖中英文、`7.5` 边界和 `9+` 锚点的样本，完整端到端独立运行 3 次，验证
  map 波动不会改变结论。若这组不稳定，再扩大端到端样本，而不是默认重跑全部 40 个输入。
- 执行脚本必须提供不调用模型的 `--dry-run`，报告每项字符数、分段数、map 调用下界、预计
  reduce 次数和总费用区间；未确认预算前不得启动全量基线。
- 基线结果与 prompt/scoring version 固化进 fixture；改提示词前后都跑同一集合。
- 报告整体、六组、中文/英文、节目和分档切片，不能只看一个总平均数。

第一阶段工具与工作文件：

- `scripts/eval_podcast_score_golden.py`：默认 dry-run；只有显式 `--run` 才调用模型。
- `tests/fixtures/golden_podcast_score.json`：完成双人复议后才写入的黄金集清单。
- `docs/podcast-score-annotation-template.csv`：人工盲标与复议导入模板。
- `docs/podcast-score-golden-candidates.json`：待核权、取稿和双人标注的候选池，不是黄金答案。
- `var/evals/podcast-score/transcripts/`：本地私有逐字稿目录，已 gitignore；清单用 SHA-256
  固定内容，避免无意间换稿后继续与旧基线比较。

本地准备与 dry-run 示例（均不会调用 ASR 或 LLM）：

```bash
.venv/bin/python scripts/prepare_podcast_score_transcripts.py \
  --database data/cms_data.db \
  --item <gold-item-id>=<episode-id>

.venv/bin/python scripts/eval_podcast_score_golden.py --include-candidates
.venv/bin/python scripts/eval_podcast_score_golden.py \
  --include-candidates --mode end-to-end
```

只有完成双人标注并把条目标为 `adjudicated` 后，才能显式加 `--run`。`candidate` 即便已经有
本地逐字稿也不能进入付费运行；`--include-candidates` 与 `--run` 同时使用会直接报错。

### 6.3 首轮通过标准

- JSON/契约成功率 100%；单项三次极差的 p90 `<= 0.8`。
- 人工允许区间命中率 `>= 75%`，到允许区间的平均距离 `<= 0.35`。
- A 组 4 项中至少 3 项中位数 `>= 9.3`，且无一项 `< 9.0`。
- C 组 `7.5` 上下分类至少 7/8 正确。
- D 组不得因嘉宾不知名普遍低于 8；E 组不得因名气、播放量或产业信息密度出现 9 分，
  明确标记为技术读者低相关的 E 组样本不得达到 `7.5`。
- F 组至少 3/4 对满足原始内容比转述高 `>= 0.7`。
- 相同文本的 transcript 来源鲁棒性配对，中位分差均 `<= 0.3`。
- 相对现行提示词，整体与各关键组都不得回归；不能用抬高全部分数来修复 A 组。

若模型没有通过，先看失败集中在哪一组，再修改对应锚点。禁止设“每月必须出现多少个 9 分”
或按生产直方图强行配额；9 分稀少本身不是 bug，硬标杆稳定过不了 9 分才是尺子过严。

## 7. 上线与回滚

1. 先合入 P0 开发改造，不改变 Podcast prompt/scoring version。
2. 发布前备份数据库，核对生产 KV 优质线；需要采用本次产品决定时显式保存 `7.5`。
3. 上线后抽查四类真实样本：低分官方稿、高分无官方稿、低分无官方稿、官方稿失败。
4. 发现任一低于 6.0 的非强制任务产生 ASR reservation/attempt，立即视为阻断级回归。
5. 回滚代码恢复原候选逻辑不会删除既有 artifact/终评/TTS；运行时阈值按管理员需要独立回调。
6. 黄金集准备和评分实验随后独立进行；在结论前不 bump 评分版本、不批量重评。
