# 播客逐字稿问答与可核对引用（issue #248）

> 状态:已归档（2026-10-31；实现记录，真实点播、原生界面自查及单集 13/13 检查点已完成；交叉检视返修与用户验收未完成；未合入、未发布）。
> 归档说明：代码已实现，本文记录方案、边界和验证证据；尚未完成的验收不因归档视为通过。
> 关联：[issue #248](https://github.com/zlzfun/DoramiSourceArchive/issues/248)。开发版沿用 `3.67.4-alpha`，本波不另升版本。
> 实现：Codex；实际模型、交叉检视方及模型由主执行者在检视节补录。

## 1. 问题与用户目标

播客简介存于文章正文，发布方原稿、ASR 原稿则独立存于文字制品。此前问答只读文章正文，即使单集已有逐字稿，问答仍只能看到简介；订阅检索也无法命中仅在节目后半段出现的内容。

用户要求端到端修复，并实际点播一期新的播客，用较深入的问题验证问答。此次实现把已发布原稿的相关片段接到既有问答链路，保留文章问答、订阅范围、引用编号和单集跳转。

## 2. 采用的资料与边界

| 资料 | 本波行为 |
|---|---|
| 发布方原稿 `publisher_transcript` | 读取当前发布指针，按既有安全阅读投影生成可检索文本 |
| ASR 原稿 `normalized_transcript` | 校验规范化制品并读取其真实文字，标注「ASR逐字稿」 |
| 节目简介 | 无可用已发布原稿时回退，明确只读了简介、未读取音频，不能据此确认节目细节 |
| 中文译稿 `transcript_zh` | 不纳入检索或作答证据；译文仍可在阅读器单独阅读 |
| AI 导读 `digest_blog_zh` | 不纳入检索或作答证据，不把二次总结当成嘉宾原话 |
| 音频与时间定位 | 问答不触发 ASR/TTS、不下载音频；保留打开单集，不提供虚构时间戳或按字符数估时 |

发布状态和原稿指针决定可用性，生成任务状态、旧制品或存在导读音频都不能替代当前已发布原稿。问答与点播是两个动作，点播继续遵守既有成本和评分门控。

## 3. 检索与上下文

`services/podcast_qa.py` 负责只读证据解析及可重建的本地投影。首次相关查询在允许的来源范围内为缺失或版本变化的原稿建立索引；后续复用。`podcast_qa_indexes` 保存原稿哈希、投影版本与有效性，`podcast_qa_chunks` 保存文本片段和字符范围，`podcast_qa_fts` 是同一 SQLite 内的 FTS5 索引。默认片段 1,600 字符、重叠 200 字符，优先在段落边界断开；不是新向量库，也不是整库主动回填任务。

- 「本期播客」也规划关键词，再检索完整原稿的片段，避免只截取开头。没有关键词命中时从原稿不同位置取有界样本，明确是节选。
- 「我的订阅」与后端 `all` 范围分别检索文章正文和播客片段，按单集 ID 去重，通过倒数排名融合，避免直接比较两套 BM25 的分值。标题、简介不含关键词或简介为空的单集也可由逐字稿命中。
- 查询计划分开提供发现单集用的 `keywords` 和定位集内论据用的 `passage_keywords`，后者避免只按节目名或嘉宾名寻找证据；旧计划没有该字段时回退到 `keywords`。
- 播客候选向选篇模型提供命中的片段引子。最终每集最多六个片段，上限随总字符预算动态调整；优先覆盖不同查询概念，去除大幅重叠，预算允许时补足命中位置前后的原文，保留论证和说话人上下文。预算截短时尽量保留命中附近的原文，并同步修正字符范围。
- 沿用编号上下文；只要最终资料含播客，总上下文预算为 24,000 字符，可容纳最多六个命中起点及其前后论述。纯文章保持显式问答 12,000、订阅检索 14,000 字符。`sources` 只来自实际进入上下文的内容，不能把没送入模型的整稿登记成依据。
- FTS 不可用或短词无法使用 trigram 时，在片段文字上回退 LIKE；仍保留来源、日期和发布条件。时序兜底不会伪称主题匹配。

迁移 `b248c7a10e31` 创建两个投影表与 FTS/失效触发器。发布指针、发布状态、authority 或发布时间变化时清除相应投影，删除单集时级联清理。缓存是本地可重建数据，不新增 Archive Sync 流；同步来的原稿和发布指针仍经相同读取与失效规则。

## 4. 权限与在途变化

来源可见性、订阅范围、用户私有源资格及外部 AI 外送限制继续生效。凭据来源不送外部模型；显式访问隐藏或未订阅私有单集按既有权限拒绝。检索前筛范围，选篇后重读当前范围，回答前后再核对单集权限与发布指针。

每条证据绑定 `artifact_id`、`kind`、`content_hash`。作答期间撤稿或替换原稿，不返回依据旧证据生成的回答，而返回 409 提示重新提问；权限变化沿对应权限错误处理。问答不以索引存在为授权依据。

## 5. 引用与交互

播客的 `sources` 增加 `content_type`、`basis_label` 及 `evidence`。每条证据包含原稿 ID、种类、哈希、`range_start`、`range_end` 和实际原文 `text`。范围是**阅读投影的字符偏移**，不是原始 JSON 字节位置，也不是音频秒数。

每个播客片段的上下文标签显式重复同一资料编号 `[n]`，并要求模型核对说话人归属；片段数量不产生新的引用编号。引用标题仍打开单集。引用行下的「查看依据」折叠区显示本次提供给模型的片段及种类；这些片段支持核对，但不声称逐句对应模型的每个论断。只有简介时显示「依据：节目简介」，不造空逐字稿或假片段。前端只显示服务端返回的原文，不把其作为 HTML 执行。

选中播客时，本文范围显示「本期播客」，占位与等待文案匹配播客，建议问题覆盖主张、前提、反例、观点张力、事实与推断、证据局限。普通文章保持原有本文文案，订阅等待阶段统一称「内容」「条候选」「条资料」，同时适用于文章和播客。样式复用主题 token，原生折叠控件提供键盘操作及焦点环。

### 真实新一期点播

节目为 The AI Native Dev 的 [Dexter Horthy: Why We Stopped Trusting AI to Write the Plan](https://www.buzzsprout.com/2375985/episodes/19844826-dexter-horthy-why-we-stopped-trusting-ai-to-write-the-plan.mp3)（链接为记录中的公开节目来源）。隔离环境中的本集在点击前 TTS 调用数为 0；采用 63,012 字符的发布方原稿，未调用 ASR。沿用提供的预算限额，原节目时长未改。

### 固定深入问题与实际结果

依据完整发布方原稿先建立 13 项评分点，所有轮次保持以下三问及其范围不变。最终组合是 Q1 v3、Q2 v3、Q3 v4；并非三题都在 v4 重跑。问答实际调用模型为沙箱配置的 `deepseek-v4-flash`。

| 问题与范围 | 核验内容 | 最终结果 |
|---|---|---|
| Q1「本期播客」：Human Layer 夜间维护如何发现坏模式、调度和产出？为何不能靠堆积 AGENTS.md 规则取消人工审查？ | 检测器与期望状态；同一 harness 配不同消息，cron/GitHub Actions 运行，早晨约五个 PR；规则过载和拆分；PR 产生不等于已审查或合并 | 4/4，v3；后半段具体事实与依据一致 |
| Q2「我的订阅」：坏代码为何影响之后每项工作？联系六服务架构失败、人工重建及 PR 评论/session traces，判断他是在反对复利工程还是规定前提 | 代码上下文中的坏模式反馈；六服务和重建；人工质量闸及反馈沉淀；支持渐进改进，不将案例当成受控因果实验 | 4/4，v3；订阅路径找到同一单集并串联跨段论据 |
| Q3「本期播客」：把 taste 写进 skills、补齐验证器，是否足以推出不再审查？区分主持人设想与 Dexter 判断，解释审查的 alpha、可维护性缺少 fast oracle 及开放组件预测的边界 | 主持人的理想条件；Dexter 的审查价值判断；没有快速可维护性判据不等于没有 benchmark；未来审查对象与时间未定；开放组件次序及领先期未定 | 5/5，v4；说话者区分正确，引用仅 `[1]` 且均合法 |
| 原生界面额外反事实：每日五个 PR 是否有合并率、缺陷下降百分比或对照实验，足以支持取消人工审查？ | 缺失数字必须明确说未提供；不从 PR 数量推算效果 | 正确说明三类证据未提供，不能推出取消审查；此题另行验证，不并入 13 分 |
