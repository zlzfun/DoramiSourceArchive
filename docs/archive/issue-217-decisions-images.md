## 现场与根因

- 原文：https://openai.com/index/decisions-api/ 。线上文章 `rss_openai_news_27825e3003584012` 于 2026-10-23 抓取，方法为 `playwright_html_selector`。
- 两张图是语音演示里的 neutral / thinking-bulb 素材，路径以 `/_next/static/immutable/media/` 开头。WebP 已受支持，故障不是编码格式问题。
- OpenAI 浏览器分支漏传 `base_url`：相对图链原样入库，预取仅认 http(s) 而跳过，浏览器最终向本站请求源站资源；相对正文链接也会丢失。
- 媒体代理实际 UA / Referer 请求图片仍返回 HTTP 403、`cf-mitigated: challenge`。原文浏览器里的子资源也失败；单独打开图片后，站点自动检查完成，可以显示原图。
- 独立无账号 Chromium 验证取得原始 WebP；正式媒体预取链路在沙箱得到 2 cached / 0 failed，尺寸分别为 400×400、190×209。
- 常见性：本地 125 篇与获授权只读查询的近期 86 篇，共 211 篇 OpenAI 文章中，仅本篇含相对 `_next/static` 图片，尚无其它同类案例。修复按该源静态资源地址形状覆盖，不绑定文章 slug 或两张图片名；不能据有限历史保证未来源站策略不变。

## 实现与边界

- 新采集：crawl4ai / Playwright 共用出口补文章基址，保留图片及正文。
- 存量显示：Markdown AST 根据 `sourceUrl` 解析相对图片地址；桌面、移动端、译文、公开分享页共用，不改历史正文。代码块、普通链接与问答引用不变。
- 媒体消费：提图链支持文章基址；预取、热点图、单篇重试、公开分享图链白名单、识图、Archive Sync manifest / 二进制白名单 / GC 使用同一口径。同步候选用文件名缩小范围，最后仍按解析后的完整 URL 精确授权。
- 取图：只有文章实际引用、位于 `https://openai.com/_next/static/(immutable/)media/` 的栅格图片且 HTTP 403 明确为 CF challenge 时启用 Chromium；每次独立上下文，不使用用户浏览器资料，不操作验证码。仅放行目标图片和站点检查资源，逐主机查公网性，禁止 service worker；响应阶段拦下所有 3xx，包含检查资源，防止跳转绕开请求路由守卫。
- 浏览器每实例串行取图，排队与取图阶段分别有超时；CDP 按块读原始响应，声明长度与实际字节双限，媒体库再查魔数；复用现有内容哈希、OSS、负缓存与同步所有权围栏。游客会话仍只读缓存；公开分享访客只能为该文章白名单内的图片触发取图。
- 恢复静态原图，不接入原站语音 API 或麦克风。没有全量回填；上线后可通过媒体库对该文章定点重试。原文 JSON 行号粘连另记观察期。

## 部署顺序

- 先升级内网 replica，再升级外网 authority 并对故障文章执行单篇媒体重试，两端应同波上线。
- 不应让旧版 replica 接收新解析的相对图媒体后继续运行超过 7 天：它的旧 GC 不认识相对引用，会误回收媒体并留下已前进的 checkpoint。若曾超过此窗口，升级后需运维安排媒体流重新同步；不要仅靠再次打开文章。
