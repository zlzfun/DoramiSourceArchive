# 早报播客导读入口（issue #269）

> 状态:归档（2026-11-09 实现、自测与用户放行完成；归档执行记录；用户已授权合入，发布状态以 PR / Release 为准）。

## 用户要求与范围

用户在早报「来源 / 时间 / 分数 / 兴趣」信息栏旁指定导读入口：没有音频显示「生成导读音频」，已有音频显示「播放导读」。覆盖所有播客条目，包括桌面/手机头条、普通分区与播客精选；普通文章不增加此入口。

本波不改变早报的选篇、排序、分数或冻结快照。#268 的生产模型配置与付费恢复独立跟踪：其本地真实音频验收已完成，产物复用于本波的早报播放验收；本波交互测试不触发供应商，本 PR 未修改生产。

## 实现

- `BriefPodcastGuide` 使用既有文章详情 GET 读取当前发布状态，避免历史早报快照永久停在无音频状态。按文章 ID 挂载，卸载中止读取；生成中每 4 秒检查，其他状态每 30 秒检查，页面隐藏时暂停，回到页面立即检查。
- `briefPodcastGuide` 统一识别快照内容类型、来源形态与历史 listen 通道。只认可播放 URL；文字就绪或 `ready` 标志不替代实际音频地址。
- 点击生成复用 `requestPodcastOndemand`；提交中/排队/合成/等待重试时保留同一按钮并禁止重复提交。旧 GET 不覆盖已接受的请求，读取失败只提供「重试加载导读」，不会因此重新生成；永久 404 停止自动轮询与前台自动刷新，仅手动重读，成功后恢复轮询。
- 用户额度、权限、全文依据、部署能力、费用账本与未知结果保护仍由原接口执行。拒绝原因通过现有 Toast 呈现；本波不承诺所有条目都满足后端生成资格。
- 游客可播放已有音频；点击生成先弹「登录后即可生成导读音频」，不发送生成请求。
- 播放进入全局播放器，原地播放/暂停，不打开文章。按钮在整卡打开覆盖层之上，手机高度至少 44px，保留键盘焦点环；键盘关闭播放条后焦点回到对应早报导读入口。

## 本地目检

打开当前会话给出的隔离预览地址，用本地测试账号登录；桌面进入阅读器 → 早报，手机直接进入早报。斯坦福 AI 原生工程播客现已显示「播放导读」，点击可听真实的 7 分 49 秒导读，并留在早报显示全局播放条。无音频时的「生成导读音频」状态见之前的截图及浏览器回归；缩窄窗口后入口可换行，不能被卡片标题覆盖。预览生成入口遵守本地关闭的 AI 配置并反馈不可用。
