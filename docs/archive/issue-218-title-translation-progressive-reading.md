## 1. 范围收敛与预期效果

| 项目 | R2 行为 |
| --- | --- |
| 所有内容类型的标题 | 新入库自动补齐中文译名，不按新闻分、来源热度或内容类型筛选 |
| 中文标题开关 | 阅读设置“默认显示中文标题”，默认开启；仅影响标题展示 |
| 资讯、论文正文/摘要、社交帖子、播客简介/逐字稿 | 沿用现有手动翻译入口、权限、额度和缓存，不自动调用 |

第一眼收益来自中文标题；正文等待收益来自“先读已完成的部分”。本方案不再追求“打开任意外文文章就已经有完整中文正文”。

撤销 R1 的正文预译范围、论文摘要/播客简介自动翻译、默认中文正文、社交译文自动展开、正文系统队列/金额池、内网全文译文覆盖表和相关能力标记。R1 的日 ¥10/月 ¥300、正文长度阈值及 7 天预译窗口均不沿用。

“所有标题”指所有新入库内容记录的标题字段，不等于历史全库回填，不扩展为章节标题、图片说明、源名称、节目名称或正文首段。已是中文、空标题、纯链接/标识符或无需翻译的专名原样保留；现有禁止外送来源继续跳过，标题也不能绕过此限制。历史标题回填可单独立项，不能因上线/重启悄悄执行。

## 2. 标题自动翻译

### 2.1 触发、资格与输入

1. 原文与轻量标题待办在同一事务落库，提交后原文立即可读，再由后台领取待办调用 DeepSeek；不在采集事务内等待模型。这样避免原文提交后、待办创建前进程退出造成漏单。
2. 对新入库的资讯、论文、播客、版本更新、仓库/模型卡等统一处理。社交记录如存在标题字段也可译该字段，但不把 `content`、`reposted.text`、`quoted.text` 送去自动翻译，不给原本无独立标题的社交卡片强加新标题区。
3. 输入仅原标题和既有标题翻译提示词，不附全文来提高质量；继续保留模型名、项目名、版本号与必要英文术语。明显异常的超长标题不截断后冒充完整译名，标为跳过并保留原标题。
4. 标题变更时旧译名立即失效并重新入队；只更新正文、图片、分析或阅读次数时不重译标题。已有有效中文标题缓存直接复用。
5. 只在原始内容的本地权威节点自动翻译。公共内容外网生成、内网同步；节点本地用户源按既有允许外送政策处理，不能因为是标题就扩大含凭证/私有来源的外送许可。

首次启用持久化新增水位；从此对新记录及其原标题后续变更产生的标题待办持续处理。待办持久化且可有界恢复，不能把标题为空/已译视为调用失败，也不能把重启视为全库补译信号。采用现有 cron 基础设施时使用 misfire_grace_time=300 与 coalesce；长时间积压分页处理。

### 2.2 复用存储和调用

继续使用 `translation_zh_title` 与 `translation_zh_title_fp`，原标题 `ArticleRecord.title` 不改写。复用 `reader_ai._translate_title()` 的语义和提示词，外网自动标题调用显式关闭思考；不更换现有问答、分析或手动正文模型配置。

新建轻量、独立的标题待办，拟以文章 ID + 原标题指纹 + 目标语言 + 标题流程版本去重。只需状态、尝试次数、下次重试时间和执行租约，不复刻一套正文分段系统。初期建议 1–2 个低优先级标题调用并发，防止冲击手动正文任务；模型调用在事务外，提交前再次检查原标题及来源权限。

现有早报标题补译和手动正文任务也会写同一标题缓存。应接入共享的标题去重/领取与发布逻辑，避免入库、早报和手动任务同时付费；若另一方已完成就直接复用。在途调用不能保证撤销计费，但只能发布与当前原标题匹配的结果。早报中的编辑标题 `title_cn` 仍只供既有展示使用，不能冒充忠实译名写回缓存。

所有内容类型都适用，但不是无限吞吐承诺：故障/配额暂停期间原标题继续展示，待办保留且后台恢复。建议每标题最多 3 次自动尝试；达到上限进入可观察失败状态，不能无限轮询重试。新模型/表变更在实现时必须配 Alembic 迁移。

### 2.3 费用与运行控制

新增调用用途 `auto_title_translate`，归系统开销，不扣某位读者的翻译次数；读者关闭“默认显示中文标题”也不会停止全站共享标题生成。原标题上限、单次输出上限、并发和有限重试构成基础控制，按 input/output token 聚合可观察用量。

不沿用 R1 的正文月度金额预算系统；如需硬上限，建议增加独立的每日标题 token 额度并复用现有逐调用原子预留/核销模式，数值在实施前以真实标题长度和日新增量确认，不能把本方案当作批准无限调用。达到上限后暂停新标题请求、保留待办，读取缓存和手动正文不受此池影响。AI 生成总闸及外送策略继续约束自动调用。

若按每标题含提示约 300 输入 token、100 输出 token 的示例，每天 1,000 条需要约 30 万输入、10 万输出 token；这是容量示例，不是测得均值或费用承诺。无需正文重译、ASR、额外摘要或逐段重试来获得中文标题。

## 3. 默认显示中文标题

### 3.1 设置与渲染优先级

设置文案为“默认显示中文标题”，布尔值默认 true。登录账户在同一部署跨设备保持一致；游客只记当前浏览器，不写共享 `guest:shared`。现有偏好接口改为可选字段更新，保存标题偏好不能覆盖登录默认界面等其它设置。

| 场景 | 标题展示 |
| --- | --- |
| 开关开，有有效中文标题 | 显示中文标题；详情保留查看原标题的方式 |
| 开关开，翻译未就绪/失败/原标题已变 | 显示原标题，不显示空白、加载遮罩或标题翻译按钮 |
| 开关关 | 显示原标题；已经生成的译名仍保留共享缓存 |
| 原标题为中文或无需翻译 | 原样显示 |

原标题与有效译名随既有列表/详情响应一并返回，在前端展示处选择，不按每条标题另发请求。当前页面不专门轮询标题；重新获取列表或详情时自然得到新译名，避免额外请求与阅读中的频繁跳动。

标题中文化作为内容展示，不要求读者开启 AI 或当日有生成额度；其内容访问权限仍与原文章完全一致。仅标题展示与付费权限解耦，不把 R1“正文缓存全面按普通阅读权限开放”的设计带回来。默认标题开关不改变正文默认语言，不创建正文翻译任务，不自动展开已有正文/社交译文。

### 3.2 页面覆盖与已有特例

覆盖所有现有的“文章标题展示位”：阅读列表与详情、搜索、收藏、手机页面、播客单集标题等，复用一个选择函数。没有独立标题的社交卡片保持原样。后台管理原始字段、导出/feed/MCP 的原始标题不按某位用户偏好修改；搜索索引也不改为中文标题索引。

正文翻译视图目前也会展示 `translatedTitle`，需与新开关统一：正文切中文不再暗中绕过用户关闭标题中文化的选择。此处是“开关只控制标题”的必要一致性调整，不影响正文翻译结果。

个人早报已有冻结的标题原文/中文字段：只在显示层按偏好选择已有字段，不重编、不重写快照、不以当下文章标题替换旧快照。公共日报、事件等已有编辑/派生标题继续原行为，不把“所有标题”扩成另一轮编辑内容自动改写；实施前盘点现有标题缓存消费者，避免新开关只对阅读器一处生效。

## 4. 正文并发翻译与分阶段阅读

### 4.1 当前基础与真正需要改的部分

现有 `translation_jobs` 已将每个通过校验的片段写入 `translation_chunks`；接口目前只返回完成数量，前端只在完整 `result` 出现时显示译文。`completed/total` 还可能包含一个标题任务，不能直接当作正文段数。

检查点文本仍含公式、代码、URL 等受保护占位符，需由同一 `TranslationPlan` 逆序还原；模型片段按约 3,500 字符拆分，一个片段可能含多个自然段，也可能跨表格行或长段边界。因此不能把数据库片段原样返回后逐片各自渲染 Markdown，更不能把半篇写进 `translation_zh`。

### 4.2 已选定交互：逐段占位、完成后原位替换

2026-10-26 用户选定第三稿并授权正式实施，取代第二稿连续前缀方案。点击“译为中文”后进入中文视图，未完成内容各有对应骨架，任意完整块完成后在原处出现；后台保持有界并发，文档顺序不变。

- 完成顺序 3 → 1 → 2 时，第 3 片所依赖的完整块先显示，第 1、2 片随后各自替换对应骨架。不等待前片、不增加逐自然段模型请求。
- 正常状态只有“中文”控件圈圈；不显示段数、进度说明或完成提示。删除进行中的“取消翻译”按钮，无替代取消入口；旧后端 cancel 端点仅作兼容保留。
- 骨架复用既有 skeleton 视觉，按原文块结构和大致篇幅占位；减少动效遵循应用开关。失败/暂停保留已完成块与静止骨架，只显示一处原因及可用恢复操作；读屏不逐片播报。
- 可见真实译文优先作阅读锚点；原文和中文分别保留阅读位置。手动切回原文后更新不能抢切中文。切篇/关闭只停止页面订阅，后台任务继续。

### 4.3 安全预览与最终发布

新增 `translation_preview` 根据同一任务输入身份重建 TranslationPlan。先还原源文并用 CommonMark 块映射建立稳定块身份，再映射到受保护检查点行；包含多行代码/公式的列表仍保持完整容器。自然段、表格、列表或引用可能依赖多个 API 片，全部依赖校验完成后才返回该完整块；不能逐片直接渲染占位符文本。

`preview` 独立于最终 `result`：首次/无效游标返回完整有序布局（id、source、kind、translation），后续只返回新完成块的 id/translation；客户端按 id 合并且不重排。游标是任务身份与已完成正文片的位图，不按最大 ordinal 推进，也不计标题片。任何输入变化、残余占位符或损坏检查点均不展示。引用链接只附当前块用到的定义，避免响应随段落数平方增长。

原位块统一走生产 ReaderMarkdown 的净化、媒体代理与公式链。最终仍由既有整篇组装和结构校验原子发布完整缓存，预览不写 `translation_zh`。正文所有块完成而标题尚待处理时，正文已可读。

### 4.4 完成通知

新增同权限 SSE `GET /api/reader/ai/translation-jobs/events`，事件 `snapshot` 与普通状态接口同型；支持 `preview_cursor` / Last-Event-ID。检查点提交后唤醒，跨进程及遗漏通知每 2 秒读取持久状态兜底。终态发送最后快照后关闭；断线客户端回退普通轮询，不能依赖内存事件恢复历史。

每次快照重新核验 cookie 有效期、session epoch、账户 AI 权限、文章可见性和任务输入，不能沿用长连接建立时的身份缓存。权限拒绝后关闭流；前端清除无权继续展示的预览。连接和普通接口复用游客策略与额度错误语义。

### 4.5 失败、恢复和输入变化

| 状态 | 行为 |
| --- | --- |
| 中途失败/达到现有额度 | 保留所有已完成的有效块；停止圈圈与骨架动效，只给一处原因及恢复入口；额度未恢复不提供立即重试，原文仍完整可读 |
| 兼容旧客户端留下的取消态 | 页面没有新取消入口；已有有效检查点可恢复，不冒充整篇完成 |
| 刷新或重新打开 | 先恢复可用进度；仍按当前正文默认原文规则，不自动进入中文预览；用户切到翻译视图后复用片段 |
| 原文、流程或模型配置改变导致任务失效 | 停用旧预览并回到当前原文，不能把旧片段嵌入新文章 |
| 当前用户失去文章/AI 权限 | 沿用既有门控停止获取并清除对应预览；不能靠长连接继续收正文 |
| 最终整篇校验失败 | 不能发布完整缓存；只保留通过局部及当前输入校验的预览并标“未完成”，不宣称语义质量已被证明 |
| 检查点过保留期被清理 | 按现行 7 天清理/容量规则，剩余预览不承诺永久保存；完整缓存不受影响 |

## 5. 论文、社交与播客：其它机制不扩展

- **论文**：只自动译论文标题；摘要和全文均不自动翻译。用户手动翻译全文时使用新的分段预览，保留公式、表格、参考文献及术语保护。分析仍用摘要，对外交付仍遵守摘要边界。
- **社交**：只涉及已有标题字段；帖子正文、转推和引用推继续逐卡手动翻译及原有展示方式。社交当前未接文章持久分段任务，不为本次需求强行迁移，不能承诺其同步翻译自动获得正文分段预览。
- **播客**：单集标题自动译；简介、逐字稿仍手动，ASR/制作权威/费用豁免不变。通过文章后台任务翻译的简介可复用分段预览；独立的逐字稿翻译目前不是该任务机制，本波保持原状，不加新的持久分段系统。

## 6. 内外网与原有正文缓存保护

公共标题在外网权威节点生成，合并已有标题缓存字段，经现有 `articles` 流同步。v3 触发器已监听扩展字段变化，不需新增译文流或更改 analysis payload generation。内网公共记录不重复自动调用；内网自定源按本地权威和外送策略处理。同步不会因此等待标题就绪，内网首屏是否已有中文标题还取决于一次正常同步周期。

只同步最终标题缓存；手动正文的片段预览、任务、检查点、账户开关及用量账本均留在各节点，不新增跨网任务指令。完整正文的现有同步行为不在本波扩大。

一个必须处理的兼容点：当前内网导入会整体替换文章扩展，频繁增加“仅标题更新”的同步可能擦掉内网已生成的正文缓存，使“其它维持原状”受到影响。建议**窄范围合并保护**，不沿用 R1 的全文覆盖表：在导入同一原文/同一权威的标题更新时，仅保留本地通过当前指纹校验、且远端没有提供有效替代的既有正文/社交译文缓存；远端有效缓存优先，原文或社交快照变更立即失效，不保留所有未知扩展字段。

保护字段组必须显式列出正文、版本与指纹，社交按主推/引用推指纹校验；无指纹 legacy 缓存不能在一次同步覆盖中擅自当作已验证缓存保活。标题变化只失效标题，不应让不变正文的已完成缓存丢失；旧在途任务仍按现有输入身份规则处理。文章删除、authority 变更与现有撤回规则不被合并逻辑绕过。

接收端先支持上述保护，再启用外网标题补译。外网、内网都是 `runtime.role=all` 时仍按现有 source/article authority 与 consumer fence 决定写者，不能按 runtime 字段区分。通用代码归 main，内网专属端点/部署适配仍只归 master。

## 7. 实施拆分与验收

| 步骤 | 改动 | 验收重点 |
| --- | --- | --- |

## 9. 开工核对（2026-10-24）

Codex 子代理只读核对最新主线，未改业务代码。以下约束用于后续实现，样页不冒充已接通：

- **持久待办**：`DatabaseStorage.save()` 有多个元数据刷新分支；播客刷新成功也可能返回 `False`，不能仅按返回值投递。轻量待办与原文同事务，模型请求提交后执行；原标题指纹、资格在领取与发布时复核。
- **标题发布**：现有 `reader_ai._save_translation()` 也比较正文，不直接用作自动标题发布；标题专用路径只约束原题与权限，重读最新扩展再写。`personal_digest_titles.localize_edition_titles()` 的早报补题同样接入该路径，避免旧 ORM 快照覆盖新正文缓存。
- **同步指纹**：`compute_content_hash()` 包含原标题，论文又取分析摘要，不能用它判定正文译文是否可保留。正文按接收后实际 `content.strip()` 与版本校验，社交按 `social_translation_sources()` 的主推/转推、引用推快照校验；不以 legacy 宽松规则保活无指纹缓存。
- **计量**：新用途 `auto_title_translate` 必须进入 `ai_usage.VALID_PURPOSES`。现有 `TranslationCallRecord` 未分用途，其 hold 被读者预算累计，不能直接混入自动标题调用；独立预留或加用途并修改全部消费者。标题专用配置显式关闭思考，`for_aux()` 本身不保证关闭。
- **列表契约**：`serialize_article_list_item()` 增加轻量有效中文标题字段；不能为显示标题把全文扩展带到列表响应。偏好更新只写明确传入字段，游客仍用浏览器状态，内外网账号偏好不随公共内容同步。
- **预览**：同一任务身份重建计划，后台保留全部有效片段，按每个完整 Markdown 块的依赖集合决定是否原位显示。增量游标不能用最大 ordinal，任务数须排除可选标题片段；损坏检查点不得展示。正文状态与标题开关独立，切回原文后后台完成不能强制切中文。
- **范围**：社交同步翻译和播客独立逐字稿不自动获得新的分段系统；异步标题未就绪回退原题，内网仍有同步周期。当前约 2 秒轮询不称为零延迟，通知方案待实现验证。
