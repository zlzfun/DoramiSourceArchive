# 设置 · 聚合接口列全令牌可调的接口(issue #315)

> **归档于 2026-11-20(issue #315,开发版 3.70.0-alpha)**:现状以 `docs/architecture/reader-distribution.md`「令牌接口在设置页的清单」与代码为准,文中路径与状态为当时记录。
> 状态:归档(2026-11-20 立项、出第一轮样页;同日用户「全按推荐」拍板方向 A,同日实现;同日用户在沙箱目检后放行:「可以,开 PR。」)。
> 样页:[`docs/design/issue-315-feed-endpoints/`](../design/issue-315-feed-endpoints/README.md)。实现方 Claude Code(Fable 5.2);检视方 Codex(见 §8)。

## 1. 来由

issue #312 目检时用户指出:issue #310 新增的「用令牌拉热点事件榜」在设置 → 聚合接口没有明示,普通读者没法知道系统里现在有哪些接口可调。查下来属实,而且不止这一条。

## 2. 当时的现状(v3.69.0 + issue #312)

个人聚合令牌(`dfeed_`)能调 5 个 HTTP 接口,设置页列了 2 个:

| 接口 | 设置页 | 范围 | 一次最多 |
|---|---|---|---|
| `GET /api/public/feed/articles` | 列了 | 已订阅来源(管理员:全站公开内容) | 500 条 |
| `GET /api/public/feed/articles.md` | 列了 | 同上 | 200 条 |
| `GET /api/public/feed/articles.xml`(Atom) | 没列(v3.20 起就有) | 同上 | 200 条 |
| `GET /api/public/feed/events` | 没列(issue #310) | 全站公开内容 | 10 件 |
| `GET /api/public/feed/events/{event_id}` | 没列(issue #310) | 全站公开内容 | 1 件 |

- 设置页之外读者没有别的途径:应用里没有指向用户手册的链接;自动生成的接口文档页在容器部署下到不了(nginx 只转发 `/api/` 与 `/mcp`)。
- 事件榜是 issue #310 有意延后的(卡头的范围签写「已订阅来源」,事件榜是全站口径,要重想范围怎么表达);Atom 是一直漏着。这张卡靠人手维护,没有东西保证它和后端一致。
- 顺带查到:页面的「接口参数」写「limit 上限 500」,只对 JSON 成立,Markdown 上限 200 且不认 `include_content`;Atom 接口在 `docs/contracts/reader_subscription.md` 的接口清单与 `docs/reference/endpoints.md` 里没有记,契约的参数表还把 `include_content` 写成只有 JSON 认(Atom 也认)。
- MCP 分区的 5 个工具是列全的;单订阅令牌(`dsub_`)没有任何界面。

## 3. 拍板(2026-11-20,用户:「#315 全按推荐,开始开发。」)

样页给了两个方向六项待定,用户全部取推荐:

1. **方向 A 分组列全**:一行一个接口,写真实路径;点开一行是它的调用示例和它认的参数。(没选 B「一组一行,行尾分段切换」——五个地址里有三个要点一下才看得到。)
2. **打开时全收起**:五行一屏看全,不出滚动条。(没选「第一行点开」。)
3. **行尾标返回格式**:JSON / Markdown / Atom。
4. **卡头加一条通往「MCP 接入」的链接**(那边已有一条通回来的)。
5. **Atom 的示例是把令牌写在地址里的一行订阅地址**:RSS 工具带不了请求头。代价:契约把地址里带令牌记为安全性较低的退路(地址会进访问日志)。
6. **单订阅令牌的接口不列**:这种令牌现在没有界面。

范围的表达随方向 A 定下来:范围签从卡头挪到组上——文章按订阅裁剪(管理员不受限)、热点事件对谁都是全站,一枚令牌两种范围,写在卡头只对得上其中一组。

## 4. 做法

- **清单单点** `frontend/src/utils/feedEndpoints.js`(纯数据 + 纯函数,无 React 依赖):`FEED_ENDPOINT_GROUPS` 两组五条,每条记方法、路径、它在交付计量里的名字(`channel`)、返回格式、示例的写法、它认的参数(`names` 是后端真正的参数名);`FEED_LIMITS` 是后端的六个数(条数上限 500 / 200、Atom 不下发正文时的摘要长度 280、事件榜默认窗口 168、最大窗口 336、件数 10),参数说明里的数由它拼出来;四个函数给出范围签、地址、示例、参数行。组的 key 与名字和 issue #312 的接口组(`utils/deliveryChannels.js`)同一套,运维 → 账户抽屉「接口调用」里写的接口名就是这里的 `channel`。
- **设置卡** `components/settings/FeedTokenSection.jsx` 照清单渲染,自己不再写任何接口地址:
  - 卡头:去掉范围签,右端加「MCP 接入 ›」(`SettingsModal.jsx` 传 `onOpenMcp`)。令牌槽、签发 / 重新生成、「最近调用」那一行都没动。
  - 两组:组头 = 组名 + 范围签;组里一行一个接口——`GET`、地址、返回格式、复制钮。
  - 一行是一个 `<details>`:点开是调用示例(带复制钮)与参数行。同时只开一行;开合以 `<details>` 自己的状态为准(点行、键盘、浏览器页内查找都会改它),组件只跟着记是哪一行。点开靠下的一行时,等别的行收起后把它带进可视区(不做滚动动画)。行尾的复制钮只复制,不开合这一行。
  - 原来卡片底部的一条 curl 示例和「接口参数」折叠没有了,内容分到了各行里。
- **样式** `frontend/src/index.css` 加七个类(`.ep-group` `.ep` `.endpoint-fmt` `.ep-body` `.ep-code` `.ep-code-text` `.ep-params`),取值只用现有 token;收起的行与原 `.endpoint` 同高(42px)同底。示例的文本自己一层横向滚动,复制钮在滚动区外(检视返修:钮比一行文本高,放在滚动容器里上下沿与焦点环会被裁)。行首的 ▸ 与 `.scope-note` 是同一枚 9px 图形字符,字号守卫(`typography.test.mjs`)的图形字符豁免里加了这条选择器。
- **对账守卫** `frontend/test/feedEndpoints.test.mjs`(10 条),读后端 Python 源码逐项比:
  - `/api/public/feed/` 下的路由与清单一条不多一条不少(方法也比)。解析前去掉注释、清空文档串;认 `@app.` 与 `@<router>.` 的全部 HTTP 装饰器,路径取第一个位置参数或 `path=`,路由器自带的 `prefix` 会拼上,带占位符的路径段按「能匹配任何值」算。读不懂的写法一律失败并指出文件与行号,但只对与令牌接口有关的声明这样要求:路径或 `prefix` 读不出(不是字符串字面量、也不是本文件的字符串常量)、`add_api_route` / `api_route` 落在令牌接口前缀下、`include_router(prefix=…)` 挂的是声明了令牌接口的路由器或挂上后会落到前缀下——这些失败;无关路由器带 `prefix` 挂载、注释里提到这些写法,不失败。
  - 清单写的参数后端都认;后端认而清单没写的,只能是测试里 `UNLISTED` 点过名的(现在两个:`content_type` 是 `content_types` 的单值旧写法,`has_content` 默认只给有正文的条目)。参数用了 `alias`(对外的名字不再是参数名)时失败。
  - 说明里写出来的布尔默认值(`include_content` 默认 true、`include_members` 默认 false)与后端一致。
  - 条数上限、事件榜默认 / 最大窗口与件数、Atom 的摘要长度,和后端一致;两条事件接口确实都过范围检查。
  - 每条接口的计量名在 `services/token_usage.py` 里登记过、归的组一致;组名与 `DELIVERY_GROUPS` 一致。
  - 范围签:事件榜两条取数时不传令牌主人(哪天开始按订阅裁剪,「全站公开内容」这枚签要重新想)。
  - 示例:curl 两行、带占位符的接口换成能发出去的地址、Atom 是地址里带令牌;示例里的查询参数这条接口都认;后端仍从 `?token=` 读令牌。
  - 设置卡从清单取数、不再手写 `public/feed`。
  - 放在前端测试里是因为 CI 的前端任务每个 PR 都跑(只改后端的 PR 也跑);代价是读源码而不是读跑起来的路由表,所以每处读不出预期形状时都明说「请更新本测试」而不是放过。
- **说明位守卫** `explanatorySlots.test.mjs`:`scope-note` 在册数 3 → 2(「接口参数」折叠没有了);参数行的类 `ep-params` 按名字不属于说明位,仍登记了 1 处,免得这块参考内容从守卫的视野里消失。
- **文档**:契约 `docs/contracts/reader_subscription.md` 的接口清单补 Atom,更正 `include_content` 的适用面与条数上限;`docs/reference/endpoints.md`、`docs/architecture/reader-distribution.md` 记清单单点与对账;用户手册 `docs-site/features/integrations.md` 改写聚合接口一节并重拍截图。
- **不改后端**:任何接口的请求与返回都没动。

## 6. 部署顺序与混版本

纯前端 + 测试 + 文档;不改接口、不动库、不进 Archive Sync。外网、内网先后升级互不影响。页面列出的五个接口后端早已都有(Atom 自 v3.20,事件榜自 v3.69.0),而新页面随 3.70.0 发出时后端同版本,不存在「新页面配旧后端」的组合。

实现方 Claude Code(Fable 5.2);检视方 Codex(`gpt-6-astra`,effort ultra,本地 `codex exec` 只读沙箱)。任务书、报告、表态与修复清单在 worktree `.review/`(不入库)。

**第 1 轮(全面检视):「修后可合入」,无 P1,4 条 P2、2 条 P3。全部接受,没有分歧。**

| 条目 | 意见 | 修法 |
|---|---|---|
| 1(P2)| 对账测试只认「第一个位置参数是字符串字面量」的装饰器:用 `@router.get(path="…")` 新增令牌接口它不红;读不出的 `prefix` 被当成空串 | 已知路由器的全部 HTTP 装饰器都进解析,路径取位置参数或 `path=`;路径、`prefix` 读不出就失败 |
| 2(P2)| 参数表里的注释会把后面一个参数吞掉(`# …` 换行 `order: … = None`),新增参数不红 | 解析前去注释、清空文档串;参数段认不出名字时失败而不是跳过 |

| 6(P3)| 「读不懂就失败」的范围太宽:无关路由器带 `prefix` 挂载、注释里出现 `add_api_route(` 都会红 | 去注释;`include_router(prefix=…)` 解析被挂的是哪个文件的路由器,只在与令牌接口有关或解析不出时失败;`add_api_route` / `api_route` 同理 |
