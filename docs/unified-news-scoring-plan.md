# 统一新闻价值评分波：文章评分单尺子化 + 日报复用入库分析(设计讨论稿)

> 状态:**讨论定向,未动工**(2026-09-05)。方向由 §0 承载;§1 保留讨论脉络与论据,
> 其中被后期观点推翻的前期结论以「已推翻」标注,只作决策来龙去脉,不作现状依据。
> 缘起:issue #13(阅读窗摘要复用与精简,v3.45.1)收官后的自由讨论——从「日报能否复用
> 入库分析的评分」出发,一路推到「平台定位是新闻价值为主,文章级评分只保留一把尺子」。
> 相关现状:v3.44 文章分析(`services/article_analysis.py`,`quality_score` 语义=全局阅读价值)、
> 公共日报 map/select/render 链路(`services/daily_brief.py`)、v3.44 为公共日报预留的
> analysis adapter(KV `public_digest_analysis_adapter_enabled`,默认关)与 shadow 指标。

## 0. 结论与方向

**定位**:平台以**新闻价值**为主。文章级评分只有一把尺子——「这件事有多重要」,不再量
「这篇写得好不好」。理由:重要性比阅读价值更有共识(GPT-6 发布是头等大事所有读者都认,
一篇小众随笔值 8.6 分则一半读者不认);分数要给所有人看,就该量共识高的那个东西。

**一条流程**:文章入库后的分析调用是全站唯一的文章级 LLM 评估,一次调用产出
重要性分 + 一句理由 + 摘要 + 体裁 + 规范标签 + 实体(+ 可选的要点排版与中文标题)。
消费方——阅读器、个人早报、公共日报——都读这份结果。公共日报的 map 逐篇打分退役。

**日报对分析是软依赖**:日报运行时,候选中尚无分析结果的文章由日报**就地调用同一个
分析函数**补评,结果写回分析表,**不设上限**;不做「附录未评估」,不做「延期名单明天补登」
——漏掉一条大新闻不可接受。最坏情况(worker 整晚没动)成本等于今天的 map,不会更贵。

**日报保留的 LLM 调用只剩三处,都不是评分**:入选后每篇一次「点评 + 中文标题 + 要点排版」、
同事件聚类、跨天查重。点评与中文标题**不并入**分析调用(覆盖面不对等 + 编辑口吻与中性
描述冲突)。公司/领域两个字段由分析的实体与行业标签机械推导。

**机械层原样保留**:官方源同分置顶的 +0.5 有界加成、来源/领域多样性、论文占比上限、
候选时间窗(时效由窗口给)。

**配套约束**:
- 日报名单内的源**必须开着分析**(源级开关语义是「不允许对这个源跑分析」,日报不得打穿);
  配置面板校验,反向关分析时提示将从名单退出。
- 读者面分数**改名**(「内容价值分」→「资讯重要性」之类),评分理由随之改为「为什么重要/不重要」。
- 个人早报的意义从「订阅范围里值得读的」变为「订阅范围里最重要的」:兴趣通道的分数门槛
  放低或不看分数只看标签,否则博客订阅者的早报会经常空掉;既有「订阅源最新更新」降级通道兜底。
- 评分文档必须给**非新闻体裁写实锚点**(里程碑论文、被广泛讨论的观点、行业级教程各留上行空间,
  量的是影响力不是写作水平),否则占语料两成的论文/教程/观点会全部塌在 4–5 分失去区分度;
  并补**领域相关性**一条(一篇职场随笔在 AI 资讯产品里不该是 7.8)。

**方案排序**(讨论终态):单轴新闻价值 > C(一条流程两步) > B(一次调用两个分) > A(维持两流程)。

**动工前先看数据**:读生产 KV `daily_brief_analysis_shadow_metrics`(v3.44 起每期记录 map 分
与分析分的偏差分布),别只凭 dev 的 210 篇定案;手标约 30 篇黄金集作为提示词改动的门禁。

## 1. 讨论脉络与论据(按时间;含被推翻项)

### 1.1 日报生成不是「取摘要、按分排序」

实际链路:map 阶段每篇一次 LLM 调用(中文标题、1–3 条加粗要点、100–150 字点评、重要性分、
分类、公司、领域)→ `dedup_clusters` 同事件聚类(簇内官方源在 1 分差内优先当代表)→
`select_top` 按「分 + 0.5×官方」有界加成排序,再叠来源/领域多样性与 `paper_cap` →
`cross_day_dedup` 对照近几期日报 → 确定性渲染(分类固定顺序、类内按分降序)。
分数只是排序输入之一,被三层去重与多样性规则修饰。

### 1.2 复用与归一化:两把尺子刻度相同、量的东西不同(已被 §1.6 部分推翻)

v3.44 的 adapter 已能用分析的分数/summary/分类/标签覆盖 map 产出并记 shadow 指标,但它是
事后覆盖,map 照跑——点评、中文标题、公司、领域仍只有 map 产,没有省到钱。

| | 分析 quality_score | 日报 map score |
|---|---|---|
| 量什么 | 内容本身的全局阅读价值 | 当日资讯的重要性与读者相关性 |
| 时效 | 无 | 隐含(候选本就是当日窗口) |
| 品牌 | 明令不加分 | 不加分,但有「风向标厂商例外」 |
| 读者偏好 | 无 | 车载降权、营销稿重罚、模型发布优先 |
| 步长 | 0.1 | 0.5(8.0 为入选线) |

初版方向(**已推翻**,见 §1.5–1.6):保留分析分为「内容价值」,日报有效分 =
分析分 × 时效与新闻性杠杆;杠杆全在机械层可配置(体裁权重、官方加成、行业标签降权、
实体标签加成)。真正的收益点在**把 map 挪到选篇之后**——只为入选十几篇写点评与中文标题,
map 调用从每天上百篇候选降到入选篇数。这一点在终态中保留。

### 1.3 时序:日报生成与分析完成的关系

现有节奏:全量采集 07:10,日报 08:30,中间 80 分钟;分析 worker 每分钟一轮、每轮领
`map_concurrency` 篇、`fetched_date` 倒序(早上刚抓的先分析);dev 实测高峰每小时 124 篇,
日报候选每天约一两百篇——正常情况 08:30 前基本跑完,「等分析」是安全网不是常态路径。

个人早报(v3.44)已有同构先例:冻结范围、就绪判定(`calculate_due_source_ids`)、
首开期限(08:30 + 15 分钟)、到期降级、降级原因落库。公共日报只是把「就绪」从
「源的采集完成」换成「候选文章的分析完成」。

初版五层设计(部分**已推翻**):①覆盖率就绪(分母排除源关闭分析/无正文)②等待有期限
(08:30 起每 5 分钟复查,最迟 09:15)③到期就地补评、设上限、超出进「其它收录」标「未评估」
④延期名单存 KV 下次注入 ⑤名单与分析开关联动。

用户否决 ③ 的上限与 ④:「明天补登就是漏,某个大新闻恰巧漏了无法接受」;「宁多费功夫也不漏」。
→ 终态:补评不设上限,③④ 的附录未评估与延期名单**取消**。单篇补评失败沿用 v3.35 现有做法
(串行重试一轮,仍失败进附录裸标题)——与今天 map 失败处理相同,不是新增漏点。
真正还会「漏」的只有「日报跑完之后才抓进来的文章」,那是明天的候选,现状亦然,
且已有同日增量合并可手动补一期。

依赖性质的澄清:日报**强依赖分析这个能力**(函数:提示词、解析、写回),**不强依赖 worker 的进度**。

| 情形 | 后果 |
|---|---|
| worker 慢或停 | 日报就地补评,慢几分钟、多付一些钱,内容不变 |
| LLM 端点挂 | 日报出不来,与今天 map 挂掉一样,不是新增依赖 |
| 单篇补评失败 | 串行重试一轮,仍失败进附录裸标题(现有处理) |
| 分析总闸关着 | 日报绕过总闸直接调函数;总闸管 worker 不管函数 |

推论:有了无上限的就地补评兜底,08:30 的「等覆盖率」从必需变为可选优化(用几分钟换省钱),
可先不做,看生产数据再定。

用户提出的另一变体——「来不及分析的直接按日报标准评」:调用次数一样,区别只在用哪套标准;
用分析标准则与其它文章同尺、结果可写回复用;用旧日报标准则多一套刻度混进同一排序且算完即丢。
→ 选前者。(在单轴终态下两者本就合一。)

### 1.4 日报口味逐条归宿(在「分析分 × 杠杆」初版框架下;终态见 §1.6)

| 日报 map 的规则 | 初版归宿 |
|---|---|
| 营销稿、软广、榜单认证重罚 | 分析 1–4.9 档已覆盖 |
| 大厂名号本身不加分 | 两边一致 |
| 旗舰模型/核心 API/开源权重 7–10 | 分析 8.5–10 档 + 杠杆按 genre 加权 |
| 企业案例、区域上线、纯增量压 4–6 | 分析本就低分 |
| 官方源同分置顶 | 已是机械层 |
| 论文占比上限、来源多样性 | 已是机械层 |
| 车载、智能座舱降权 | 杠杆用行业标签降权 |
| OpenAI/Anthropic 小功能不机械压分 | 杠杆用实体标签有界加成 |
| 产品线 GA、重大里程碑 7–8.5 | **缺口**:分析分与 genre 都分不出里程碑与小更新 → 拟补描述性字段 `event_scale` |

口味放杠杆而非提示词的理由:透明可调(改一个数就生效、不重跑分析、不污染尺子),
与 v3.35 官方加成同一做法。——在单轴终态下,这些口味直接进唯一评分文档,不再需要杠杆重建。

### 1.5 转向同一标准:A/B/C 三形态

触发数据(dev 库 210 篇 succeeded,按体裁均分):

| 体裁 | 篇数 | 均分 |
|---|---|---|
| tutorial | 6 | 8.38 |
| research_paper | 24 | 8.38 |
| opinion | 13 | 7.82 |
| industry_news | 29 | 6.89 |
| model_release | 24 | 6.82 |
| product_update | 102 | 6.04 |

分析尺子奖励原创、论证、实践价值,随笔与论文高于模型发布——对「今日要闻」是倒的。
Sean Goedecke 五篇 7.5–8.6(全部 opinion),其中「You should never be angry at work」7.8:
暴露分析尺子缺「与本产品领域的相关性」一条。

| | 独立性 | 每天成本 | 日报对分析的依赖 |
|---|---|---|---|
| A 两流程(维持现状) | 完全独立 | 分析 + map,与今天相同 | 无 |
| B 一次调用两个分 | 有渗漏风险,可测 | 只有分析 | 有,就地补评兜底 |
| C 一条流程两步 | 完全独立 | 分析 + 一次约 300 token 轻调用 | 有,就地补评兜底 |

B 的诚实边界:「点评的问题是声音」(人设是全局指令,一份提示词装不下两种声音,结构性冲突);
「两个分数的问题是光环效应」(判断相互渗漏,只能压低与测量,不能靠设计消除)。压低手段=
成对反例锚点(「深度职场随笔:阅读价值 8 / 新闻重要性 3」「三行字的旗舰发布:6 / 9」);
测量手段=黄金集(两分 Spearman > 0.85 视为塌缩;按体裁必须出现反转)。

C 的要点:第二步只喂分析产出的标题、摘要、体裁、实体、来源角色,**刻意不喂阅读价值分**,
光环在输入侧切断;不读全文故比 map 便宜一个量级;跟在同一 worker 任务里紧接着跑,仍是一行记录。

用户提出「A + 入库分数做日报初筛」:**不成立**——两把尺子按体裁反着,用阅读价值设门槛先筛掉的
正是三行字的旗舰发布;要不漏只能把门槛压到 4 分以下(dev 占 4%),省 4% 换筛错风险不划算。
去掉初筛,A 就等于不做这次改造。

当时排序:C > B > A。

### 1.6 终态:单轴新闻价值(推翻 §1.2 的双轴前提与 §1.5 的 B/C)

用户提出:「完全不考虑阅读价值,平台定位就是新闻价值为主。」评估结论:最自洽,比 B、C 都干净——
定位一旦是新闻价值,前面所有纠结消失:不存在两个分互相渗漏、不存在初筛筛错、不存在黄金集要验两个轴。

代价三处(即 §0 的配套约束):读者面分数含义变了要改名;个人早报意义变了要调门槛;
非新闻体裁锚点必须写实(否则两成语料塌在 4–5 分)。

顺手好处:现行日报 MAP 提示词经 v3.35、v3.39.2 两轮生产实证校准(风向标例外、里程碑与小更新
区分、营销重罚、厂商主次甄别),单尺子方案等于把它提升为全站唯一评分文档,再补领域相关性
与非新闻体裁锚点,起点不是从零。将来真需要「阅读价值」,再作为第二轴加回——从单轴长到双轴,
比现在背着双轴的耦合问题走容易。

### 1.7 点评/中文标题/要点是否并入分析调用

- **点评、中文标题不并入**:①覆盖面不对等——分析跑所有开启分析的源的每一篇,日报候选只是名单内
  一部分、入选更只有十几篇,点评 100–150 字约 150 token,给每篇分析都写等于为大量永不上日报的
  文章付费,总量超过今天的 map;②口吻——点评是日报的编辑声音带判断取舍,分析是中性描述。
- **要点排版可并**:分析已产一段客观概述,日报要 1–3 条加粗要点,同一内容两种排版;
  可让分析多产 `key_points`(约 80 token),或日报改用段落式摘要。实施时定。
- **中文标题可选并入**:每篇都有用,阅读器现有标题翻译是另一条按需缓存路径,`title_zh` 并入
  约 20 token 可直接复用。锦上添花,实施时定。

## 2. 实施草图(动工时细化,此处只钉方向)

1. **评分文档**:以现行 `MAP_SYSTEM_PROMPT` 的锚点体系为底(旗舰/里程碑/常规/边角四档、厂商主次甄别、
   风向标例外、车载降权、营销重罚),并入 v3.44 分析提示词的标签/实体/摘要契约,新增领域相关性
   与非新闻体裁锚点;输出 重要性分(0.1 步长)+ ≤40 字理由 + summary + genre + tags + entities
   (+ 可选 key_points / title_zh)。`ARTICLE_ANALYSIS_PROMPT_VERSION`/`SCORING_VERSION` 同步升级
   → 近 7 天存量自动重跑,更早等 `full_analysis` 回填。
2. **消费方**:阅读器与列表投影分数改名;个人早报 `min_quality_score` 策略与兴趣通道门槛重定;
   公共日报链路改为 候选 →(可选)覆盖率检查 → 就地补评(无上限,同函数写回)→ `select_top`
   (重要性分 + 官方加成 + 多样性 + `paper_cap`)→ 聚类 → 跨天查重 → 入选后逐篇
   「点评 + 中文标题 + 要点」调用 → 渲染;`map_summarize` 逐篇打分退役;adapter 与 shadow 指标退役。
3. **配置校验**:日报名单 ⊂ 分析开启源(面板双向校验)。
4. **黄金集**:约 30 篇手标重要性分,作为提示词改动的门禁测试。
5. **观测**:`last_run` 记覆盖率起点、就地补评篇数;流水线视图视需要加「补评」阶段。
6. **明确不做**:延期名单、附录未评估、阅读价值第二轴、日报自己的评分标准。
