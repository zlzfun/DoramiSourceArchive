# 移动阅读器布局 Evolution

## 2026-09-15 · 修复移动分流与导航失踪

- 发生：用户截图中桌面导轨在手机上纵向占据大半屏，内容被挤到下面且无法滚动。要求底栏贴住可视区域底部，优先代码简洁和桌面隔离，确认沿用现有底栏而非新增侧边主导航。
- 分析：本机在“宽屏启动再缩窄”及 900px 直接启动复现同类布局。App 只在首次挂载时按 767px 分流；桌面 CSS 在 1024px 以下改成单列，但根滚动仍锁住。异常状态根本没有移动底栏，不是底栏位于更下方。仅监听断点并替换整个 App 分支会卸载阅读状态，因此将数据与共同页面状态保留在稳定的 ReaderWorkspace，由两种已有视图消费。
- 改变：统一阅读器断点并监听变化，移除桌面单列降级，保持同一数据实例；滚动位置在内存恢复，哨兵随 DOM 重绑。实测还发现移动层卸载留下空历史、StrictMode 重挂载重复压栈，补充批量卸载回退，并用反复宽窄切换验证。移动正文已有按文章 ID 的 key，删除重复的挂载后滚动归零，以免覆盖跨版式恢复进度。
