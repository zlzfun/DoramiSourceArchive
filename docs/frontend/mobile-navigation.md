# 移动阅读器布局（Issue #86）

## 用户体验

- 视口宽度不超过 1024px 时使用现有移动阅读器：主导航贴住可视区域底部，中间内容独立滚动，沿用系统安全区留白。
- 文章、播客、动态、社交和「我的」保留底部入口；启用个人早报时沿用早报入口。来源筛选使用现有侧滑抽屉。
- 正文、发现和设置沿用整页层：正文阅读时隐藏底部导航，返回列表后恢复。系统返回先关闭当前层。
- 宽屏使用现有桌面四栏。窗口跨过断点时保留同一份阅读数据、栏目、筛选、当前文章与早报返回路径；列表按滚动偏移、普通正文按阅读进度比例恢复。

## 实现边界

`useCompactLayout` 监听媒体查询变化；`App` 保持阅读器挂载位置稳定；`ReaderWorkspace` 持有 `useReaderState` 及共同页面状态，向 `ReaderTab` / `MobileReader` 提供同一份数据，只切换视图。

滚动位置仅保留在内存，记录列表和正文两个区域，不复制文章数组、不写入 storage。无限滚动通过回调 ref 跟随新的哨兵节点；移动层卸载时合并消费历史，避免缩放后多出空返回步骤。

两个现有视图随阅读器入口一起加载，避免切换中再下载外壳；不在浏览器中同时挂载两套阅读界面。管理页继续按访问记录惰性挂载，宽屏管理台不重新设计。后端契约、数据库和 PWA 安装能力均保持现状。

## 验证入口

在仓库根目录运行，目标为已启动的本地 Vite 开发或构建预览服务：

```bash
.venv/bin/python scripts/check_mobile_navigation.py --base-url http://127.0.0.1:5186 --output tmp/issue-86/browser
cd frontend && npm run lint && npm test && npm run build
```

浏览器脚本使用本机 Chrome；API 请求由合成数据拦截，不登录真实账户、不写业务库。输出包含检查结果与长列表、正文、亮暗色截图。自动检查覆盖窄屏启动、宽窄往返、底栏可见与点击、内容滚动、正文进度、返回栈、无限滚动和触屏模拟；这是前端回归，不替代真机及后端验收。
