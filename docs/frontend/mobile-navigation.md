# 移动阅读器布局（Issue #86）

## 用户体验

- 视口宽度不超过 1024px 时使用现有移动阅读器：底栏是浮在内容上的磨砂胶囊（离可视区域底部 8px，往下读时退场、往上一划回来），中间内容独立滚动，沿用系统安全区留白。
- 底栏是功能模块：早报（启用个人早报时）· 内容 · 订阅 · 榜单（issue #230 第 2 批）。文章 / 播客 / 社交在「内容」页头的标题位转盘里切换，列表顶部可按内容类型横向滑动筛选（issue #178）；来源、收藏与兴趣列在「订阅」Tab；设置从页头头像推入（原「我的」并进设置页）。
- 正文、发现和设置沿用整页层：正文阅读时隐藏底部导航，返回列表后恢复。系统返回先关闭当前层。
- 宽屏使用现有桌面四栏。窗口跨过断点时保留同一份阅读数据、栏目、筛选、当前文章与早报返回路径；列表按滚动偏移、普通正文按阅读进度比例恢复。

## 实现边界

`useCompactLayout` 监听媒体查询变化；`App` 保持阅读器挂载位置稳定；`ReaderWorkspace` 持有 `useReaderState` 及共同页面状态，向 `ReaderTab` / `MobileReader` 提供同一份数据，只切换视图。

滚动位置仅保留在内存，记录列表和正文两个区域，不复制文章数组、不写入 storage。无限滚动通过回调 ref 跟随新的哨兵节点；移动层卸载时合并消费历史，避免缩放后多出空返回步骤。

两个现有视图随阅读器入口一起加载，避免切换中再下载外壳；不在浏览器中同时挂载两套阅读界面。管理页继续按访问记录惰性挂载，宽屏管理台不重新设计。后端契约、数据库和 PWA 安装能力均保持现状。

## 验证入口

真实后端端到端测试见 [E2E 说明](./e2e.md)(#90):`cd frontend && npm run test:e2e`。移动壳的守卫在其 `guards` 流程里——
360 / 375 / 390 / 430 四档的返回键矩阵、长按动作单、触控与输入字号抽样、长列表 DOM 上限,以及 1024 / 1025 首启分流。

原先的前端合成 API 回归 `check_mobile_navigation.py` 已于 issue #230 批 4b 退役:它的选择器停在第 2 批之前的五 Tab /
源抽屉形态,覆盖面(宽窄往返保留同一篇与进度、断点两侧首启、返回栈、无限滚动、暗色)已全部由真实后端 E2E 接住,
不再维护两套会各自漂移的选择器。
