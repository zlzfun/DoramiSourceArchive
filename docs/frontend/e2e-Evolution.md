# 阅读器 E2E Evolution

## 2026-09-15 · #90 的移动读者切片

- 发生：用户要求为移动端适配补 E2E，并关联已有测试 Issue；选择轻量方案，先复用 Python Playwright、Chromium，不引入第二套 Node 测试框架或 Docker。
- 分析：原 `check_mobile_navigation.py` 拦截全部 API，能做快速前端回归，但不能证明真实认证、字段契约和读态落库。#90 的管理端、个人早报和 CI 是更大范围，本次不将整个 Issue 视为完成。
- 改变：新增自建服务／临时 SQLite 的真实阅读链路，提供 `npm run test:e2e`，保留原快速脚本。启动沿用实际后端入口、前端使用本次构建的 preview；失败留 trace 与截图，成功也留关键渲染产物。

## 实跑与实际产物发现

1. **手机 → 桌面覆盖阅读快照**：旧移动 DOM 会先按新宽度重排并派发 scroll，媒体查询通知稍后才换视图。实测原进度约 0.275 被旧 DOM 的约 0.366 覆盖，阅读章节 07 跳到 09。修复为仅在 DOM 版式仍与当前媒体查询一致时记录滚动快照；断言同时检查进度和附近章节，不只比较数值。
2. **反馈挡导航**：收藏后马上返回列表，Toast 挡住底栏中间按钮。移动提示上移至底栏上方，桌面位置不变；检查实际命中目标，而不仅是 visible。
3. **长名称挤压筛选**：直接查看长来源名截图发现「全部 / 未读」折成两行。移动顶栏让来源名省略、筛选段不收缩，并补单行断言。
4. **避免测试自身假设失真**：同宽度返回检查原像素偏移，跨宽度后的行高变化则检查原条目仍在视口内。断网用例先关闭旧成功提示，等待实际请求失败和新的错误反馈；预期网络失败按请求身份记录，避免异步事件晚到被误算为意外错误。

当前只进行了自动化验证与实际产物自查；PR #91 的独立 Codex 检视仍待完成，本地 `codex --help` 两次启动被 SIGKILL（137），未得到检视结论。用户此前确认 5186 基础布局正确，不等于本轮全部流程已获真机放行。

## 2026-09-30 · #90 桌面读者与管理台切片

- 发生：#90 余下两块——桌面读者主链路（含个人早报）与管理台采集页的关键状态。约束：继续用 Python Playwright、同一套沙箱，不 mock 业务 API，不用固定睡眠，只跑无头。
- 改变：运行器 `check_mobile_reader_e2e.py` 改名 `check_frontend_e2e.py`（已不止移动端），新增 `desktop`、`admin` 两个 `--flows`；沙箱运行角色由 `reader` 改为 `all`（管理员要看到采集页），夹具补分析数据、桌面读者和管理员。`preview_pwa.py` 共用夹具但会经公网隧道暴露，保持 `reader` 角色、不建管理员，并加测试守住。
- 删除：节点看板「暂无某形态节点」空态的断言——真实注册表四种形态都有内置节点（播客 37 个来自目录），沙箱里到达不了，不为它造假数据。

### 实跑发现

1. **主干基线本就不稳**：移动流程点「文章」后立即 `reload`，取消了在途的 `/api/articles` 与 `unread-counts`，审计判失败，约一半概率。改为等两者 `requestfinished` 再刷新（检视指出只等 `response` 仍会被响应体下载打断）。
2. **产品缺陷：首屏并发懒建未读水位 500**：新读者首屏的 `unread-counts` 与带未读的 `/api/articles` 同时补同一批 `reader_read_cursors` 行，后到者撞主键返回 500。约 1/3 概率在桌面流程复现。`ensure_cursors` 改为 `ON CONFLICT DO NOTHING` 后重读，补单测（去掉修复即失败）。
3. **`role=all` 会让沙箱外联**：后端导入时安装播客目录并建一个启用的 Tessl 观察期采集任务（cron `20 */6`），`all` 角色会注册它。夹具先装目录并把任务存为停用；启动引导尊重已有任务启停。管理流程断言没有待触发任务，故意留启用时断言失败。
4. **浏览器侧外联**：发现页 LogoMark 走 Google favicon；此前 focus 流程在自建上下文里就会真实发出这些请求而不被审计。改为浏览器启动时把非回环流量指向无人监听的本地代理（覆盖所有上下文，含 IP 字面量），审计要求每个 favicon 请求都失败并回退字母头像。先试过 `--host-resolver-rules`，检视指出挡不住 IP 字面量，弃用。
5. **测试写法的坑**：发现页会带入当前容器形态（从动态进入即筛动态），筛选框角色是 searchbox；Playwright `route` 不能直接传 `list.append`，且应先放行暂存请求再 `unroute`。
6. **环境**：worktree 需自行 `uv sync` 与 `npm ci`；Playwright 升级后要重装 Chromium。

### 交叉检视

实现方 Cursor Agent；检视方 Codex CLI（`codex exec -s read-only`，默认模型）。首轮 1 阻塞 2 建议：外联防护只覆盖部分上下文（接受）、运行史载入态未证明请求确实发出（接受，加 `expect_request`）、reload 只等响应头（接受，改 `requestfinished`）。复检一：两条建议已解决；外联仍未解决——解析规则挡不住 IP 字面量、favicon 在发出时即记为已拦（接受，改死代理 + 以失败事件计数）。复检二：已解决，无新阻塞。`reader_state` 修复首轮即无意见。

故意破坏：把低于门槛的分析分改到 6.0，桌面流程因早报篇目不符失败；把采集任务留为启用，管理流程因出现「距下次」失败。修复并发缺陷后，全部五个流程的无头全量运行共 8 次通过（最终版本 2 次）；另有一次失败是解析规则误伤 `127.0.0.1` 的配置错误，已随改用代理消失。
