# 兴趣即透镜波(issue #27 第一波,v3.52.0)

> 状态:**已实现**(2026-09-09,五稿)。本文是方案与决策记录;样页 `docs/design/dorami-interest-axis-quiet.html`
> (五稿,现行)与 `docs/design/dorami-interest-lens-quiet.html`(四稿,含三次被否方案的注记)。
> 后续波次的候选见文末「明确不做 / 后续」。

## 题

v3.47(#23)把「我的兴趣」做成了整幅页面,但消费方仍只有个人早报选篇一处——一整页只承载一份
「关注 / 屏蔽」开关清单,页面分量与它能产生的效果不成比例。issue #27 立项把兴趣接到更多消费方。

## 设计过程与拍板(2026-09-09,同日完成)

| 稿 | 方案 | 结论 |
|---|---|---|
| 一稿 | 兴趣页做成「关注动态(篇数 + 热度折线)+ 主题流」的阅读面 | **否**。①篇数不是明智方向——数字催人比较、又依赖分析覆盖率并不可靠(与撤源栏未读数字、社交流不展示互动数同一取向);②兴趣页混读各形态,重犯「今日」混合流被取缔的错(标签几乎只落在文章上,动态零星、社交为零) |
| 二稿 | 兴趣是透镜不是地方:源栏加「兴趣」组列标签,发现页第三段承接编辑面 | 部分采纳。标签混进来源清单让「我的订阅」栏头名不副实;拆「兴趣 / 我的订阅」两节只是转移别扭 |
| 三稿 | 源栏「只看关注」与「全部 / 只看收藏」并列 + 作用域推翻(阅读器 = 订阅 ∪ 关注) | 宏观讨论后**不做隐式并集**:并集让「文章为什么出现」有两个隐式解释;兴趣先做透镜,渠道等数据 |
| 四稿 | **左栏 = 过滤面板,三谓词多选联合**(用户 idea) | 实现后目检推翻(同日):选中左栏某个源之后「订阅」开关空转——订阅集 ∩ 单源 = 单源;停在未订源上它又被临时关掉、再点变成「回聚合」,同一枚开关两种状态两种动作。根因:「订阅」与来源列表约束的是同一个变量,不是正交的第四维 |
| 五稿 | **左栏 = 一根轴,栏头二选一「订阅 \| 兴趣」决定按什么切分;收藏挪到列头**(用户 idea) | **采纳**,见下 |

宏观拍板(是否值得引入兴趣维度):作为透镜是好设计——可完全忽略,零认知税;作为进货渠道有保留——
用户对「为什么这篇出现」需要两个解释,系统每个既有概念都要多答一道「兴趣管不管这里」的永久税。
关注对象以**实体**为主更自然(「跟 DeepSeek」比「关注 AI 智能体」);上线后看数据(设兴趣的用户占比 /
兴趣开关使用 / 早报兴趣命中率)再决定要不要更多。

口径:维度 / 开关 / 列头 / 发现页段名统一叫**「兴趣」**;兴趣页里对单个标签的动作仍叫关注 / 屏蔽。

## 模型(五稿)

- **左栏是一根轴**。栏头 = 容器名(文章 / 播客 / 动态 / 社交媒体)+ 二段互斥切换 **订阅 | 兴趣**,
  决定其下列表列什么:订阅 → 已订阅源(按角色分组,今天的源栏);兴趣 → 关注的标签(按目录面 主题 / 行业 /
  实体 分组,与源行同一套行语法)。点栏头段 = 该轴全集,点一行 = 收窄到一项(`activeSourceId` /
  `activeTagId`,互斥,切轴即清)。两侧结构对称,「选了源之后订阅还有没有意义」在结构上消失。
  整栏只有一种语义——单选:栏头段、源行、标签行的选中态统一浮白 + 弱高程(四稿的 wash 底 + 勾整体退役)。
- **兴趣轴的范围 = 全站可见源**(隐藏源与私有自定源照旧排除):只在订阅内就退化成订阅的子集,失去
  「看见订阅之外」这一透镜的核心价值。「订阅内命中兴趣」不再是可选过滤,靠订阅轴里的命中胶囊呈现。
- **「全站」浏览态取消**(四稿三者全关):它本是副产品,发现页与未订源预览锚点行已覆盖浏览需求。
- **收藏挪到列头**:与 全部 / 未读 seg 并排的一枚星。未读与收藏都是「逐篇的状态」,与「按什么切分」正交,
  同类归同类;可与 订阅 / 单源 / 兴趣 / 单标签 任一组合。这反转了 v3.10「收藏进源栏当一级入口」的拍板——
  当时源栏没有轴语义,现在有了。社交容器没有标签(推文不打标),栏头不出轴切换,收藏星在社交头。
- **轴 + 收藏按用户按容器记住**(localStorage `dorami-reader-scope:{user}:{mode}`,四稿三布尔自动迁移);
  下钻项不记(切回该轴回全集,与点容器钮回聚合一致)。点源 / 按 id 打开一篇(深链、早报卡)= **临时**进入
  来源轴且放开收藏,不落盘,回聚合(`goContainerAll` / `goView`)即读回记住的轴。
- **列头回显**:标题 = 订阅 / 源名 / 兴趣 / 标签名;副文案 = 兴趣轴全集的「全站」+ 收藏星开着时的「收藏」。
- **屏蔽不是开关,是全局透镜**:任何轴取值都生效,条目折成「已屏蔽 · 机器人技术、具身智能 · 展开」一行
  (写屏蔽了什么,不写几篇),点开就地摊开(条目降调)。早报的硬排除口径不变。屏蔽标签不进兴趣轴列表(拍板 3 另议)。
- **命中胶囊也是透镜**:顶行源名后一枚 accent wash 小胶囊,只写命中的那个兴趣标签;订阅全集 / 单源 /
  兴趣全集里照挂,**单标签视图不挂**(每行都因同一个标签而在,再挂是重复信息——与「单源里订阅空转」同一类冗余;
  分析主签与当前标签同名时同样让位)。未打标条目零变化——「未知」不是「不命中」。
- **订阅外文章直接出现**(兴趣轴):源名后 faint「未订阅」,悬停翻「+ 订阅」;阅读窗眉头挂「+ 订阅 源名」胶囊。
- **没设兴趣时**切到兴趣轴:左栏一句引导直落发现页兴趣段,列表空态同一句(不锁栏、不弹层;引导形态拍板 3 另议)。
- **兴趣的编辑面并入发现页第三段**「源 · 合集 · 兴趣」:挑源、挑合集、挑标签都是「挑」,同一个目录页;
  读东西全在容器;早报是唯一的「我的」页。视图轨撤掉「兴趣」钮。首登引导 = 发现页兴趣段顶部一条横幅
  (不锁页),完成即落早报;发现钮挂点直到完成或跳过。兴趣页卡片脚部的篇数撤除。
- **未读**仍是 seg(读态不是范围);兴趣轴的订阅外源没有水位,按逐篇读态判定(没读过即未读)。
- **交付面不动**:早报冻结订阅源 + 兴趣标签;feed / MCP 仍是订阅域。

## 检视返修(codex,PR #48 第一轮,对四稿实现的意见在五稿里落地)

- **P1 · 未读标注与全站过滤不同尺**:`unread_only` 在全站范围按逐篇读态判定,而页级 `unread` 标注
  (`unread_ids_among`)把无水位源一律当已读,「只看未读」列表会把订阅外条目画成已读、逐条标读按钮反向。
  修法 = `unread_ids_among(include_uncursored)` 与 `unread_filter_condition` 同一把尺子,列表接口按
  `subscribed_scope != only` 传入;测试补页级标注断言。
- **P2 · 全部标读越出订阅范围**:该动作推进的是源水位,兴趣轴(全站)里订阅外源没有水位,标了会在重载后复活。
  修法 = 兴趣轴全集不出「全部标读」钮(单源预览仍出,按源推水位);hook 内兜底早返。
- **P2 · 引导完成回调闭包陈旧**:`onSaved` 里的 `discover` 是渲染时快照,PUT 在途读者走开后仍会开早报盖住当前页。
  修法 = 桌面 / 移动各经 `discoverRef` 读最新值。
- **P2 · uv.lock 根包版本未随 bump**:沿上一波惯例只提交根包 `version` 一行(开发机镜像源改写不入库)。

第二轮(对五稿):**P2 · 兴趣轴未随能力位**——`personal_digest_enabled` 关闭时兴趣端点 403、发现页无兴趣编辑面,
轴切换却照出,选了得到空列表。修法 = hook 加 `interestAxisEnabled`(桌面 / 移动传 `personalDigestEnabled`):
轴切换不出、记住的兴趣轴就地回落订阅轴(不改写存储,重开即恢复)、不打兴趣端点。**P2 · 分析轮询丢兴趣标注**——
`withFreshAnalysis` 只投影分析键,pending 篇拿到标签后胶囊 / 折叠要等整列重载;`interest_hits` / `interest_muted`
加入投影键。两轮上限到此,合入。

## 返修 v3.52.2:兴趣轴的「全部标读」与未读时效下限(2026-09-10)

用户目检:兴趣轴中栏没有「全部标为已读」钮,与订阅轴不对称。之前藏掉的理由是该动作推源水位、兴趣轴的订阅外源
没有水位;正解是把动作做出来而不是藏掉。用户的心智模型是对的——读态就是每篇一份、两根轴复用:

- **读态两层的事实**:逐篇行(`reader_article_read_states`,打开 / 手动标未读写它)+ 源水位(`reader_read_cursors`,
  「全部标读」推它,压两千行为一行并回收水位以下的逐篇行)。兴趣不满足水位的前提(一篇命中多个标签、与订阅是同一批
  文章的两个视角),按标签设水位会造成跨轴不一致,**不做兴趣水位**。
- **兴趣轴「全部标读」= 按范围逐篇写行**:`POST /api/reader/mark-scope-read?shape=&interest_tag_id=`,范围 = 全站可见源
  ∩ 兴趣命中(单标签只认那一枚)∩ 容器 ∩ 未读(与列表同尺),一条 `INSERT … ON CONFLICT` 写整批,单次上限
  `MARK_SCOPE_READ_MAX = 2000` 取最新;不推水位(订阅源里未命中兴趣的文章不受影响)。响应与 `/mark-all-read` 同形。
  前端两根轴同一枚钮,hook 内按轴分流。
- **代价实测**(dev 库):884 篇已分析文章,4 个标签命中 24 篇(2.7%);逐篇行 93 字节。生产按每天 100 篇入库、命中
  3–10%,一个读者每天 3–10 篇;一次「全部标读」只写当前未读的命中篇,量级是几十到几百行。
- **存量增长的天花板 = 未读时效下限** `UNCURSORED_UNREAD_MAX_AGE_DAYS = 30`:无水位源的文章没有逐篇行且入库超过
  30 天一律视为已读(列表过滤与页级标注同尺;显式未读行压过它)。作用有二:新关注一个标签不再把全站历史命中全部灌成
  未读;逐篇已读行只在滚动窗内有意义,留存清理(`_read_state_cleanup`)删掉无水位源窗外的已读行,表大小从线性变成
  每人几百行的常量。订阅源的对应物是订阅时播种的水位。
- 测试:`test_reader_interests` +2(时效下限过滤 / 标注 / 显式未读压过;按范围逐篇标读含单标签与不推水位)、
  `test_data_lifecycle` +1(读态清理只删无水位源窗外已读行)。
- 检视(GitHub codex 两次平台错误,改本机 `codex exec` gpt-5.6-sol 独立检视,三条 P2 全修):①固定 LIMIT 2000
  会把「全部标读」静默变成「最新 2000 篇」→ 服务端逐批写到写完(批次封顶 10,超出 `has_more=true` 如实回报,
  前端不谎称「已全部」);②留存清理用按日历日的 `_cutoff(30)`、未读判定用精确 `now-30d`,差半天会删掉尚未满
  30×24 小时的已读行使文章复活为未读 → 清理直接复用 `uncursored_unread_cutoff()`,补临界测试;③admin 会话在
  列表里能看到隐藏源命中、新端点却无条件排除 → 可见性按会话角色与 `GET /api/articles` 同尺,补 admin 用例。

## 明确不做 / 后续

- 列头下的**标签 chip 行**(逐标签收窄):四稿拍板暂缓,五稿由兴趣轴的下钻行天然承接,不再需要。
- **兴趣轴列表列什么**(仅关注 / 是否露屏蔽)与**无兴趣时的引导形态**:2026-09-09 拍板另开讨论;现行按
  「仅列关注的标签,屏蔽只作折叠行透镜;空态一句引导直落发现页兴趣段」实现,均为占位。
- 发现页标签卡脚部**「主要来源」**(不带数字的桥):作用域可关掉订阅之后它是可选项,留待拍板。
- 兴趣渠道**准入门槛**(是否再加新闻价值分下限)、**早报兴趣半取全站**(→ v3.53.0 已做,`docs/personal-brief-interest-union.md`)、**feed / MCP 屏蔽**(改交付契约)、
  **问答先验**、**隐式建议关注**(从阅读 / 收藏反推,只建议不落库):均为后续候选,先看数据。
- 收藏不再按收藏时间另排(列头星只是谓词,列表统一按到货序);原 `GET /api/reader/favorites` 端点保留。
