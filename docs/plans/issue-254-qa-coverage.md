# issue #254：问答覆盖与 ASR 歧义回归

> 状态:进行中（2026-11-03）。实现基线 `cdf168b`，用户已授权修复。#245 的 PR #258 已按用户验收 squash 合入；本波不改变现网模型设置。

## 问题与范围

#248 已让原稿进入问答，但历史六题 high/16384 对照仍遗漏三个评分点：开放模型后训练/可信部署变现、新版编码比较不足、权限代码触发安全降档的例子。那是固定小样本观察，不是总体准确率。当前规则已有 ASR、不确定性和反事实约束，本波补多子问题覆盖与关键歧义的短引文依据。

第一阶段：同一次最终回答中按子问题对应证据并检查遗漏；缺证据逐项说明。简单问题仍简短，不展示内部检查表或虚构覆盖率。原稿、检索预算、模型配置与调用次数不因这项修复改变。

## 验证设计

- 自动化验证真实问答消息构造、配置和调用次数、上下文/历史/引用边界；这些不能证明模型语义正确。
- 合成语义案例覆盖三处历史机制、ASR 专名/数字/说话者/矛盾、资料缺失、多轮追问与简单问候；评分标准先固定。合成例子不冒充真实新节目或盲测。
- 评测默认离线准备，冻结资料、日期、提示词和评分表；真实调用显式启用，按实际 HTTP 尝试限制次数，失败与兼容降级重发也保留。请求模型、思考配置、供应商返回模型及 token/延迟分别记录；供应商自报不证明底层快照。
- 先固定模型配置对照旧/新提示词，再固定提示词比较模型；全部响应保留，不筛选最佳结果。人工语义评分与引用编号检查分开，不用词语命中代替语义正确。
- 必须区分召回缺失、已召回但未送入上下文、已送入但漏答。固定上下文实验只测最后一项，不声称覆盖订阅检索端到端。

## 真实评测与费用

复用已有原稿，不隐式新增 ASR/TTS。真实付费批次先准备具体输入、调用数与估算，再按 [沙箱验收](../dev/sandbox-acceptance.md) 的既有约定由用户确认；估算控制不是供应商实付硬上限。未经真实对照验证，只记候选修复，不关闭 #254 或宣称已消除语义遗漏。

### 复现命令

仓库合成集可完全离线准备：

```bash
.venv/bin/python scripts/eval_qa_coverage.py prepare --today 2026-11-03 --runs 2 --out /tmp/qa-batch.json
```

`--baseline-prompt` 可指定冻结的旧 system 文本，`--cases` 指定已含完整上下文和人工评分标准的 JSON 列表。评分表只保存在批次清单中，不送入作答提示词。`run --help` 列出必填模型、思考、输出上限、实际 HTTP 尝试和估算金额限制；密钥只从指定环境变量读取，不写配置回执。每次运行新建目录，拒绝覆盖已存在的账本，无自动恢复重提。

每次请求前先写预留，成功/失败均保留供应商响应；兼容降级同样扣请求次数；传输错误不重试，不退回不明请求的估算预留。输入按请求字节数加余量估算，输出按上限预留，包括思考 token；不能视为供应商实付保证。报告的 `quality_status=not_evaluated` 要由逐题人工评分另行补齐；引用编号合法只能证明编号可解析，不能证明语义有依据。

### 语义验收表

逐个「题目 × 提示词 × 重复轮次」保留全部回答，按冻结评分点分别标记正确、遗漏、错误、恰当不确定或无法评定，附对应原句和回答位置。独立记录：关键事实错误、关键点遗漏、ASR 不确定性、说话者归属、引用支持、原稿不变性、延迟与 token。既有三处遗漏每次采样都应覆盖，其他题不能以新增事实错误换覆盖分；合成案例单列。仅历史题通过仍不能关闭 #254：未调优新节目的重复采样和是否调整模型配置的结论必须补齐。

### 历史问题仍未稳定解决

- 后训练环境和可信企业部署变现：v2 两次均覆盖。
- 新版编码内部比较不足：v2 两次均遗漏；不能由「不做统一排名」替代这条具体证据。
- 权限/访问控制代码触发安全降档：v2 两次均覆盖。
- 机器人题仍有一次写成「人形机器人（含四足、轮式等形态）」，原稿含混插话不支持确定包含关系；两次都遗漏科研采购与供应商支付能力的比较。
- 开放模型反事实仍有一次从能力/成本优势推导反供应商锁定价值下降；锁定与控制权是题设没有改变的独立条件。
- 两次安全隔离回答都提到共享高权限和按实例拆分，但没有清楚区分后端授权与看板视图过滤。

历史六题/两次中，4/12 个回答完整满足冻结检查项；其中既有细节遗漏也有事实/推断错误，不能把所有未满足项视为同等严重，不能外推总体准确率。八组合成案例为 7/8：简单问候仍主动追加「文章暂时没有可用资料」；追问、缺资料、角色/歧义及简化机制题通过，不能据此替代真实长稿验收。v2 与 v1 的有限采样没有证明可靠的整体改善，不继续把堆叠规则作为已验证修复。

### 新节目固定提示词模型对照

两期发布方原稿各问一题、每个配置重复两次，完整上下文、日期、评分表和输出上限固定。仅模型/思考设置不同；配置顺序未随机化，供应商返回名称只是自报身份。以下「完整检查」由实现方人工判断，包含细节校准，**不是模型总体正确率**。

| 请求配置 | 完整检查 | 请求中位耗时 | 本组高峰缓存口径估算 |
|---|---:|---:|---:|
| Flash disabled | 3/4 | 5.64 秒 | ¥0.070485 |
| Flash high | 3/4 | 25.46 秒 | ¥0.171800 |
| Pro high | 3/4 | 75.63 秒 | ¥0.721322 |

三组主要问题都回应了，未通过项不同：Flash disabled 有一次比例计算的前提和分母说明含混；Flash high 有一次仅凭密钥外置就扩展成单次泄漏影响范围缩小；Pro high 有一次公式正确，却把「每 PR 对应的事故数」这个比率本身称作分母（应为 PR 数）。另有将「更愿意逃逸」写成「更容易逃逸」等非核心措辞偏差，保留为观察项，不称全文无误。

当前证据不足以证明开启 high 或换 Pro 能稳定解决本问题；Pro 没有测历史 ASR 失败题，更不能用新节目结果替它背书。暂不改变默认模型或思考配置。固定全文实验已确认至少部分错误属于「证据已进入上下文但回答遗漏/误读」，不是这些样本的检索召回缺失；实际订阅检索端到端仍需单独验证。

## 下一步修复策略（待对齐，未实施）

先保留已冻结的失败集和评测工具，不再依据两次偶然答对直接改默认模型。建议把复杂问答改成可核对的内部步骤：先列出用户子问题，并为每项取出原文短句及适用条件；再按这些子问题输出答案，缺证据逐项说明。程序核对原句确实存在于本轮资料、引用编号对应，并检查每个已列子问题都交付了回答或缺口说明；这些确定性检查仍不能证明推断正确，语义验收继续用同一失败集和新节目重复对照。

优先在离线评测路径做结构化输出候选，界面只显示自然答案，不暴露内部核对表。比较单次结构化作答与分两步调用的覆盖、误读、延迟、token 成本后再决定是否接入运行时；不得先承诺额外一轮模型调用一定能修好。简单问候和对话追问单列回归，避免复杂作答规则扩散到闲聊。任何新增付费批次仍先给具体输入、最多请求数及累计费用估算再按既有约定确认。
