# 公共日报跨天去重与逐条复核（#313）

> 状态:进行中。第一步建立旧算法可回放的生产基线。第二步通过盲测后调整删除规则。
> 方案与验收由 Codex 和 Claude Code（Claude Fable 5.2）于 2026-11-20 商定。[讨论结论](https://github.com/zlzfun/DoramiSourceArchive/issues/313#issuecomment-7027869079)

## 问题和目标

11 月 20 日定时运行有 70 篇候选、24 篇过线、18 条预选，跨天判断后正文 11 条、附录 7 条。旧日志只有剔除总数。对照前三期，IPO 发行定价与首日收盘、千问的渠道消息与阿里财报表态可能被混同。被删代表稿与配对前报无法逐条从当时的记录证实。这期只能提供开发案例。

目标是让新闻的阶段推进、数字更新和独立事件进入下一轮选篇，同时消除前报充分覆盖的重复。所有指标在**跨天查重出口**计量，后续版面裁剪、附录补位及每日总条数不能代替逐条判断。

## 第一步：取得可重放的真实批次

成功发布日报时，生成节点在同一 SQLite 事务往 `daily_brief_dedup_runs` 追加一行，与日报、候选消费、游标一起提交。增量重跑有各自的批次 ID。只含推荐内容的发布也记录空候选。空运行、预览和失败发布不写行。审计落盘失败整批回滚，记录错误日志，定时任务原有失败记录/手动任务错误可见，下一次可以重试。

快照保存预选时的完整编辑稿（含被删稿的 ID、标题、全部要点和点评）、当次前报正文条目的完整要点及顺序、实际送出的两条消息、系统提示 SHA-256、算法标识、辅助模型及生成参数、模型原始返回、逐条最终去留和接前报说明。输入文本完整保存。原始返回超过 65,536 个字符时留前段、截断标志与整串哈希；异常只存类别。无历史、无候选、调用失败和全删保护分别标记。旧模型没有给出的命中对象和理由保持未知。

管理员读 `GET /api/daily-brief/dedup-runs/YYYY-MM-DD`。默认返回最近一次，`limit` 最大 10，`before_id` 向前翻页，旧期返回空数组。下一步的编辑只能看盲化后的候选和历史事实，不能看这条管理接口中的模型动作。

## 第二步：用同一批次比较两种判断

- 拟用一次辅助模型调用对照前三期正文，向模型提供标题和多条事实。使用每批确定的前报编号，输出今日每条的 keep / followup / drop。删除须引用同一事件的前报，在今日和前报各给出可以定位的实质事实。逐侧归一化全半角、空白和标点后校验。仅词面重合不够。跟进也需要有效引用。
- 有新阶段、决定、数据或证据时保留。对缺行、引用不存在、相互矛盾或证据不足的建议保留；官方一手保护和全删保护继续生效。附录只有标题，不作为已充分报道的证据。新数字的机械否决先在开发集比较，包括单位换算、四舍五入、版本号与时间，之后再决定是否启用。
- 生产默认规则切换在正式留出通过之后。原基线用 v3.69.0 相同模型入口与提示。11 月 20 日的七组还原、单元测试的模拟返回均不作为真实模型成绩。

## 取样、盲标与冻结

1. 按生成日整天收集成功发布的全部预选批次；保留批内次序、模型参数、前三期上下文及所有采纳/未采纳条目。快照不齐或引用晚于报告日的历史补跑单列。先按日期和事件族分开发池与留出池，同一事件族或同一稿件不能横跨两池；每个样本都有稳定的批次号和文章 ID。重跑重现的同一候选单独列出。
2. 独立编辑在看不到旧/新输出时只用当时材料标注「应保留 / 真重复」、可接受的前报引用集合及决定性事实。争议样本先记录原因，仲裁前不入分母。开发集 40 条；留出集 110 条。按日期、批次和原候选顺序在每层取最早符合者，若某层不足继续收完整日期。保存自然分布与排除原因，人工构造数据单列。不要把分层样本的误删比例当作线上总体比例。
3. 65 条应保留分别为数字更新 15、阶段推进 15、同数字不同事件 10、同主体不同事件 10、完全无关 15。45 条真重复分别为纯复述 15、换源改写 15、多候选中只有一条真重复 10、隔两三期才重复 5。重叠类按预先标注的主因归层。两个已知[开发锚点](../../tests/fixtures/daily_brief_dedup_controls.json)另计。存样本、标签、参数、代码与提示词哈希，留出冻结后才调新版提示；实现方只看开发集。看过留出结果后更改规则，下一轮需新留出集。
4. 用生产同款辅助模型与相同参数，旧、新在原始完整批次上各跑三次；保持相同顺序、官方来源和其他保护。保留全部六轮原输出、候选和最终动作，不挑最好一次。开发锚点与不相关陪测项同批，防止单例触发全删保护而虚假过关。核对模型名、参数、实际返回和调用状态，整轮故障单列并重做一对，报告保留失败运行。正式评测前不能宣称语义已达标。

## 通过门槛

| 指标 | 通过条件 |
|---|---|
| 新信息误删 | 新版最差一轮 ≤2/65，且不高于旧版三轮中位数 |
| 配对回退 | 应保留组内，旧版多数保留而新版多数删除 ≤1 条 |
| 真重复消除 | 新版中位数 ≥36/45，且比旧版中位数少不超过 5 条 |
| 引用与定位 | 每轮最终 drop/followup 的引用与盲标一致 ≥90%；每条最终删除的双侧引文均可定位 |
| 误标与拒绝 | 每轮 15 条无关稿被标跟进 ≤2；模型提出删除后因校验驳回 ≤30% |
| 两个开发锚点 | 新版三轮都须保留，两条均不占用误删容差 |

逐条列出翻转、旧留新删和错引，特别复核高分稿。证据定位的自动断言只能证明所引用的文字存在；语义是否同一事实由盲标判定。40+110 是固定样本验收，须同时报告分子、分母及不确定性。

`python3 scripts/score_daily_brief_dedup.py labels.json trials.json` 对冻结结果判门，退出码 0 表示通过。标签为 JSON 数组，每项含 `id, stratum, valid_refs`（分层键见脚本 `QUOTAS`）。三轮数组每项包含 `old` 和 `new` 两组完整行，每行有 `id, action`。新版另有 `ref, proposed_drop, validation_rejected, evidence_verified`；证据标记取双侧定位的真实结果。样本配额、缺行和重复 ID 检查在算分前执行。两个锚点需在每轮同时提供。脚本只负责算分，盲标、样本/提示冻结和模型身份须按上面的协议另行核验。

## 部署顺序与混版本

新增表、管理查询和盲评都局限于生成节点。外网新、内网旧时，内网仍按原来的日报内容同步；内网新、外网旧时，外网没有批次快照，内网不会为同步来的旧报补造审计。现有 `extensions.items`、归档同步导出和神灯输入形状不变。应用回退到旧版可继续使用旧表结构和数据，另行降级迁移会删除本地审计表。

## 协商与检视

Claude Code 首轮代码检视通过。Codex 接受四项建议：在判断时复制完整预选快照以隔离增量归并的原地修改，逐条记录模型提删与官方/全删保护原因，校验两个锚点的输入完整性，并输出每轮核心指标的分子、分母和 Wilson 95% 区间。

Codex 实现。Claude Code（Claude Fable 5.2）建议双侧举证、盲标与可复盘的实际输入。双方同意第一步只收取证基线，审计与发布原子提交，完整输入不截断，有限原始输出明确标记；后续用真实盲测决定切换。已讨论的分歧中，附录缺乏充分事实、数字硬否决可能误伤单位换算，分别采用排除附录和开发集消融。
