> **拍板(2026-10-23,用户)**:主路线取 §3.2 的 B6 配置(FTS5 三通道召回 + 辅助模型,首篇关窗 48h、代表稿描述、只标题、回显校验),不引入 embedding API;已记录于 issue #121 评论。

## 0. 结论(TL;DR)

0. **两条过线路线实测打平**:词面(FTS5 式)召回 + 模型(B6)成对 F1 0.54 / B³ 0.945;向量召回 + 模型(C3b)0.56 / 0.955;二者最大簇都回到金标水平(10 / 9)。人工目检表明最佳方法的「误并」约六成是金标过严,真实精度约 0.8–0.9,召回 0.6–0.7。
1. **规则法只配折叠精确重复**(URL / 同题):最佳成对 F1 0.24;而且 URL 直连必须对 `docs_*` / `github_*` 这类共享页面 URL 的源关闭,否则整条变更日志并成一个事件。
2. **「机械召回 + 模型判定」路线成立,但 R1 方案里两处细节会让它失败**:事件按末篇续期 72 小时 + 用最新成员描述事件 → 热点簇一周滚雪球(最大簇 28–31 篇,精度 0.19–0.26)。改成**按首篇关窗 48 小时 + 代表稿描述 + 禁并后续 / 评测 / 下一版本**后精度翻倍(C3b 成对 P 0.52 / R 0.60 / F1 0.56;人工目检其「误并」约六成其实是金标过严,真实精度约 0.8–0.9)。
3. **召回层两条都够用**:FTS5 式 BM25 三通道(标题 / 摘要 / 译中标题)top-10 并集召回 87–88%、约 20 候选 / 篇;bge-m3 向量 top-10 召回 88%、top-20 93%、候选少三分之一且免翻译。向量召回不需要 sqlite-vec:±72 小时窗内 numpy 点积 < 1 ms,向量存 BLOB 即可;向量须由外部 API 产出(DeepSeek 无 embedding 端点,首选阿里百炼 text-embedding-v4)。
4. **纯向量聚类(AIHOT 式)不可单独用**:F1 0.31–0.33,相似度分布重叠(金标对中位 0.71,窗内负例 p99 0.62),没有单一阈值;**LLM 事件签名不立项**:同事件组内签名全等只有 35%;**公共日报聚类不能当事件层**:F1 0.14。
5. **「不回溯」几乎零代价**:允许事后合并只多 +0.01–0.02 F1 → 稳定事件 ID 可以保证。
6. **产品侧硬约束是供给**:理想归并下每天 48 小时窗内 ≥ 2 个独立发布主体的事件中位 4 件(均值 4.35,16/48 天不足 3 件,周一 2.0 → 周五 7.7);≥ 3 主体日均不到 1 件。热度公式与半衰期对 top-5 排序几乎无影响(与「来源数 + 最新时间」35/39 天 top-5 相同);**多源 publish_date 被抓取回填到 08:00**(aiera 75%、anthropic 77%、openai 46%),热度衰减与「新」标签必须用首见时间。
7. **事件链要做**:34% 的多篇事件被判为先前事件的后续(保守 15–20%),其中四成间隔 > 72 小时,任何关窗都并不回去 → 需要 story 级「后续」链接而不是并簇。
8. **代表稿标题 52.8% 非中文**,事件题须中文优先(92% 事件有中文成员)。

## 3. 各方向可行性

### 3.1 方向 A:规则 + 召回层
- 规则判定上限 F1 0.24;标题相似加「数字串一致」守卫必须保留(去掉后出 40 篇巨簇)。统一译中后再比只 +0.01–0.02。
- 召回层(对 441 金标对):标题 BM25 top-10 0.69–0.76;摘要 0.51;译中标题 0.75–0.79(top-20 0.85);三通道并集 top-10 **0.87–0.88(约 20 候选)**,top-20 0.92(35 候选)。实体通道本语料不可测(实体标签仅 1 篇),词典代理 0.76 且与 BM25 互补(+3.6 点);`legacy_tags` 无用。
- 37% 金标对是一中一外:标题 BM25 在其上只有 0.55,译中标题通道升到 0.68 / 0.82 → 生产已有 `translation_zh_title` 缓存,零增量成本。13% 漏召回是 X 短帖与 HN 元讨论,无文本可检,产品层接受。
- 生产形态:FTS5 一次 MATCH;单篇 ≈ 17 ms;无新依赖。**可行,作为召回层首选或与向量并用。**

### 3.2 方向 B:词面召回 + 辅助模型增量分配(R1 主路线)
- 骨架可用:非法事件引用 0、缺 idx 0;0 失败批;每篇 ≈ 252 token(只标题 130),日均 54 篇 ≈ ¥0.03 / 天量级;召回 0.93,漏并 31 对中 25 对是模型拒并而非召回缺失。
- 失败点:事件按末篇续期 + 最新成员描述 → 热点簇滚雪球(最大簇 28 篇含 18 个金标组),精度 0.26。
- 不回溯零代价:上帝视角纯净合并只 +0.012 F1;模型自己的事后合并 720 对只合 5 对、2 对 3 错。
- 只标题输入在 20 天子窗上反而更好(0.534 vs 0.479,token 0.56×);批大小 10 多花 2.1× token 无增益;候选上限 15 几乎从不触发(平均候选 6.3)。
- **B6(首篇关窗 48h + 代表稿标题 / 摘要描述 + 新文章只标题 + 标题回显校验)**:全 48 天成对 P 0.42 / R 0.73 / F1 0.54(B1 0.41),B³ 0.945,最大簇 28 → 10,token 252 → 183 / 篇,回显失配 0 / 2333;
  20 天干净 A/B 窗:B1 0.479 → B6 0.600(P 0.51 / R 0.73)。代价:关窗把 26 对金标对的旧事件挡在候选外(候选上界 0.907 → 0.855),上帝视角合并上界升到 +0.067,但远小于它消灭的误并(1169 → 442 对)。
- B7(B6 + 摘要):同窗 P 0.43 / R 0.85 / F1 0.57,贵 11%——摘要在修好关窗后仍是「换召回、拖精度」,只有更看重热点覆盖时才选。36h 关窗未测(预算),B1 事后切窗提示可能再 +0.03–0.04 F1 但再丢召回。
- **可行;主路线取 B6 配置,按 §5 的修正实现。**

### 3.3 方向 C:向量召回 / 聚类 / 向量 + 模型确认
- 召回:bge-m3 标题 + 摘要 top-10 0.878、top-20 0.934;标题 ∪ 标题 + 摘要 top-20 0.971;候选比词面三通道少三分之一,免翻译。
- 纯向量判定不可行:金标对相似度中位 0.71、p25 0.63,窗内负例 p99 0.62,40% 金标对落在重叠区;流式 0.31、离线 0.33,质心变体更差。误并全是同题日更、changelog 连发、模板标题、话题链、同厂连发。
- C3b(τ 0.60 取 top-10 事件,事件锚定首篇,提示词禁并后续 / 评测 / 下一版本):**P 0.52 / R 0.60 / F1 0.56**,最大簇 9。主代理人工目检 30 个「误并」:约 18 个其实是同一事件(Frozen v2 芯片中英稿、十万卡集群、OpenAI 辣椒芯片、GeneBench-Pro 两篇官方稿、HN 同文两次入库…)、8 个是同周期边界(SpaceX IPO 三稿、Qwen3.8 预览期、豆包 2.1 vs 2.1 Pro)、4 个真错(同批过度归组);20 个「漏并」:13 个真漏并且集中在**同日两家中文媒体报道同一次发布**(GPT-5.6 aiera vs qbitai、Nano Banana 2 Lite、GPT-Live…)。即:真实精度约 0.8–0.9,召回短板在确认提示词过保守,不在候选层(上界 0.97)。
- C3c(C3b + 正向准则 few-shot + 批内「共同事实」):P 0.40 / R 0.73 / F1 0.51(v3)——目检指出的两类真漏并确实修回(新增命中 70 对:跨语言 20、同日 33),但新增误并 288 对,净负 0.045(v2 口径净负 0.02)。
  教训:① 提示词措辞只能在精度 / 召回之间换,想同时提要靠结构规则;② 「共同事实」要求无效(87 组全给出了主题级事实,0 组被拆),须改成「含具体产品名 / 版本号」;
  ③ 「相差 1–3 天也算」压过了「日更栏目不并」,同源同题的连载 / 广告(新智元「英雄帖」10 篇)要在进模型前用「同源 + 标题全同 + 非同日 → 不并」拦截;④ 跨日并入既有事件是残余误并主体(391 / 553 对),应限定「≤ 1 天或明确指向代表稿那次发布」。
- sqlite-vec:20k × 1024 维 float32 kNN(k=20)19.9 ms、84.5 MB;int8 12.8 ms、21.5 MB,按数据幅值预缩放后 top-20 重合 0.99;bit 量化不可用。但 numpy 内存点积 20k 只要 0.5 ms——事件归并候选限 ±72h,按时间窗取 BLOB + numpy 即可,**不需要引入 sqlite-vec**(pre-v1、维护者 2024-10 后少有表态);全库语义检索才需要它。
- 生产前提:1.6 GB 生产机不能跑 bge-m3,向量须由外部 API 产出。DeepSeek 无 embeddings 端点;阿里百炼 text-embedding-v4(1024 维、100+ 语种、¥0.5 / 百万 token、首百万免费、OpenAI 兼容)为首选,SiliconFlow 托管 bge-m3 免费档可兜底;换模型后 τ、top-k、int8 缩放、跨语言对齐都要重验(本实验的 0.60 / top-10 只对 bge-m3 成立)。符合 RAG 退役方案 §4「轻形态:派生数据、外部推理、可随时全量重建」。
- **可行,且是目前实测最优;代价是一项新的外部 API 依赖与每篇一次 embedding 调用(约 300 token,成本可忽略)。**

### 3.4 方向 D:LLM 事件签名
- 抽取稳定(2590 / 2590 合法,208 token / 篇),但同事件组内 event_key 全等 34.9%(actor 81%、object 61%、action 70%):失配来自粒度(系列 vs 子产品)与视角(release / research / partnership 随报道角度变),不是拼写。D1 0.42、加 LLM 确认 0.51 且已不是零增量。
- 并入受控评分提示词不建议(`tests/test_content_value.py` 钉死 sha256;签名规范 ≈ 1.4k 字会扰动尺子;LLM 未配置的部署缺签名)。**不立项**;若做只作分桶键。

### 3.5 方向 E:产品模拟(理想归并前提)
- 供给:≥2 主体事件 / 天 均值 4.35、中位 4、最小 0;16 / 48 天 < 3 件、27 天 < 5 件;72h 窗 6.77 / 6;周一 2.0 → 周五 7.7。真实归并召回若为金标的 60–70%,再打折。生产源更多,须用生产数据复算。
- 热度:半衰期 12 / 24 / 48h 的 top-5 集合 38 / 39、33 / 39 天相同;热度 vs 纯来源数 35 / 39 → 首版「可见发布主体数 ↓ → 最新首见时间 ↓」即可,衰减可后加。**时间口径必须用首见时间**(publish_date 回填)。
- 发布主体去重必须(按篇数计数时 17% 的 top-10 席位是单主体多发);`x_sama → openai`、`google_deepmind → google` 并入后 4 个事件失去上榜资格,建议并入。
- 事件链:32% 锚点有后续,34% 多篇事件被判为后续(上界),间隔 >72h 占 41%,最长链 13;判定 ≈ 1.2k token / 事件(日均 ≈ 5k token)。
- 日报当事件层:P 0.15 / R 0.14;只覆盖 61% 榜单席位。日报应是事件层的消费方。
- 代表稿:官方 37.8%、标题非中文 52.8%;92% 事件有中文成员。

### 3.6 AIHOT 公开口径对照(网络核实,2026-10-23)
热度 = 「多少账号和机构在讨论同一件事」,24 小时减半、只看 48 小时、同机构多平台合一;「新」= 首报 6 小时内,另有「爆 / 发酵中」;走势只比较固定追踪的一组源,无可比历史不画;story 有 active / settled;API 匿名只读,返回 sourceCount / signalCount / latestAt **不返回热度值**;访谈披露 embedding 聚类 + 官方源永远优先当主条;884 源,15 分钟抓 / 5 分钟刷新。与本调研一致的点:热度值本身不重要(他们也不公开)、机构去重、官方代表。差异:他们的供给靠 884 源,我们 52 源时榜单填不满。

## 5. 对方案(R1)的修正清单(已回写方案 R2)

1. 事件**按首篇时间关窗 48 小时**(不按末篇续期),之后的同题报道另立新事件并经 story 链接;候选事件用**代表稿**描述,不用最新成员。
2. 判定提示词三件套:正向准则(不同来源 / 语言 / 角度报道同一次发布、公告、报告、事故)+ 禁并规则(后续进展、评测、下一版本、同主题不同事)+ 批内并组须给出**含具体产品名 / 版本号**的「共同事实」(主题级事实无效,C3c 实测);输出回显标题前几字做 idx 校验。
   提示词只能在精度 / 召回之间换(C3b ↔ C3c),再往上要靠两条结构规则:**同源 + 标题全同 + 非同日 → 不并**(连载 / 日更广告拦在模型前);**并入既有事件须 ≤ 1 天或明确指向代表稿那次发布**(跨日并入是残余误并主体)。
3. 召回层 = FTS5 三通道(标题 / 摘要 / 译中标题)top-10 并集 ∪ 实体码 ∪(可选)向量 top-10;候选上限 20 已够(实测平均 6–20)。
4. URL 直连排除 `docs_*` / `github_*` 等共享页面 URL 的源;同归一化标题(≥ 8 字、数字串一致)也走机械直连。
5. 向量召回若采用:百炼 text-embedding-v4 产向量,存 `articles` 侧 BLOB 列或独立表,不引入 sqlite-vec;LLM / embedding 未配置时退化为纯 FTS5 召回。
6. 热度首版简化为「可见发布主体数 ↓ → 最新首见时间 ↓」,时间一律 `first_seen_at`;publisher 合并表(sam_altman → openai、google_deepmind → google 等)。
7. 事件对象加 `story_id` / `follows_event_id`(wave 2 用 LLM 判「后续」填),榜单与详情展示「接前报」链。
8. 榜单产品定义改为「今日热点(最多 10 件,不足不填)」;wave 0 的立项门槛改为用生产数据实测 ≥ 2 主体事件 / 天,本机语料中位 4 件只是下界。
9. 事件题中文优先(中文成员标题 → 翻译缓存 → 原题);官方稿做一手链接。
10. 不做:LLM 事件签名、纯向量聚类、日报聚类持久化为事件层、sqlite-vec。
