## 0. 结论

把桌面读者面的动效收成一套语言,三句话:

- **精密做底**——按下、浮层、打开文章、切视图、AI 速读卡、提示、明暗:短、准、可打断;弹簧、对准触发点的缩放、6px 以内的位移;键盘触发的一律不动。
- **连续管空间**——指示器与筛选、来源栏、早报到场、标题滚动停靠、榜单卡进事件页、订阅:东西有来处、有去处。
- **光只给问答**——问答面板的玻璃、由虚到实、极光沿边一圈。别处不发光、不做玻璃。

另加**沉浸阅读**:正文往下读过一屏,导轨、来源栏、列表降到 30%;指针碰到、回滚、按键即回。

取值进 token(曲线三条、时长档、弹簧五档),规则进 `conventions.md` §7。手机壳、管理面、登录与品牌动效观感不动。

### 2.1 第一批:规则与 token

只打地基,**样式表其余部分零改动、观感零变化**(新增的只是自定义属性与 JS 导出,没有任何规则引用它们)。

- `frontend/src/index.css` `:root`:`--motion-ease-drawer`、`--motion-ease-focus`;`--motion-press`(120)、`--motion-hover-in`(100)、`--motion-hover-out`(180)、`--motion-base`(200)、`--motion-drawer`(360);五档弹簧 `--motion-spring-<snappy|glide|move|settle|pop>` 与各自的 `-dur`(落定时长 413 / 446 / 583 / 687 / 704ms)。不支持 `linear()` 的浏览器由 `@supports not` 块把五档退回 `--motion-ease`。
- `frontend/src/utils/spring.js`(新):共用取样。`springSamples` / `springEasing` 是播放条原来的写法(阻尼比 + 周期 + 自定时长),原样搬来;`springCurve` / `spring` / `motionSpring` 是「感知时长 + 回弹」的写法,落定时长由算法算出(偏离终值不超过 0.1% 的最后一刻),与样页 `motion-core.js` 的 `M.spring` 同一算法;`MOTION_SPRINGS` 是五档的唯一参数表。
- `frontend/src/utils/playerSpring.js`:取样函数改为从 `spring.js` 导入并再导出,只留播放条的参数表;既有引用(`PlayerDock.jsx`、`usePlayerCard.js`、`player.test.mjs`)不用改。
- `frontend/test/motionTokens.test.mjs`(新):① CSS 里五档弹簧的 `linear()` 与落定时长逐字等于取样结果、降级块五档齐全、曲线与时长档取值——取 token 时去注释后按花括号走一遍样式表,只认顶层 `:root` 里的声明,同名声明两次即报错;② 取样的性质(临界阻尼不过冲、末点为 1、封顶 64 段);③ 抽取前后播放条的曲线逐点相同(十条缓动与抽取前逐字比对过,守卫里留 morph 与 spread 两条的首尾点)。反向用例写在守卫里:改错取值、挪进别的选择器、注释掉降级块的一档、后面再覆盖一次、降级块不在,五种都报问题。
- `docs/frontend/conventions.md` §7:加「桌面读者面的动效语言」一条(能不能动、材料、空间、入场清单、离场、token、可动属性、可打断、减少动效、验收;样页「合并时定的几处」里的两处例外——导轨问答钮的一次光晕、「依据」展开的行高过渡——登记在材料与可动属性两行);原「工作区只做反馈 + 白名单」改称「管理面与其余工作区」,内容不变;具名例外原文不动(分数里程表的改写随第二批)。

**与样页落地表的三处出入**(第一批定的):

1. **token 名并入现有的 `--motion-*` 命名空间**。样页取值表里的拟名是 `--ease-*` / `--dur-*`;仓里已有 `--motion-fast / medium / slow / ease`,新 token 跟着叫 `--motion-press`、`--motion-ease-drawer`、`--motion-spring-glide`。
2. **`--motion-ease` 的取值不动**(`0.22, 1, 0.36, 1`)。样页用的是 `0.23, 1, 0.32, 1`,两条曲线全程最大偏差 1.1%(逐点算过),肉眼分不出;不动它,既有的 344 处引用(`index.css` 317 + `mobile.css` 27,含手机壳与管理面)零差异。
3. **「桌面读者面写死的时长并档」不在第一批单独做**。普查下来读者面写死值集中在悬停与按下(140 / 130 / 120ms),正是第二批要整体改写的那些声明;第一批先替换一遍等于改两次。各批改到哪类交互,就把那类交互的写死值换成 token,收口时再出一次普查数字(§6)。

三条通用规矩收在 `readerMotion.pointerMotion()`:键盘触发的不动、减少动效只留不超过 200ms 的明度淡入、没有 WAAPI 直接落终态。「怎么触发的」按触发那一刻算:同步路径看 `utils/inputModality` 记的最近一次输入;请求回来才换内容的路径(从早报 / 榜单 / 「下一条」/ 播放条打开文章、收藏)在入口处 `holdIntent()` / `motionIntent()` 记下,带到播放处。样式表里的状态过渡拿不到这个函数,靠 `<html data-input="key | pointer">`(同一个模块维护)判:按下缩放与提示的位移只在最近一次输入不是键盘时生效。

**与样页的出入**(现网与样页底稿的原型不一样的地方,第二批开工时才逐条核到):

1. **现网没有 j / k 换篇快捷键**。它是样页底稿(#279 的可点原型)里的东西,第一轮普查把它当成了现网,「键盘 j / k 换篇也触发入场」一句写错了。现网的键盘触发是「焦点在条目行、导轨钮、主题钮上按回车或空格」,「键盘触发的不动」按这个口径实现并核过。
2. **卡头的分数原来是静态文字**。里程表只在页边(阅读窗容器 ≥ 992px,1440 宽且来源栏展开时不出现)和手机壳的速读卡里。为了和样页一致(样页 1440 宽下看到的是卡头分数在滚),卡头第一个维度也换成滚动结构:改前改后卡头几何一致(分数宽差 0.2px,高与位置不变)。手机壳的速读卡仍是原来的 2.2s 里程表,没有动。
3. **提示没有「撤销」**,样页里的撤销钮是原型自己的;「换提示时旧的缩到 0.94 退后」也没有做——现网换提示是同一个元素换文字,没有新旧两条。
4. **提示的冷热延迟没有做**:现网自绘的提示只有导轨的浮签,其余是浏览器原生 `title`,管不了。
5. **早报条目、发现页来源卡没有按下缩放**:现网它们不是整块可点(可点的是里面的标题与按钮),缩整块会骗人。
6. **只有阅读窗的星标会弹**;列表行里的星、早报条目的星没有加。
7. **提示的限定方式**:提示挂在 App 根上、全站共用,用「页面里有正在显示的桌面读者面」限定(`:root:has(.reader-shell):not(:has(.tab-panel.is-off .reader-shell))`——管理员从阅读器回到管理面时阅读器仍挂着,只是所在面板带 `is-off`),管理面与手机壳仍是原来那组。
8. **减少动效下明暗仍有 180ms 交叉淡化**(纯明度,不超过 200ms 的那一类)。

### 2.3 第三批:指示器与列表

分支 `feat/issue-301-b3-indicators`(叠在第二批之上)。两件事都做成**独立的一层**:挂在 `.reader-shell` 上自己跟,页面组件不用接线(榜单、发现页自己重渲染时照样跟得上),手机壳与管理面不挂。

**滑动指示器**(`utils/glideIndicators.js`)。选中项的底色 / 底线不再各画各的,改由每个宿主里一块 `.reader-ind` 来画;宿主带 `.has-ind` 时各项自己的让出来,这一层没挂上时各项照旧自己着色。

| 宿主 | 选中项 | 滑法 | 外观 |
|---|---|---|---|
| 导轨 `.reader-vrail` | 当前视图(问答钮不算) | 前缘 0.20s 先到、后缘 0.40s 跟上 | 选中底 |
| 列头「全部 / 未读」、来源栏「订阅 / 兴趣」、榜单范围、发现页形态筛选 | `.is-on` | 同上 | 面色 + 细影的拇指 |
| 类型签 `.reader-kind-band` | `.reader-kind-chip.is-on` | 同上 | 选中底 |
| 榜单页签、发现页签 | `.is-on` | 同上 | 2px 底线 |
| 来源栏 `.reader-source-scroll` | 选中的来源 / 标签行 | 前缘 0.34s、后缘 0.42s | 选中底 |
| 列表 `.reader-list-scroll` | 选中的条目行 | 整块 glide 弹簧(落定 446ms),不拉伸 | 选中底 |

靠 `MutationObserver` 盯 class 与子节点变化,变化之后(微任务里、绘制之前)各量一次:选中项换了、上一个还在文档里、且是指针触发,才滑;尺寸变了、列表重拉、键盘、减少动效都直接落位。滚动容器里的指示器按内容坐标摆,跟着内容滚。指示器垫在各项下面:一般宿主用 `z-index: -1` + `isolation`;导轨不能自成层叠上下文(它的浮签要压在右边各栏之上),改为把指示器放在最前、不设层级。

**筛选后留下的行滑到新位置**(`utils/listFlip.js`)。现网的筛选(未读 / 只看收藏 / 内容类型 / 换来源)都要回服务端重拉,列表先整个换成骨架、新列表到了再重画——新旧两份行不是同一批节点,中间还隔着空白。做法是表现层的一座桥:指针点下筛选控件的那一刻(捕获阶段)把看得见的行各记一个位置、各克隆一份,摆成一层替身盖在列表上;重拉期间替身留在原位;新列表挂上时,两边都有的行从旧位置滑到新位置(move 弹簧,落定 583ms),新来的淡入并上移 10px,走了的替身原地淡出,选中块跟着它那一行同拍。超过 700ms 新列表没到,替身淡出、把骨架露出来,回到原来的换法。只在列表停在顶上时做。行靠 `data-flip-id` 认(`ArticleRow` 上加的属性,手机壳也带着但不用)。

**与样页的出入**:

1. **筛选不是本地过滤**。样页原型的筛选是同步的,行可以直接 FLIP;现网要重拉,所以多了替身层与 700ms 的等待上限。数据流没有动。
2. **语言二段(原文 / 译文)没有接指示器**:它的选中态带 AI 色,拇指式的指示器会把那层意思抹掉。

### 2.4 第四批:空间转场

分支 `feat/issue-301-b4-spatial`(叠在第三批之上)。五件事,两件用 View Transitions,其余是 WAAPI 与滚动驱动动画。

| 项 | 做法 | 落在 |
|---|---|---|
| 早报到场(入场清单之一) | 这次载入里早报第一次有内容时播三拍:头条区 → 页边评分晚 90ms → 目录与板块晚 150ms,各上升 16px(settle 弹簧,落定 687ms),导轨一起淡入。之后换日期、从别的视图回来不再播(那是切视图)。登录抵达时等品牌抵达幕与主界面显影走完再播 | `spatialMotion.enterBrief / endArrival`,`PersonalBriefPage` |

**同步入口用自己的触发方式**(检视返修时定的口径,回补到第二批的几个函数):开合浮层、切主题、全部标读、收起来源栏、起共享元素转场这类同步的交互入口,一律用这一下自己的 `motionIntent()` 判,不看别的请求挂起的那一份;挂起的只留给「内容到了」那一刻的编排(阅读窗挂载、工作区淡入、指示器)。

**与样页的出入**:

1. **早报到场不看输入方式**。「键盘触发的不动」管的是某一下交互;到场是载入的结果,登录本来就是回车提交的。减少动效时各拍只淡入(160ms)、不上升。一次性标记是模块级的:同一个页面里登出再登录、管理员在管理面与阅读器之间往返都不重播。
2. **来源栏展开只有「从下拉固定」一条路**(现网收起后没有别的展开入口),所以展开一律是浮层变形;样页里「直接展开」那一半用在了退路上。
3. **事件页返回时那张卡不在视口**:样页是整页交叉淡化;现网按这个意思做成旧页原地淡出、榜单淡入(转场中途才知道卡在不在,旧端已经拍下,没法再改名)。
4. **订阅飞入等请求成功才飞**(样页原型是同步的,点下去就飞);整组订阅、合集订阅不飞。
5. **非早报视图的到场没有做**(样页里「别的视图只有工作区一拍」):入场清单里只有早报到场。

### 2.5 第五批:问答的光

分支 `feat/issue-301-b5-qa`(叠在第四批之上)。现网的问答是右下角的浮窗(`ReaderAiPanel`,只有桌面读者面在用;点面板外任意处即收起),回答不是流式的——一次返回,检索型的提问每 600ms 轮询一次进行到哪一步。光就落在这个浮窗上。

| 项 | 做法 | 落在 |
|---|---|---|
| 面板 | 玻璃:站内镀层那一组 token(`--glass-bg` / `--glass-blur` / `--glass-edge`)。打开由虚到实 260ms(模糊 8px → 0、0.985 → 1,`--motion-ease-focus`),收起虚化 160ms | 样式 |
| 压暗 | 面板开着时工作区退后一步(亮色 7% / 暗色 34%),240ms 入、140ms 出;不压导轨、不拦点击 | `ReaderAiPanel` 的 `.reader-ai-scrim` + 样式 |
| 极光 | 沿面板边走一圈 1150ms,过后留一瞬整圈的余辉;打开时一次,每次提问再一次 | `.reader-ai-aurora`(按序号重挂载来重播)+ 样式 |
| 导轨光晕 | 面板由指针打开时,导轨上的问答钮泛一次光晕(600ms)——光唯一落在面板之外的地方 | `qaMotion.haloQaButton` |
| 提问 | 问句由虚到实 200ms(模糊 4px → 0) | `qaMotion.focusQuestionOnce` |
| 等待 | 正在做的那一步是一行流光(1.15s 一轮,全站唯一的循环动画),出现时淡入;做完的步骤留在上面、不带动画 | 样式 |
| 回答到达 | 各段依次由虚到实(220ms,段间 140ms,至多错开 8 段)→ 来源条淡入 → 引用角标依次亮(间隔 150ms)、对应的来源行跟着亮(同一来源只亮一次) | `qaMotion.revealOnce / revealAnswer` |

**键盘**:开合不动(面板、压暗、打开时的那圈极光、光晕都不演)。提问与回答照常演——提问多半就是回车发出的,等待与逐段出现对应的是回答真实的到达过程,不是哪一下点击的结果(样页口径)。
**减少动效**:没有极光、流光与光晕;问句与回答各段只短淡入(160ms)、不带模糊;面板与压暗由全局兜底压成瞬时。
**只演一次**:回答刚到的那一次才逐段出现(回答对象带 `fresh` 标记 + 一次性登记;Markdown 渲染器按需加载,回答先到、正文晚一拍才挂上时等正文挂上再演);面板收起再打开,旧的几轮问答直接在——原先每一轮自带的淡入上移(`reader-ai-block-in`)在桌面读者面去掉了,否则面板每次打开都叠一层入场。

**一条新规则**(同时回补了第二批的提示,见 §8):**一次性的入场 / 离场动画不在样式里按 `<html data-input>` 判**。元素还在场时人换了输入方式(键盘打开面板后动一下鼠标、点完收藏紧接着按一下键),选择器的命中跟着变、动画名一换,入场就被重播一遍。做法是出现的那一刻把输入方式记在元素自己身上:问答面板与压暗的 `is-still`、提示的 `data-input`。跟随状态的过渡(按下缩放)仍看 `<html data-input>`,那里不存在重播。同理,等待行从「正在做」换成「做完了」时不能还挂着入场动画。

**与样页的出入**:

1. **等待是分步的**。样页是定时 900ms 的一行「正在检索…」;现网检索型提问有四步(理解问题 → 检索 → 挑选 → 作答),做完的步骤留在上面。流光只给正在做的那一行。
2. **逐段对焦封顶 8 段**(样页没有上限)。回答按 Markdown 的块算一段(标题、段落、列表、引用、代码、表格各一段);很长的回答后面的段一起出,不让人等。
3. **玻璃的取值用站内镀层 token**(底 72%、`saturate(1.7) blur(22px)`、内高光),不是样页另写的那组(76% / 66%、`blur(24px) saturate(1.6)`)。
4. **极光是一个元素、不是面板的伪元素**:要靠重挂载重播,且键盘打开时只停掉「打开的那一圈」。
5. **键盘收起**:现网的问答面板没有 Esc 收起,键盘收起是在导轨问答钮或面板的关闭钮上回车。

**验证**:`npm run lint` / `npm test`(423 条;新增 `qaMotion.test.mjs` 五条:逐段与引用的时序、减少动效、只演一次、问句对焦、正文晚挂上时等它挂上再演)/ `npm run build` 过。自查脚本 `b5_checks.py` 21 项(指针打开的面板 / 玻璃 / 极光 / 光晕 / 压暗、问句对焦、流光、键盘发出的提问也演极光、逐段与引用的时长与错峰、演完不留动画、点面板外收起时压暗退掉、收起再打开旧问答不重演、分步等待里做完的行不闪、回车开合不动、键盘打开后动鼠标不重播、减少动效)全过;带标题 / 列表 / 引用 / 代码 / 表格的 13 段长回答另核对过落点与封顶。第二至四批的八份 137 项回归全过(其中第二批补了两项:提示在场时换输入方式不重播)。亮暗截图与回答到达的慢放连拍看过。静止画面对主干逐屏像素对比与上一批相同(文章页只差卡头分数与导轨指示器边缘),手机壳动效指纹 12 屏零差异。
像素对比脚本自己有过一处时序抖动:公告条出现 8 秒后自动收起,正好撞上早报那一屏的截图时刻,两边一个在收起、一个还没,差出几千像素——主干与改后的停留时长实测相同(7.98 秒),与改动无关;脚本改成等公告条走完再截。

## 5. 约束与做法

- **手机壳不动**:桌面与手机壳共用内容类(`.reader-*` `.bp-*` `.rk-*`…)。改了取值的规则后面紧跟 `:where(.m-shell, .m-page, .m-read, .m-sheet) <原选择器> { <原值> } /* m-keep */` 留值(#279 的做法),或把新写法限定在桌面容器下;每批以主干为基线对手机壳做样式指纹对拍。
- **键盘触发的不动**:交互入口要能分清指针与键盘(事件类型或 `utils/inputModality.js`)。
- **可打断**:高频交互一律 CSS 过渡或 WAAPI;View Transitions 只在三处低频转场。
- **减少动效**:JS 编排经 `motionReduced()` 判定;CSS 仍靠文件尾的全局兜底。
- 新增动效不写 OS 媒体查询(硬规则 2)。

## 6. 验收

每批:`npm run lint` / `npm test` / `npm run build`;每个新增动效附连拍图(正常与减少动效各一),连点与中途打断各试一次;手机壳对主干样式零差异;用户本地目检放行。收口时再跑一次 §1 的普查,数字写进本节。

## 7. 部署与混版本

纯前端:不动后端接口、同步流字段、迁移与配置。外网与内网谁先上都一样,没有混版本窗口要处理。
