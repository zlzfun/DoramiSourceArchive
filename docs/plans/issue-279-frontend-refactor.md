## 0. 结论

1. **颜色与 token 不动**。现网全站文字对比度 0 处不达标,颜色只有四档墨色加一个强调色,描边三档。
2. **要改的是两类事**:同一级的东西有好几个尺寸(字号 17 级、图标 8 种尺寸、同级控件圆角七种);早报之后的页面没有接着用早报的写法(页名横坐标 6 个、整幅页面左边挂着上一个容器的来源栏、阅读窗正文从第 749px 才开始)。
3. **分五批,每批一个分支一个 PR**,各自沙箱自查、交叉检视、用户目检。批与批之间不互相挡路:第一批只改样式值与文案,后面每批动一块结构。
4. **只做桌面阅读器**。手机壳(issue #230 另有定稿)、管理面、设置柜与反馈、登录页不在本 issue。

### 2.2 第二批:版框与页头

榜单、发现、社交、事件页去掉来源栏,整幅页面统一版框(1200,两侧 48)与页头(宋体 30 页名 + 右侧工具);页签原语(与分段分工:页签切内容,分段切视图 / 范围);事件页两栏(左代表报道吸住,右时间线);发现页目录行;社交改正文 + 页边。事件标题、代表报道、榜单条目改宋体。

涉及 `RankingsPage` `DiscoverPage` 社交流与外壳的栏位。规范修订:页头三族、页间对齐。

**实际落地(2026-11-13,分支 `feat/issue-279-b2-frame`,叠在第一批之上)**:

- **外壳**:`ReaderTab` 里来源栏的内容提成常量 `sourcesPanel`;整幅页面(`widePage` = 早报 / 榜单 / 发现 / 社交)不渲染来源栏,三个页面的根都占 `grid-column: 2 / -1`。
- **统一版框与页头**:新类 `.reader-page-wrap`(1200,两侧 48)、`.reader-page-head`(高 124)、`.reader-page-title`(宋体 30)、`.reader-page-bar`(页签行,吸顶)、`.reader-tabs` / `.reader-tab`(页签原语)。1440 屏上榜单、发现、社交、事件页的页名都落在 x = 200,与早报一致。
- **榜单**:桌面分支换成页头 + 页签行(页签在左,时间窗分段或列头「内容价值」在右);条目标题宋体 20(榜首 24、名次 44),摘要两行末行渐隐,徽标并排不叠放,悬停给标题加下划线。
- **事件页**:返回行 + 眉题 + 宋体 30 标题(按词平衡折行);正文两栏,左代表报道(滚动时吸住、去卡片底),右时间线;桌面不出「最新进展」卡(与时间线第一条是同一篇),手机底部层照旧。
- **发现**:标记不动(手机壳渲染同一份),桌面靠网格重排——页名与搜索 / 添加在页头,目录页签(源 / 合集 / 兴趣)与形态筛选在页签行,页头滚走后页签行吸顶;来源从带边框的两列卡片改成三列目录行。
- **社交**:`SocialFlow` 新增 `side` 参数(桌面整幅页面形态):页头进滚动区随页面滚走,正文一栏(640)加页边(账号列表,同一份来源行)。手机壳不传 `side`,标记与原来一致。
- **字号护栏**:事件页三处在册例外收口(`.rk-event .rk-dtitle` 宋体 30、`.rk-event .rk-rep-title` 宋体 20;`.rk-dtitle` 基础值 20,手机底部层留 18)。

**与方案 / 样页的出入**:页签文字沿用现网(「源 / 合集 / 兴趣」,样页写的是「来源」);社交页名沿用「社交媒体」,来源名没有去掉「X ·」前缀;发现页的「目录行」每行仍带订阅钮。兴趣页没有动(游客看不到)。

**推翻的旧决定(目检时请确认)**:2026-11-04(#221 目检)「榜单打开时源列表保持在场」——现在榜单、发现、社交都不挂来源栏。发现页原先靠在场的来源栏让订阅结果即时可见,现在靠按钮变成「已订阅」与提示条。

**没验证到的**:合集详情页头(游客点合集会弹登录)、兴趣页签、登录读者的订阅 / 退订反馈、播放条在整幅页面上的位置。

**验证**:`npm run lint`、`npm test`(352 例)通过;以主干为基线手机壳 22 屏样式指纹零差异;桌面对第一批:早报、文章、播客各屏零差异,榜单 / 事件 / 发现 / 社交按上面变化;1920 与 1180 两种窗口宽度目检。

### 2.3 第三批:阅读窗

吸顶栏收动作(查看原文、原文 / 译文、收藏、标为未读、分享);标题区四行变三行;AI 速读卡按句分段、卡头两个维度、依据可点开;正文加页边(容器 ≥ 992 才出);来源栏可收起,栏头的「订阅 | 兴趣」并入栏名行,来源列表首行「全部订阅」;返回与预览。

涉及 `ReaderTab`、AI 速读卡、播客标题区、`useReaderState`。规范修订:阅读窗标题区四行、AI 速读卡、栏头二段(issue #27)。

**实际落地(2026-11-14)**:

- **吸顶栏**:语言二段与「查看原文」从标题区尾行收到 `.reader-pane-bar`,排在收藏 / 标读 / 分享之前;返回带(早报 / 榜单)并入吸顶栏左端,占掉来源名的位置,早报另带「下一条 n / N」。旧的 `.reader-brief-trail` 样式删除。
- **标题区三行**:眉题只写类别(吸顶栏被「返回」占用时才带来源)、标题、署名行;与速读卡之间不画线。播客封面 96 在标题左边,「优质播客」挪到眉题旁,收听入口单独一行。
- **AI 速读卡**(`<AiReadingCard page>`,手机壳不传):一句一段;卡头并排两个维度,点开看依据(记住展开与否);标签住卡脚;「听导读」在卡头右端,去掉说明句(`<ListenEntries quiet>`)。
- **页边**(`ScoreMargin`):阅读窗容器 ≥ 992 时出现,主分 44(里程表入场)+ 依据、另一个维度、标签;此时卡里的分数钮、依据、卡脚收起。正文一栏 664(原 720),阅读窗左右留白 40(原 `clamp(28px, 5vw, 72px)`)——1440 屏来源栏展开时正文行宽由 628 变 664。
- **来源栏**:栏头一行 52(栏名 15 + 小号轴分段 + 收起钮);可收起并记住选择;收起后列表栏头的范围名是下拉,点开是同一份来源列表(同一个 `sourcesPanel` 常量);首行「全部订阅 / 全部兴趣」。
- **预览订阅**:列表栏头下一枚「订阅」小钮,取代整条色带;订阅胶囊在桌面改成 S · 28 / 10px 圆角。
- **日期**:`formatReaderDate`(署名行与悬停提示)、`formatRelativeTime(…, { cn })`(桌面条目行)、发现页「N 天前更新」(`relativeFresh`)。
- 手机壳共用的组件(`AiReadingCard` `ListenEntries` `ArticleRow` `DiscoverPage`)新行为都经参数只在桌面打开;新样式锚在 `.reader-shell` / `.reader-col-read` / `.reader-col-list` / `.reader-sources-inner`。以主干为基线,手机壳 22 屏样式指纹零差异。

**与样页的出入**:

- 页边与卡脚的「同一事件 · N 家来源」链接**没做**:样页的数据来自早报条目的关联报道,文章详情接口不带事件归属;要做得先让后端在文章详情里带上事件。已登记 backlog。
- 语言二段沿用现网用词「原语言 | 译为中文 / 中文」(样页写的是「原文 | 译文」):「原语言」与「查看原文」分家是 v3.45 目检定的,不改。
- 评分的免责句(「AI 新闻价值评估,用于辅助筛选…」)原先在悬停浮层里,现在是维度名的悬停提示,不占版面;播客的「基于整期内容 / 仅基于节目简介」是数据,留在依据下面。
- 早报「下一条」样页没画,现网有,保留在返回钮旁边;原先的「已到本版末尾」不再写(没有下一条就没有那枚钮)。
- 阅读窗空态没动(样页那两句是样页自己加的,已删;现网的图标 + 一句话 + 去发现的链接照旧)。
- 社交流、早报、榜单里七天以外的时间仍是连字符写法(「11-03」):这几处与手机壳共用同一个组件,本批只改了条目行、署名行与发现页。已登记 backlog。

**没验证到的**:语言二段的翻译流程(游客 AI 未开,只看了版式)、听导读的生成中 / 失败状态在卡头的排布、兴趣轴下的「全部兴趣」行与兴趣标签列表(游客点「兴趣」跳登录)、登录读者的订阅钮反馈。

### 2.4 第四批:列表与早报

列表按分值收放(8 分以上两行摘要、6–8 一行、6 以下只留标题),设置里留「一律等高」;条目行四周对称内边距;早报条目两栏、吸顶目录;导轨标签常驻;问答从右下浮钮进导轨。

涉及条目行、`PersonalBriefPage`、导轨、问答面板入口。规范修订:轨面标签揭示(v3.45)、问哆啦美浮钮。

**实际落地(2026-11-16)**:

- **条目行按分值收放**:`rowTierOf`(8 分及以上两行摘要 / 6–8 分一行 / 6 分以下只留一行标题);没有分数的照常两行;搜索、播客行、紧凑行、手机卡片不参与。设置柜「阅读」里加「列表条目一律等高」(只存本机,`useEvenRows` 用模块级订阅表让设置柜与列表同步)。夹具首屏 10 条里:两行 4 条、一行 3 条、只留标题 3 条(行高 137 / 117 / 64)。
- **对称内边距**:列表两侧各 6、行内 10,文字左右缘都在 16;日期组头用负外边距铺满。
- **早报**:板块原本就是「板块名一列 + 条目一列」,这一批把条目改成两栏(标题 24 → 20、摘要 15 两行 → 14 三行、元信息 13 → 12),板块名列 200 → 180;海报之下加吸顶目录(板块名 + 条数,读到哪里点亮哪里,点了跳过去),板块头的条数挪进目录。版框窄于 1040 时退回一栏。
- **导轨标签常驻**:只改读者面视图轨;管理面应用导轨仍是悬停揭示(管理面不在本 issue)。
- **问答进导轨**:视图轨底部工具组最上面一枚「问答」钮(选中态 = 面板开着),右下角的悬浮圆钮删除;面板从「只在文章 / 播客 / 社交」改成任何页面都能开(整幅页面上没有当前这篇,自动落到订阅范围)。面板的形制没动(仍是右下的浮层,可放大)。空态里复述标题的「问问哆啦美」与说明句(「在你订阅的内容里检索相关资料后作答」等)删除——范围看输入框里的占位与下面的范围切换。

**与样页的出入**:样页的问答面板是贴右边的一整条(上下各留 8,宽 400);这一批只挪了入口,面板还是现网的右下浮层。早报条目的收藏星没有挪到元信息行尾的小方钮(现网已有同位置的收藏钮,形制沿用)。

**留下的**:播放条里为悬浮圆钮让位的那段逻辑(`PlayerDock` 的 `fabOffset` 等)现在没有对象了——它和面板抬升、Toast 抬升写在同一个函数里,播放条形制又是「沿用」,这一批没有拆,已登记 backlog。

**没验证到的**:登录读者的早报(游客看的是全体游客共享的一版);问答的提问与回答流程(只看了开合与空态)。

### 2.5 第五批:排印

标点挤压、中西文间隙(`text-autospace`,旧浏览器无变化)是纯前端。标题按词断行要在入库时存一份分词结果,动后端、迁移与 Archive Sync 字段;届时本节补「部署顺序与混版本」(`docs/dev/workflow.md` §0 四问)再动工。样页阶段已验证:jieba 加标签名词典可用,纯前端的 BudouX zh-hans 模型在科技标题上会切错。

**实际落地(2026-11-16):三项都做了,全部是纯前端,没有动后端与同步字段。**

- **中西文间隙**:`.reader-shell { text-autospace: normal; }`,代码、表单控件、里程表数字排除。不支持的浏览器无变化。
- **标点挤压**:`components/DisplayTitle` 把全角标点包进 `.ts-pz` / `.ts-pzh`(收掉空的半个字宽),只用在 30px 以上的三处标题——阅读窗标题、早报头条、事件标题。句末的收尾标点不收。
- **按词断行**:`utils/wordBreak.js`。分词用浏览器自带的 `Intl.Segmenter`(Chromium 与 WebKit 实测对 128 个真实标题的输出逐条相同),再过一遍合并规则——它的词典对科技标题偏碎(128 个标题 2198 个片段里 678 个是单字:「谷 / 歌」「英伟 / 达」「智能 / 体」):连续的单字并成一块(2–4 个)、落单的单字接到前一块后面(前缀与虚词则带着后一段走)、收尾标点跟前一块、起首标点带着后一段。块之间放 `<wbr>`,外层 `word-break: keep-all`;块边界上汉字贴着字母数字时补八分之一字宽(实测 `<wbr>` 会让自动间隙在那里失效)。用在上面三处标题与早报条目标题(桌面)。只合并不改字:块拼回去与原文不等就放弃,原样显示。

**为什么没走「入库时分词存字段」**:原方案要引入后端分词依赖、迁移、同步字段与跨节点的部署顺序。开工前先试了不动后端的路——浏览器分词加合并规则在夹具的真实标题上已经能保住绝大多数人名、公司名与术语(「谷歌」「英伟达」「黄仁勋」「智能体」「马斯克」),剩下的切错(如「准确 | 率直升」)代价只是少数标题多一个不理想的可折点,而现状是汉字之间处处可折。为这点差距引入一条跨节点的数据链路不值;词典若以后不够用,在前端补一张术语表(把订阅的标签名并进合并规则)即可,仍不需要后端。

**没做的**:文章列表的条目行、榜单行没有接按词断行(15px 的两行标题对折行位置不敏感;榜单行组件与手机壳共用且没有桌面标记)。Firefox 没有实测(本机起不来)——它也有 `Intl.Segmenter`(125 起),词典同源;不支持的环境 `titleChunks` 返回 null,标题原样显示。

## 5. 约束与做法
