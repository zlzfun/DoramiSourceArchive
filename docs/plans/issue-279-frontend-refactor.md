## 0. 结论

1. **颜色与 token 不动**。现网全站文字对比度 0 处不达标,颜色只有四档墨色加一个强调色,描边三档。
2. **要改的是两类事**:同一级的东西有好几个尺寸(字号 17 级、图标 8 种尺寸、同级控件圆角七种);早报之后的页面没有接着用早报的写法(页名横坐标 6 个、整幅页面左边挂着上一个容器的来源栏、阅读窗正文从第 749px 才开始)。
3. **分五批,每批一个分支一个 PR**,各自沙箱自查、交叉检视、用户目检。批与批之间不互相挡路:第一批只改样式值与文案,后面每批动一块结构。
4. **只做桌面阅读器**。手机壳(issue #230 另有定稿)、管理面、设置柜与反馈、登录页不在本 issue。

### 2.2 第二批:版框与页头

榜单、发现、社交、事件页去掉来源栏,整幅页面统一版框(1200,两侧 48)与页头(宋体 30 页名 + 右侧工具);页签原语(与分段分工:页签切内容,分段切视图 / 范围);事件页两栏(左代表报道吸住,右时间线);发现页目录行;社交改正文 + 页边。事件标题、代表报道、榜单条目改宋体。

涉及 `RankingsPage` `DiscoverPage` 社交流与外壳的栏位。规范修订:页头三族、页间对齐。

### 2.3 第三批:阅读窗

吸顶栏收动作(查看原文、原文 / 译文、收藏、标为未读、分享);标题区四行变三行;AI 速读卡按句分段、卡头两个维度、依据可点开;正文加页边(容器 ≥ 992 才出);来源栏可收起,栏头的「订阅 | 兴趣」并入栏名行,来源列表首行「全部订阅」;返回与预览。

涉及 `ReaderTab`、AI 速读卡、播客标题区、`useReaderState`。规范修订:阅读窗标题区四行、AI 速读卡、栏头二段(issue #27)。

### 2.4 第四批:列表与早报

列表按分值收放(8 分以上两行摘要、6–8 一行、6 以下只留标题),设置里留「一律等高」;条目行四周对称内边距;早报条目两栏、吸顶目录;导轨标签常驻;问答从右下浮钮进导轨。

涉及条目行、`PersonalBriefPage`、导轨、问答面板入口。规范修订:轨面标签揭示(v3.45)、问哆啦美浮钮。

### 2.5 第五批:排印

标点挤压、中西文间隙(`text-autospace`,旧浏览器无变化)是纯前端。标题按词断行要在入库时存一份分词结果,动后端、迁移与 Archive Sync 字段;届时本节补「部署顺序与混版本」(`docs/dev/workflow.md` §0 四问)再动工。样页阶段已验证:jieba 加标签名词典可用,纯前端的 BudouX zh-hans 模型在科技标题上会切错。

## 5. 约束与做法

- **不碰手机壳**。条目行等组件桌面与手机共用同一个类时,改动写在桌面壳的选择器下,或先确认 `mobile.css` 有自己的覆盖;每批跑 `scripts/check_mobile_reader_e2e.py` 做反向对照。
- **不碰管理面与设置柜**。全局角色类(`.page-title` `.card-title` 等)不改值;读者面的新刻度落在读者面自己的类上。
- **图标线宽**用一条作用在读者面桌面壳上的 CSS(`stroke-width`),不逐个改 JSX;管理面与手机壳不受影响。
- token 与角色类单一事实来源仍是 `frontend/src/index.css`;不手写 `text-[Npx]` / `rounded-[Npx]` / hex;新增动效不写 OS 媒体查询。
- 守卫:`frontend/test/typography.test.mjs` 与 eslint 现有规则照过;第一批给读者面字号加一条守卫(读者面样式里的 `font-size` 只能取刻度上的值),并做反向对照。
