## 问题与范围

The AI Native Dev 的 Buzzsprout JSON 逐字稿以单词为 segment。原解析逐段输出
`speaker: body` 再用换行连接，读者看到每个词一行及反复的说话人标签。
用户报告 Caleb Sima 单集，既有 #113 官方稿也复现。

本次修复 JSON 词级稿的阅读与翻译投影，不重写官方文本或字幕格式，不改变分析与精品导读输入。
VTT、SRT、纯文本及已有句段级 JSON 沿用既有显示。ASR 与中文稿也保持现状。

## 实现边界

- `parse_transcript` 新增显式 `for_reading` 选项，默认关闭。输入校验、原稿 `source_text`、
  原始 `segment_count` 均保留；阅读 API 与逐字稿翻译显式开启段落整理。
- 局部连续至少 4 个短单 token，且过半不以句末标点结尾时识别为词级流；英文 token
  至多 40 字符、含 CJK 至多 4 字符。已有多词句段不合并。先识别词级流，再按说话人分段。
- 同一说话人发言合并；换人、已知/未知说话人切换、停顿超过 2 秒时断段；
  正文达到 300 字符后优先在句末断段，段落含说话人标签至多约 600 字符。
  保留词序和全部标点，不用模型补词或去重。
- `_plain_text` 默认行为保留；全文分析和精品导读继续使用默认解析结果。
  翻译使用与阅读相同的完整段落，避免重复标签撑大输入；原有 120,000 字符上限不放宽。
  翻译 pipeline 升至 v3，缓存继续核验来源制品 ID 与哈希；v2 译文会在下次手动请求时重生成，
  此失效范围也包含输入未改变的纯文本和 ASR，不批量回填。
- 阅读时直接投影已发布原稿，已有稿件刷新页面即可生效，无需回填或重新请求供应商。
- 游标升级至 v3 并绑定实际阅读文本 SHA-256；旧游标或投影变化返回现有 400，
  前端沿用已有重新载入第一页逻辑，防止旧字符偏移跳过正文。
