# Issue #101：接收端文件复用与同步进度

实现基线：`cdc2a71`。内网接收端默认 local；兼容现有 OSS 写入、缓存读写租约与元数据条件更新。

## 实现边界

- 整页校验与元数据事务保持。文件依照已接纳的 authority、清单大小、SHA-256、MIME/扩展名检查。
- 校验本地内容寻址文件；完整则复用并完成状态登记，否则下载、验证、唯一临时文件原子替换。
- 本地校验按块读取，文件读写及 OSS 持久化期间持有缓存租约；文件 I/O 不持有数据库读事务。
- 复用与下载共用状态提交，提交时条件匹配原始身份、权威及版本，不能覆盖并发新清单或音频撤回。
- 不提前推进 checkpoint，不改变数据流顺序，不加入日期过滤或下载并发。

## 进度契约

Job 增加可空 `progress_json`（配套 Alembic），接口新增 `progress`。
V2 上报绝对累计已处理记录数、当前流及该流已处理记录数、复用/下载文件数及字节数。
阶段切换和首条完成立即落库，其余沿用任务进度节流；失败终态保留最后成功进度。
文件完成状态提交后才计数，媒体页尾不再次累计。音频 tombstone 计入记录数但不计为文件。
前端显示当前阶段和实际计数，不从当前页大小推算全任务百分比；V1 与旧任务保持原有展示。

### Claude Code 交叉检视

实现方：Codex。本轮检视方：Claude Code 2.1.275 / Fable 5.1，实际会话模型确认为
`claude-fable-5-1`（调用配置 `claude-fable-5-1[1m]`）。检视目标为基线 `cdc2a71`
至代码提交 `e6f781a` 的完整差异，通过本机 CLI 调用，仅开放 Read/Grep/Glob。

交叉检视已完成：未发现必须修复的确定性缺陷。Fable 逐条跟踪了权威与重放、条件提交、
原子替换、OSS 租约、进度持久化、旧任务兼容及迁移链。以下处理结论已在同一会话逐项协商一致：

- O1/O2（OSS 恢复优化）：非阻塞观察。本次只将经过本地完整大小、哈希和格式验证的文件计为复用。
  OSS 冷缓存遇到失败重试、checkpoint 重置或图片引用文章 revision 变化时，仍会对每个冷文件
  请求生产者二进制，并依赖生产者继续提供它；这是保留的旧依赖，不是本次新增回归。
  未来可在租约及并发保护下恢复、验证、原子替换后复用；不直接凭 OSS 登记计复用，也不直接删除坏文件。
- O3（性能）：未落盘文件的额外条件 UPDATE、OSS 复用时重复哈希与 HEAD 暂保留，维护当前持久化保证，
  后续按实测优化。
- O4（临时文件）：进程被强杀可能遗留 `.part` 文件，现有清理器未覆盖；属于已有清理债务，另行处理。
- O5（可访问性）：进度区域使用 `aria-atomic`，轮询导致内容变化时可能整体播报；后续考虑只播报阶段切换，
  并做真实读屏验收，本轮不扩大 UI 行为修改。
- O6（诊断文案）：畸形媒体哈希可能沿用 podcast text 的错误前缀；保持 fail-closed，文案改进记观察项。
- U1（未来维护约束）：当前声明比较与音频归一化一致；`_validated_podcast_audio_payload` 与二进制阶段的
  声明比较必须同步演进，改动归一化规则时同步比较逻辑并补用例。
- U2/U3：现有 authority 用例覆盖已提交页重放时的二进制守卫；阶段/首条同步落库沿用任务进度机制。
  两项均无需代码修改。
