推送绑定 · 样页总览

管理员在哪里登记一个推送的来源、把它交给哪个令牌,以及怎么一眼看出哪个源有 Agent 在推。

底页是主干(46cc0c5d)在隔离栈里的现网页面,数据是虚构账号。每个画框右上角可以打开可点的原型;原型底部的深色条是样页开关,不属于产品界面。

1 · 收录令牌

运维 → 自定源与收录。表里多一列「来源」;点一行,在抽屉里加、解这个令牌的来源。

2 · 源管理

每一行写明这个源怎么拿到内容:抓取(平台的抓取器去拿)、推送(令牌送来)、抓取 · 推送,两样都没有的是无抓取。这一格原来写的是内容形态,与上面的页签重复。只推送的源,最后一列是最近一批推送的时间。

右侧检视器按同样的两样分成两个框:「抓取」框的题条右侧写抓取器,框里是参数、运行动作与近期运行;「推送」框列出在推它的令牌。框住的都归它,「近期运行」是「抓取」框里的小节;「源审查」在框外、与两个框同级。页头多一个「登记来源」。

3 · 登记来源

源管理页头的「登记来源」。给了账号或站点的是定向源,只收这一处的内容;选「不限」的是合集,一个源里可以有很多账号的推文。

4 · 读者面

页面与逻辑不变。只有转推卡片顶上那一行的名字要改:现在取源的名字,在合集里会变成合集的名字。改为取转推者本人。下面是这一行的文字示意,不是卡片的截图。

帖子所在的源现网改后 账号源「X · Sam Altman」 X · Sam Altman 转推 Sam Altman 转推 合集「Grok 推荐」 Grok 推荐 转推 Sam Altman 转推

6 · 样页的边界

来源、令牌、时间和条数都是示意。原型里能点的是:令牌表的行、抽屉的关闭、「登记来源」和它的类型与出处切换;「绑定」「解绑」「登记」不会改动任何数据。

没有画的:签发令牌的同时选来源(接口支持,界面先不加);未绑定令牌推送被拒收时的回执(见方案 §4);手机壳(管理面不在手机壳里)。
