不随方案变化的规则

  • 翻什么：转推取原推全文（reposted.text），不翻顶层「RT @xxx: …」截断文本；引用推（quoted.text）和主推一次翻完；不翻推文标题（只是首行截断，卡片上不显示）。
  • 哪些推文出入口：看 X 检测的 lang。zh 不出；zxx / art 等无语言内容不出；und 或缺失时退回现有的中文启发式。引用推、转推的内嵌结构现在没存 lang，本波在采集时补上，存量走启发式。
  • 样页里的边角：Qwen 那条主推只有表情加链接（art），引用推是英文，所以入口照常出现，只译引用推；Karpathy 那条只有一个链接的转推（zxx）没有入口。
  • 门控：和文章翻译同一套 AI 开关（全局总闸、账户开关、模型已配置），任一不满足就整个不出现，见「AI 未开启」。
  • 失败：就地一句说明加「重试」；额度用尽（429）只给说明，不给重试。
  • 计费：方案 A / B 一次点击 = 一次请求（主推 + 引用推一起），扣一次翻译额度（现行每人每天 50 次）；收起再展开读缓存，不再扣。
  • 后端（预告，样页不涉及）：复用 #201 的分段计划（链接自动保护成占位符、只接受完整输出、带乐观锁写缓存）；推文用专门的提示词（@用户名、#话题、表情原样保留）；译文缓存进 extensions_json 新键，按文本指纹失效。
  • 素材：本机库 7 条真实推文（7 月）；本机库没有中文推文，所以看不到「中文推不出入口」的例子。样页把「现在」定在 2026-07-24。Qoder 的头像上游已 404，按现网行为显示灰色圆底。
  • 译文：Claude 按平台翻译提示词的规则手写的示意，不是平台模型的实际输出。
