播放坞与展开页

状态:待选(2026-10-29)

用户原话(第 8 轮):「对播放器进行重新设计。底部播放器组件当前只有一个按钮，不是很实用；展开页也有一些问题，如按钮的大小不统一（一些人可能不喜欢）；1x、缩小、关闭这几个按钮纯文字，太草率，且这三个按钮与上方的圆形按钮对齐性很一般；前进、后退按钮没注明多少秒，用户容易误解；关闭按钮直接停止播放，但是用户很容易误以为这个按钮的作用只是关闭这个展开页（毕竟缩小按钮的作用是缩小展开页到组件状态）；我有一个idea是，播放器组件点击的时候展开为一个圆角矩形，悬浮在底栏之上，而非现在这样是个连通到底部的卡片。可以考虑为方向之一。」这里给三个方向,另加现状当尺子。三个方向守同一组约束:只用现网已有的播放能力(播放 / 暂停、前后各 15 秒、拖进度与键盘、倍速 1 / 1.25 / 1.5 / 2 循环、收起、停止 = 停播并收掉播放坞、出错重试、缓冲、打开这一期、续播位置与锁屏控制,都在 frontend/src/components/player/),唯一要新增的播放能力是停止后提示条上的「撤销」(约 20 行;不做也成立),另有几处纯界面的新增(B 的卡外遮罩、C 的 ⋯ 菜单、坞上往上拖展开),见「现网能力核对」;坞仍是一行 60px 的浮动胶囊(封面模糊底 + 进度环),默认在播放钮左边加一枚「后退 15」;跳转钮的圆弧箭头里写秒数;「收起」(⌄,回到坞、继续放)与「停止播放」(■,停播并收掉坞)拆开,停止播放不在主控件那一行;倍速钮写当前档位;两行控件对齐到同一套栅格。每个方向三台手机(亮暗各一套):列表页收起态 / 展开态 / 正文页收起态,都能点;页顶另有 状态(正常 / 缓冲 / 出错)· 条目(原节目 / AI 导读)· 坞上(后退 · 播放 / 三枚 / 播放 · 前进)三组开关与「重置」。文中尺寸都是 Playwright 实测的手机屏坐标(sat 47 / sab 34,屏高 740),宽 360 / 390 / 430 × Chromium / WebKit。播放器的表面都是封面模糊底(issue #199 拍板,不用 backdrop-filter);Playwright 的 WebKit 不渲染 backdrop-filter,只在底栏、页头小圆钮和 C 的 ⋯ 菜单上看到降级观感(近实色、底下的字隐约透出),真机 Safari 有模糊。

现状

主样页现在的坞与展开页

对照

第 6 轮主样页的播放坞与播放展开,原样照搬当尺子:收起态是一行 60px 的浮动胶囊(封面进度环 · 标题 / 节目 · 时间 · 一枚 44 的播放钮),点坞从底部升起一张贴底的底页(顶 120):200 封面、标题、进度、56 / 68 / 56 三枚圆钮、「1× · 缩小 · 关闭」三个字钮。主样页没画缓冲 / 出错,AI 导读的坞上也不写「AI 生成」,这里照实不画。现网手机现在是另一个样子:两行 94px 的播放条(封面 · 标题 · −15 · 播放 · +15 / 进度 · 倍速 · 缩小 · 关闭)外加右下角迷你;主样页第 1 轮把它改成「一行坞 + 底页」,拍板 6 还没定。

优点

  • 坞只有一枚钮,标题最宽(360 宽 214,比 A / B / C 多 42)
  • 展开后的大封面与居中标题,一眼认得出是哪一期

风险

  • 意见 1:收起态只有一枚播放钮,想倒回去听一句必须先展开
  • 意见 2:展开态圆钮 56 / 68 / 56,下面的字钮是 44 高的透明区,三档尺寸混在一起
  • 意见 3:「1× · 缩小 · 关闭」是裸字,三列按 gap 20 居中排,和上面按 gap 28 排的三枚圆钮各列中心差 22 / 2 / 24(360 宽)
  • 意见 4:±15 只画了圆弧箭头,没写秒数
  • 意见 5:「缩小」和「关闭」并排,「关闭」读起来像关这个窗口,实际是停播并收掉坞
  • 主样页没画缓冲 / 出错;AI 导读的坞上只写节目名,不写「AI 生成」(conventions §8 要求播放条上写可读文字)

A

整理底页

推荐第 3

不换形态,只把用户的五条意见逐条修掉,看「只修细节」能修到什么程度:展开后仍是贴底的底页(把手往下拖 / 点遮罩 / 收起都能关),高度改为按内容取(360 宽顶 227、高 513)。主控件三枚统一 64(播放只靠墨色实底区分主次,回应「按钮大小不统一」);下面一行改成三枚等宽胶囊「⏲ 1× · ⌄ 收起 · ■ 停止播放」,和上一行用同一套三列栅格(列间距 12),每列中心对齐;±15 的圆弧箭头里写「15」;标题块整块可点,推入这一期的正文页(现网 onOpenItem)。坞上加一枚「后退 15」。

优点

  • 改动最少:还是读者见过的底页,只是钮整齐了、字有了图标、秒数写了、收起与停止分开了
  • 三枚 64 圆钮等大,是三个方向里唯一「完全统一尺寸」的展开态;三枚胶囊等宽,两行同一套三列栅格,同列中心差 0(360 / 390 / 430 × 两种引擎)
  • 底页高度按内容取,360 宽比现状(620)矮 107,背后列表多露出 107

风险

  • 仍是整屏底页:盖住底栏、压暗全屏,为调一下倍速也要打断阅读;只想暂停时还是去坞上
  • 停止播放胶囊在 +15 正下方 20px,手往下偏一点就停了;靠停后的「撤销」兜底(撤销是新增能力)
  • 三枚等大让播放钮与跳转钮同一个分量,常按的播放不再「最好按」;有人会觉得少了主次

悬浮卡

推荐第 1

用户的想法:点坞后,坞原地长成一张圆角矩形卡(圆角 24),悬浮在底栏之上——卡底就停在坞底(底栏之上 8px),底栏仍可见、照常能点,不连到屏幕底。卡里:64 封面 + 两行标题 + 节目 · 音轨 ›(整块推入这一期的正文页)、右上 ⌄ 收起;进度;52 / 64 / 52 三枚圆钮;一道细线下,倍速在第 1 列、停止播放在第 3 列,与上面的圆钮同列对齐。卡外的列表压一层 18% 的淡遮罩(暗色 42%,底栏不压):点卡外只收卡、不穿透;往下拖卡、点 ⌄、按 Esc、切底栏都收回坞。卡的最大高度 = 坞底到状态栏下 12px,内容超了卡内滚动。形变照夜航弹簧:clip-path 从坞的矩形长到卡的矩形(500ms,阻尼 0.84),坞的内容 150ms 淡出、卡的内容 80ms 后弹进来;收回反向(420ms,阻尼 0.9);减少动效 = 120ms 淡入淡出。

优点

  • 就是用户的想法:卡从坞原地长出来,收回去还是那枚坞(来处即去处);卡底停在坞底,底栏不动、照常能点,切 Tab 一次就切过去
  • 卡只占屏高 37%(740 高里 270),列表还露出 259px、只淡压一层,读者知道自己还在列表里;A 的底页要占 69%
  • 所有控件都落在屏幕下半部分的拇指区(最高的 ⌄ 中心在 y 390,屏高 740);尺寸三档各有其位:播放 64 最好按,±15 52,收起 / 倍速 / 停止播放 44
  • 倍速与停止播放在细线下、与 −15 / +15 同列,同列中心差 0;⌄ 的圆右沿、封面左沿与进度行边沿差 0

风险

  • 卡外点按只收卡、不穿透到列表(防误点);第一次可能「点空一下」。备选是不压暗、点卡外穿透(待拍板 4)
  • 要新写一个「坞 → 卡」的形变:现网 playerFx.js 的 expandMorph(迷你 → 条)是同一种 clip-path 写法,可以改出来,但仍是新代码,要过 conventions §7 播放条形变的护栏
  • 横屏(390 高)放不下 270 高的卡加底栏;建议横屏直接走 C 的就地展开或迷你化(审计 M-12 本来要定横屏策略)
  • 卡和坞之间有一次「内容换版」(坞的一行 → 卡的四行),做不好会闪;样页用 150ms 淡出 + 80ms 后弹进,真机要再看

C

坞内展开

推荐第 2

最轻的一档:坞原地变高,60 → 148,分三行——这一期(封面环 · 标题 · 节目 · 音轨)+ ⌄ 收起 / 进度 / 五枚等大 48 圆钮「倍速 · −15 · 播放 · +15 · ⋯」;不出大封面、不压暗、不盖底栏,列表照常能看能滚(滚过 40px 自动收回坞)。停止播放收进 ⋯ 菜单(还有「查看这一期」),两步才停,最不怕误触。⌄ 在第 1 行第 5 列,正对下面的 ⋯。形变:clip-path 从坞的高度长到 148(480ms,阻尼 0.84),内容交叉淡入;减少动效 = 120ms 淡入。这其实就是现网两行播放条的精神(控件就地全给),只是收起时缩成一行坞。

优点

  • 动静最小:不换层、不压暗、不盖底栏,列表照常能看能滚,露出 381px;想调完就走,滚一下列表坞就收回去
  • 五枚放音控件一律 48,一行五列等宽栅格,栅格偏差 0;⌄ 与 ⋯ 同列(偏差 0)
  • 停止播放收进 ⋯,两步才停,三个方向里最不怕误触;不依赖「撤销」也成立
  • 离现网最近:现网两行条本来就把控件就地全给,C 只是让它平时缩成一行坞;不需要新的遮罩层,popover 用层原语现成的

风险

  • 五枚等大在 360 宽最挤:列宽 64、圆钮之间 16;倍速与 −15 挨着,手大的人可能点错(都无害)
  • 停止播放藏进 ⋯:第一次想停的人要先猜到 ⋯ 里有;收进菜单也意味着多一步
  • 没有大封面,认是哪一期只靠 44 的小封面与一行标题(标题可用 202,长题省略)
  • 坞变高 88px,列表底部让位跟着加,滚到底的最后一条会被往上推一截(现网 applyClearance 有跟手下滑可复用)
