## 设计陈述

把早报的「夜航」气质铺到整个手机壳。内容铺满全屏,顶栏、TabBar、播放坞是浮在内容上的磨砂镀层,往下读时退场、往上一划就回来。第 2 轮按 Folo 手机版的**功能组织**重排(视觉仍是夜航,不照搬它的橙色与版式):**底栏是功能模块**——早报 · 内容 · 订阅 · 榜单 · 设置(第 4 轮定稿早报独立成 Tab);**内容类型上移到「内容」顶栏中间**——文章 / 播客 / 社交 三项固定位,当前视图在原位放大一档、转墨色(第 3 轮定 B 转盘,第 5 轮改为三项固定位;视图上不挂未读点);每个视图仍是现网那条独立的流,不混排。来源从「过滤器底页」变成「订阅」这个目的地:按分组列出所有订阅,点一个就在订阅 Tab 里推入它的条目流;发现更多来源、兴趣、收藏都收在这里。「我的」与设置栈一级页合成「设置」。长按、早报版式沿用第 1 轮;正文页第 4 轮去掉底部坞,翻译与查看原文进右上「⋯」菜单;往期定为底页月历。动效用弹簧(阻尼振子采样成 `linear()`,与播放条同一种做法),全部受 `<html data-motion>` 开关控制。

### 「全部 / 未读」:收进顶栏图标

采用顶栏一枚开关图标:空心圈 = 显示全部,带点的圈 = 只看未读;开着时顶栏视图名下面写「只看未读」,切换时有提示条。理由:

1. **作用范围对得上**:现网 `unreadOnly` 是 useReaderState 里的一个全局状态,文章 / 播客 / 社交共用;放在三条流共用的顶栏里,位置就是它的范围。留在筛选行,每个视图都得各放一份,看起来像各管各的。
2. **控件带更少**:保留固定分段的话,播客 / 社交会多出一条只放「全部 | 未读」的行;收进顶栏后,列表上方 文章两条、播客 / 社交一条。
3. **往下读也够得着**:顶栏固定,筛选行会随列表滚走。
4. **第 1 轮的根因在新形态下不成立**:① 开关在固定的顶栏里,不在任何横滑轨里(类型胶囊另起一行横滑);② 它只是 `aria-pressed` 两态的按钮,没有拇指、不量任何宽度,隐藏视图里改状态也不会塌。自检按第 1 轮的步骤复测,外加「切到播客再回来」。

代价是图标不如两个字直白,用「开着时写字 + 提示条」补;若目检仍觉得不清楚,退回第 1 轮的固定分段只要把它放回类型行最左,第 1 轮的修法照样成立。

## 风险

- **推入页的第二个列表实例**是本轮最大的落地成本(见落地注记)。退路:推入页 = 切到内容 Tab 并带上来源过滤(就是现在抽屉的语义),但那会改动内容 Tab 的状态,与「不动内容 Tab」相反。
- 底栏少了播客 / 社交直达:去社交从点一下变成两下(内容 → 顶栏的社交);内容 Tab 记住上次所在的视图能缓解,样页没画。
- 订阅列表把三种形态的订阅合在一张表里,订阅多时很长(现网按容器分开列)。太长的话,可在订阅段加同款视图切换按形态过滤,代价是多一条控件带。
- 视图切换的三项整体偏左(左边头像 44px、右边三枚钮 132px),不在屏幕正中;360 宽时槽位约 57px,选中「社交」放大后离「只看未读」钮约 11px,再加第四个视图就排不下,要换形态。第 3 轮「离当前两格以外要拖一下或先点邻居」的问题,第 5 轮改成三项固定位后已不存在。
- 「只看未读」只是一枚图标,第一次用的人未必认得;已用开着时当前视图名下写字 + 提示条补,真机目检时留意。
- 手机月历把失败日当「没有」(灰、不可点),桌面月历标红、可点,两端看到的不一样;编排失败的那天在手机上看不到失败原因。
- 翻译从正文底部坞挪进「⋯」菜单,英文文章切换语言多一次点击,第一次用的人要先知道「⋯」里有它。
- 第 1 轮起:backdrop-filter 在低端安卓、华为浏览器、微信 X5 内核上掉帧或不支持(已写降级,Playwright 的 WebKit 截图里磨砂也不生效);TabBar 下滚退场与 iOS Safari 地址栏伸缩叠在一起;底页手势与系统返回、下拉刷新抢手势;早报卡长按是新交互;改动面大(抽屉 → 订阅 Tab、正文去顶栏、镀层与手势都是结构性改动)。
