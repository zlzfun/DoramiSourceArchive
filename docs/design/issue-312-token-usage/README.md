# issue #312 令牌交付计量 · 样页(2026-11)

> 状态:耐久参考。2026-11-19 由 Claude Code(Fable 5.2)做的第一轮样页,**待拍板**;拍板依据,实现后不再更新。方案见 [`docs/plans/issue-312-token-usage.md`](../../plans/issue-312-token-usage.md),issue [#312](https://github.com/zlzfun/DoramiSourceArchive/issues/312)。

要回答的是一件事:管理面怎么把 **账户 → 它的令牌 → 接口调用与调用量** 连起来。

## 怎么看

在仓库根(本 worktree)起一个静态服务,再打开总览页:

```bash
python3 -m http.server 8765 --bind 127.0.0.1
# http://127.0.0.1:8765/docs/design/issue-312-token-usage/index.html
```

字体与品牌图引用 `frontend/public/`,所以要从仓库根起服务;不请求任何外部域名。样式与脚本的地址都带 `?v=`,返修时把 `index.html`、`app.html`(由 `tools/build.py` 的 `VERSION` 生成)与 `assets/index.js` 里的版本号一起改掉——`http.server` 不发缓存头,浏览器普通刷新不会重新取这些文件。

| 文件 | 内容 |
|---|---|
| `index.html` | 总览:账户页 A / B 并排、三种账号的抽屉、设置卡 现网 / A / B、记什么、待拍板、样页的边界 |
| `app.html` | 可点原型。底部深色条是样页开关(方向 / 看哪里 / 设置卡 / 数据 / 明暗),不属于产品界面。地址 `app.html?dir=<a\|b>&view=<page\|drawer\|settings>[&user=<账号>][&card=<now\|a\|b>][&state=<live\|empty>][&theme=<light\|dark>][&focus=<api\|table\|top>][&top=<reads\|logins\|api>][&bare]` |
| `assets/app.css` | v3.69.0 应用样式的原样导出(`document.styleSheets`),只去掉登录页专用的三条 `@font-face` |
| `assets/proto.css` | 新增部分的样式。上半是要落地的(`.tok-*` `.seg-bar` `.endpoint-n` `.endpoint-group`,取值只用现有 token),下半 `.px-*` 是样页开关 |
| `assets/proto.js` | 示意数据 + 新增部分的渲染 + 样页开关 |
| `assets/index.{css,js}` | 总览页自己的样式,以及把原型裁切、缩放进画框的脚本 |
| `tools/build.py` | 把沙箱抓到的现网 DOM 整理成 `app.html`(去掉其它标签页、清空带真实账号名的表体与图,留给 `proto.js` 重画) |
| `tools/shots.py` | 自查:逐个状态打开原型截图,收集控制台报错与失败请求 |

## 做法

1. **底稿是现网**。在隔离栈(v3.69.0,开发库副本,密钥清空、自动任务全关)里登录根管理员,用 Playwright 抓「运维 → 账户」整页、单用户抽屉、设置 → 聚合接口的 DOM,以及 `document.styleSheets` 导出的样式。原型里没改过的地方就是现网本身。
2. **新增部分沿用现有形制**。账户表的列头、排序箭头、筛选轮换;榜条、堆叠柱的取值(刻度 12px、网格线、条宽与描边);抽屉里接口明细的名称 + 数值 + 细条(现网「各源阅读 / 收藏」那一套);设置卡的行与胶囊——都照现网标记写。新起名字的只有令牌身份(`.tok-id`)、令牌卡(`.tok-card`)、占比条(`.seg-bar`)和设置卡 B 的两个小件。
3. **数据是示意**。8 个虚构账号沿用快照里 8 行的登录 / 阅读 / AI 数字(所以页头 KPI 与账户增长图不用动);令牌与调用由 `proto.js` 里的清单加固定种子的随机数生成,KPI、活跃榜、账户表、令牌台账、抽屉、设置卡同源,彼此对得上。
4. **自查**(2026-11-19):`tools/shots.py` 的 17 个状态(A / B 整页、板块亮 / 暗 / 尚无调用、五种账号的抽屉、设置卡三种 + 暗、带开关条、总览页)零控制台报错、零失败请求;截图逐张看过。

## 两个方向

- **A 并入现有**:页头 KPI 加第六格「接口调用」;「活跃用户 Top」加「按接口」;账户表加「接口」列(可排序);关系在单用户抽屉里看。不加板块。
- **B 加令牌台账**(推荐):A 的全部,再在「活跃用户 Top」与「账户管理」之间加一个板块「接口调用」——上面是每日走势(按文章 / 热点事件 / 单订阅 / MCP 四组堆叠,可切调用 / 条数),下面是令牌台账,一行一枚令牌,列序就是那条关系:账户 · 令牌 · 接口 · 最近调用 · 调用 · 条数。点一行,开这个账号的抽屉并定位到这枚令牌。

两个方向共用的抽屉「接口调用」区:一枚令牌一张卡(类型 + 尾号,作废的挂「已作废」),卡头是调用次数与返回条数,展开是它调过的每个接口;其下是每日接口调用图。账号没有令牌时这一区不出现。

## 数据来源

全部是新增,现有接口里没有一个数能复用:

| 界面上的数 | 来自 |
|---|---|
| KPI「接口调用」与「N 枚令牌在用」 | 新表按窗口汇总(`/api/admin/accounts` 的 `summary` 加字段) |
| 活跃榜「按接口」、账户表「接口」列 | 新表按账号汇总(`/api/admin/accounts` 逐行加 `api_calls`,排序键加 `api`) |
| 板块的每日走势 | 新表按日 × 接口组汇总(新只读端点) |
| 令牌台账 | 新表按令牌汇总 + 现有两张令牌表(判断是否仍是现用的那枚) |
| 抽屉「接口调用」区与每日图 | `/api/admin/accounts/{username}/activity` 加一块 |
| 设置卡的「最近调用 / 近 30 天 N 次」 | 读者自己的令牌状态接口加字段 |

## 默认处理(没有单独问的)

- 列出哪些令牌:现用的聚合令牌(没调过也列,标「未调用」)+ 调过的任何令牌。
- 空态:窗口内没有调用时,走势图的位置显示「窗口内还没有接口调用」;账户表该列显示「–」(同登录 / 阅读列)。
- 板块在 `utils/opsNav.js` 登记为 `['api', '接口调用', { root: true }]`,位置在 `top` 与 `table` 之间(观测在上、台账在下)。
- 令牌台账超过 15 行分页(同账户表)。
- 抽屉里「接口调用」区排在「登录」之后、「各源阅读 / 收藏」之前。

## 样页的边界

- 抽屉里原有的「各源阅读 / 收藏」「每日 AI 用量」两块对每个账号都是同一份快照(admin 的画面)。
- 时间窗、账户搜索、角色 / 状态 / AI 筛选、勾选批量这些现有控件没有接;新加的排序、令牌筛选、调用 / 条数切换、点台账行开抽屉是接了的。
- 设置卡 B 里各接口的次数加起来不等于令牌下那一行的总数——总数还含 MCP 与事件详情,卡上没有它们的行。
- 只画了桌面(手机设置自 issue #230 起不列「接入集成」)。
- Windows 下没有实测:新增部分只用了现有的字体栈、等宽字体与实色条,没有新的合成属性或动效。
