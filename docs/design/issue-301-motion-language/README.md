## 怎么看

在仓库根（本 worktree）起一个静态服务，再打开总览页：

```bash
python3 -m http.server 8765 --bind 127.0.0.1
# http://127.0.0.1:8765/docs/design/issue-301-motion-language/index.html
```

字体、品牌图引用 `frontend/public/`，数据与配图引用 `../issue-279-frontend-refactor/assets/`，所以要从仓库根起服务；不请求任何外部域名。

样式与脚本的地址都带 `?v=`。`http.server` 不发缓存头，浏览器普通刷新不会重新取这些文件，每次返修要把 `index.html`、`app.html` 与 `assets/index.js` 里的版本号一起改掉。

## 做法

1. **调研**：读了 emilkowalski/skills（`animate` `choreograph` `find-animation-opportunities`）、pbakaus/impeccable（`animate`）、vercel-labs/web-interface-guidelines 的原文，查了 Motion、GSAP、React Bits 等库与 View Transitions、滚动驱动动画、`@starting-style` 等平台能力在 2026-11 的状态。结论在总览页「调研」一节。
2. **普查**：脚本统计 `frontend/src/index.css` 与 `mobile.css` 里的 keyframes、过渡声明、写死的时长与曲线、按下态；逐条核对读者面桌面现有的入场与离场（`ReaderTab.jsx` 的 `reader-enter` / `reader-list-enter`、问答面板、浮层、提示、里程表）。结论在「现状」一节，「现网」一列按它移植。
3. **分方向**：四种语言各有一个主张与一组材料，在同一份原型、同样的 14 个场景上各做一遍，逐行并排比较。
4. **自查**（2026-11-18）：现网与四个方向各 14 个场景冒烟零报错；每个方向挑 3–6 个场景录帧逐帧看过（A：指示器、打开文章、分数滚动；B：打开文章、问答、明暗、榜单进事件；C：早报到场、问答、明暗、打开文章，亮暗各看；D：早报到场、打开文章、明暗、速读卡），其余场景只过了冒烟、没有逐帧看；脚本连点两行、浮层连开连关、问答连点、连切三个视图、明暗连切、轮流切方向之后查残件、减少动效下到场，五套都没有报错、没有停在半透明或模糊状态的元素。

## 第二轮：选定稿（2026-11-18）

用户在总览页逐行选定后复制回来的原文：

| 场景 | 选择 | 场景 | 选择 |
|---|---|---|---|
| 悬停与按下 | A 精密 | 早报到场 | B 连续 |
| 指示器与筛选 | B 连续 | AI 速读卡 | C 光 → **A 精密**（11-19 改） |
| 浮层开合 | A 精密 | 收藏、标读与提示 | A 精密 |
| 打开一篇文章 | A 精密 | 明暗切换 | A 精密 |
| 切换视图 | B 连续 → **A 精密**（11-19 改） | 阅读时滚动 | B 连续 |
| 来源栏收起与展开 | B 连续 | 榜单进事件页 | B 连续 |
| 问答面板 | C 光 | 订阅一个来源 | B 连续 |

在场与退场：沉浸阅读做；行内动作、来源栏探出、吸顶栏收放不做。D 刊物没有一行被选中。

`assets/dir-s.*` 按这张表合成：每类交互取自被选中的方向，取值收成一套（三条曲线、五档弹簧），交界处的归属列在总览页「合并时定的几处」。自查：14 个场景冒烟零报错；录了 18 段中间帧，逐帧看过 10 段（打开文章亮暗各一、未读筛选、类型签筛选、往下切视图、浮层变来源栏、提问与回答、亮色下打开问答、榜单进事件页、订阅飞入）；另 8 段录了没有逐帧看（往上切视图、收起来源栏、浮层、暗色下打开问答、事件页返回、明暗、提示、到场），它们的代码与第一轮看过的对应方向相同；连点、连开连关、中途切视图、减少动效、切方向残件、沉浸阅读进入与唤回、总览页静置不跳动都过了。

**2026-11-19 改动**：用户看过选定稿后要求「打开一篇文章」与「切换视图」都按精密，其它不变。打开文章原本就是精密（核对过，除速读卡按「AI 速读卡：光」外与 A 的写法一致）；切换视图从连续（沿导轨方向 28px 升入）改成精密（内容直接换 + 100ms 淡入，导轨上的指示器仍按连续的滑法）。随之变化：View Transitions 只剩榜单卡成页、浮层变来源栏两处转场加明暗；「导轨是纵轴」不再进规则；React 升级的建议由「升」改为「先不升」（由状态驱动的转场只剩两处，原生接口加 `flushSync` 手写）。复查：14 个场景冒烟零报错；往下切、往上切、亮色下切视图、榜单进事件页、事件页返回五段录帧，除榜单进事件页外逐帧看过；事件页返回时卡不在视口的退路（`ms-swap` 交叉淡化）、60ms 间隔连切四个视图、减少动效下切视图，终态都正确、没有残留。

**2026-11-19 第二次改动与放行**：用户答复「速读卡也不要发光。其它的按你的建议，即 React 可以升。现在开始开发吧。」AI 速读卡从光改成精密：卡体随正文 120ms 淡入，分数逐位滚动（弹簧并进 move，落定 583ms），极光、各句对焦、分数点亮都去掉；光只留给问答面板。分数里程表因此不是退役而是缩短（2.2s → 约 580ms）。React：按建议先不升，用户已许可需要时升。总览页「待拍板」改成「拍板」。

## 样页与平台现状的出入

- 底稿是 issue #279 的可点原型（香草脚本，整段重画），不是现网的 React 代码；实现手法要在落地时换成 React 的写法。
- 「现网」一列：来源栏列宽 240ms 一条取自原型，现网对应处没有核实；现网的问答面板是右下角浮起的小窗，样页里是 #279 的侧栏形制，只移植了它的曲线与时长。
- 问答的回答是用早报前三条拼的，分段出现是模拟的流式；现网问答是轮询。
- 数据是 2026-11-10 生产站游客接口的只读快照。
- 只在 Chromium 上看过（无头模式的录帧与截图，没有在真实显示器上测帧率）；Windows、Safari、Firefox 没有实机看。
- 没有画手机壳与管理面；播放条沿用现网已拍板的形变。
