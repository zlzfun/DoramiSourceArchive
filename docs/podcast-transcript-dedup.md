# 播客逐字稿通用去重方案

## 目标与边界

ASR 供应商可能把同一混音节目按双声道或多声道重复返回，也可能把真实的分轨说话人分别返回。
去重必须位于 Provider adapter 与规范化逐字稿之间，输入只依赖 `begin_ms`、`end_ms`、`text`、
`channel_id` 四个结构字段；任何 ASR Provider 都复用同一策略，禁止按节目、来源、语言或声道号
写特例。

核心原则是宁可留下少量重复，也不能删除未证实的独有内容。去重单位是片段，不是整个声道。

## 判定流程

1. 按有效时间覆盖、词级时间戳完整度、文本量、声道号对声道确定稳定的证据优先级，仅用于决定
   重复簇保留哪份；覆盖相同时优先保留词级证据更完整的一侧。
2. 每个候选片段只与其他声道中已保留、时间相交的片段比较。
3. 时间完全一致且文字完全一致时直接视为重复，包括很短的应答。
4. 近似重复必须先有至少 `50%` 的原始时间覆盖，再同时满足：允许 `250ms` 时间漂移后覆盖候选
   片段至少 `80%`；候选至少有 4 个 token；候选文本 token 必须 `100%` 连续出现在参考文本中。
   因此“重复内容 + 同段独有增量”不会被整段误删。
   如果同一对声道已有长片段通过上述双重证据确认镜像关系，相邻切句产生的 2～3 token 短片段
   仍须达到 `95%` 时间覆盖和 `100%` 有序文本覆盖才删除；单独出现的短应答继续保留。
5. token 化安全覆盖 Unicode 文字：拉丁文字和数字按词处理，其他文字按组合字符单元处理；大小写
   与兼容字符归一化，重音不会被静默丢弃，标点不参与相似度。中文、韩文、阿拉伯文、泰文等
   不依赖空格分词也能使用同一策略。
6. 一个片段可与同一参考声道的多个相邻片段联合比较，因此支持 ASR 切句不同；时间覆盖和连续
   文本必须由同一个参考声道同时满足。不会把多个真实分轨的时间或文字拼成一份虚构参考，也不会
   用散落在长文本不同位置的词拼出一次命中。时间覆盖只由连续文本窗口实际涉及的参考片段计算，
   同一声道的无关片段也不能代替它补足时间证据。
7. 只删除已证明重复的片段。一个声道即使大部分是镜像，只要仍有独有片段，该片段及其词级时间戳
   就继续保留。
8. 词级证据只跟随所属片段过滤；保留下来的不同语义片段即使共享同时间、同文字的词，也不会再
   做跨声道二次删除。
9. 输入片段和词会按时间、声道、文字生成稳定顺序；时间候选使用区间索引，单次文本比较限制为
   2,048 token / 65,536 字符，异常超长证据选择不去重，避免阻塞 worker。

实现返回重复片段的匹配方法、时间覆盖率、文本覆盖率、参考声道，以及完全/部分去重的声道集合，
供真实样本验收使用；规范化逐字稿格式本身保持不变。

## 验收矩阵

- 完全相同的双声道：只保留一份。
- 数毫秒错位且切句不同的镜像声道：只保留证据更完整的一份。
- 同时说话但内容不同的真实分轨：全部保留。
- 只有共享片头、主体内容不同的分轨：只去掉重复片头，不把整个声道视为镜像。
- 大部分镜像、尾部存在独有内容：只删除重复片段，保留独有尾部。
- 孤立且很短的相同应答：保守保留；只有时间和文字完全一致才删除。若同一声道对已由长片段
  确认镜像关系，2～3 token 短片段仍须满足 `95%` 时间覆盖和 `100%` 连续文本覆盖才删除。
- 中英文逐字稿：使用同一算法，无语言或来源特判。
