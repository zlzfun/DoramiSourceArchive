# R1 全文翻译实测

2026-10-20，使用本机当前有效 LLM 配置，对本地阅读器对应的 **arXiv 2501.12948v1** 全文进行真实翻译。结构化协议修复后完成全文，公式、表格结构与表格数值通过检查；语义对照发现的零样本/少样本与基准专名误译由 [#205](https://github.com/zlzfun/DoramiSourceArchive/issues/205) 加入有限术语保护后，真实全文重验通过。不能把结构完整等同于语义完全正确。

## 范围与方法

- 固定输入：[R1 v1 官方 HTML](https://arxiv.org/html/2501.12948v1)，已转换正文 62,643 字符；SHA-256 `e544ceeff99b22e4b6cfce5af77fe1aeb6ab4a1c53b1cab4797c75782ae73ed5`。不以未带版本号的 PDF 作为本轮对照基线。
- 有效配置来自主工作区 ini/env 与只读 SQLite KV 的正式配置解析器：`deepseek-flash` / `api.deepseek.com`，temperature 0.3，thinking disabled，max_tokens 10,000，timeout 60 秒，并发 4；未更换模型或调整本机配置。
- 调用正式 `translate_article`，内存文章适配器承接缓存，usage recorder 单独记录服务端返回值。生产数据库无写入，未触发自动分析或图片识别。
- 这是服务层计时，包含分段、模型调用、拼接与内存缓存写入；未包含浏览器请求、反向代理和真实数据库写入耗时，不代表生产容量/超时压测。

## 真实问题与修复

[#204](https://github.com/zlzfun/DoramiSourceArchive/issues/204)：模型将“从旧策略采样输出”按中文语序重排两个行内公式占位符，旧的全段有序校验误拒；模板表格的跨行句子被模型合并，又触发表格保护。现改为带稳定 ID 的 JSON 单元，段落、标题和表格行一一对应；本地恢复空行与单元顺序，允许同一单元内合理换序，禁止丢失、重复或跨单元搬移占位符，并检查每个表格单元格的数字及公式/链接归属。未改变的链接标签与目标绑定，图片同样适用。仍仅在整篇校验通过后保存，不放宽截断、在途取消或原文变更保护。

协议兼容沿用现有 JSON 解包器，接受普通端点返回的 JSON 围栏后仍严格验证单元；翻译计划内部将 CRLF/CR 统一为 LF，源文与缓存指纹继续使用原始正文。含未转义 `|` 的行按候选表格行保守校验（包含无外框 GFM 行），散文中的管道符及单元格数字自然换序可能误拒；没有将顺序比较放宽为多重集，以免把“从 1 到 2”变成“从 2 到 1”静默保存。同一单元内公式换序及已翻译链接标签的语义绑定仍需质量审查。

[#205](https://github.com/zlzfun/DoramiSourceArchive/issues/205)：§3 Evaluation Prompts 原文将 few-shot 改为 zero-shot，译文却写成“调整为少样本设置”；SWE-Bench Verified 专名则被误译成普通“验证结果”。现将独立的两个实验术语及这一基准专名保护为占位符，由本地恢复为“零样本（zero-shot）/少样本（few-shot）”或按论文正文写法统一的“SWE-Bench Verified”，保留英文锚点；代码、数学、链接目标和更长标识符不改写，已存在的正确双语表达不重复扩展。论文缓存流程版本升为 3，旧全文论文缓存仅在用户再次翻译时升级。最终译文是修复后的模型重新生成结果，未手改正文。

此规则只防止三项已确认术语的字面混淆，不验证整句逻辑、否定关系或任意领域术语；模型仍可能产生其它语义错误。其它术语存在风格差异，如 reward hacking 的“奖励作弊/奖励黑客”、CoT 的“思维链/链式思维”；此类可读性优化与事实性错译区分记录。
同一单元内不同术语的占位符仍允许相对换序，本样本最终顺序正确，但规则本身不能证明关联语义；术语周边半角空格保留。基准名统一大小写也作用于参考文献题名中的同一短语，引用 URL 不变，不将该大小写宣称为官网唯一规范。

后台持久任务、分段续译与进度恢复继续由 [#202](https://github.com/zlzfun/DoramiSourceArchive/issues/202) 跟踪。部署 launcher 测试时序问题由 [#203](https://github.com/zlzfun/DoramiSourceArchive/issues/203) 跟踪。
