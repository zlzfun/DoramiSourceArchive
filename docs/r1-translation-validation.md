# R1 全文翻译实测

2026-10-20，使用本机当前有效 LLM 配置，对本地阅读器对应的 **arXiv 2501.12948v1** 全文进行真实翻译。结构化协议修复后完成全文，公式、表格结构与表格数值通过检查；语义对照发现一处零样本/少样本错译，另由 [#205](https://github.com/zlzfun/DoramiSourceArchive/issues/205) 修复。不能把结构完整等同于语义完全正确。

## 范围与方法

- 固定输入：[R1 v1 官方 HTML](https://arxiv.org/html/2501.12948v1)，已转换正文 62,643 字符；SHA-256 `e544ceeff99b22e4b6cfce5af77fe1aeb6ab4a1c53b1cab4797c75782ae73ed5`。不以未带版本号的 PDF 作为本轮对照基线。
- 有效配置来自主工作区 ini/env 与只读 SQLite KV 的正式配置解析器：`deepseek-flash` / `api.deepseek.com`，temperature 0.3，thinking disabled，max_tokens 10,000，timeout 60 秒，并发 4；未更换模型或调整本机配置。
- 调用正式 `translate_article`，内存文章适配器承接缓存，usage recorder 单独记录服务端返回值。生产数据库无写入，未触发自动分析或图片识别。
- 这是服务层计时，包含分段、模型调用、拼接与内存缓存写入；未包含浏览器请求、反向代理和真实数据库写入耗时，不代表生产容量/超时压测。

## 真实问题与修复

[#204](https://github.com/zlzfun/DoramiSourceArchive/issues/204)：模型将“从旧策略采样输出”按中文语序重排两个行内公式占位符，旧的全段有序校验误拒；模板表格的跨行句子被模型合并，又触发表格保护。现改为带稳定 ID 的 JSON 单元，段落、标题和表格行一一对应；本地恢复空行与单元顺序，允许同一单元内合理换序，禁止丢失、重复或跨单元搬移占位符，并检查每个表格单元格的数字。仍仅在整篇校验通过后保存，不放宽截断、在途取消或原文变更保护。

[#205](https://github.com/zlzfun/DoramiSourceArchive/issues/205)：§3 Evaluation Prompts 原文将 few-shot 改为 zero-shot，译文却写成“调整为少样本设置”。属于实质错译，单独加入有限术语保护并重验；不静默人工改写结果后冒称模型输出。其它术语存在风格差异，如 reward hacking 的“奖励作弊/奖励黑客”、CoT 的“思维链/链式思维”；此类可读性优化与事实性错译区分记录。

后台持久任务、分段续译与进度恢复继续由 [#202](https://github.com/zlzfun/DoramiSourceArchive/issues/202) 跟踪。部署 launcher 测试时序问题由 [#203](https://github.com/zlzfun/DoramiSourceArchive/issues/203) 跟踪。
